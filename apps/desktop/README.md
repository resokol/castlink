# CastLink Client для Windows

Тестовый настольный клиент для кастера и персонала. Открывает существующий HTTPS-сервер CastLink; отдельный мастер установки, обновления и удаления сервера доступен через «Настройка сервера». Кастеру Docker не нужен. Windows 10/11 x64 — целевая платформа; фактически проверенные ОС и устройства перечисляются отдельно в `docs/testing/WINDOWS_DESKTOP_CLIENT_RU.md`.

## Разработка

Node.js 22.12+ (для текущих проверок используется Node.js 24), pnpm 9.15.0.

```sh
pnpm install --frozen-lockfile
pnpm desktop:test
pnpm desktop:dev
```

На первом экране выберите «Я — студия» или «Я — кастер / гость». Студия указывает адрес HTTPS-сервера (по умолчанию https://castlink.ru или сохранённый origin); резервные серверы раскрываются ниже. Кастер вставляет полную ссылку приглашения/постоянную ссылку. Кнопка «Нет ссылки?» открывает ввод адреса сервера, затем вход в комнату по названию и гостевому паролю. Полные ссылки сохраняют свой маршрут и параметры.

Вставьте адрес HTTPS-сервера или полную ссылку приглашения. В настройках клиента сохраняется только origin, не секрет приглашения. При повторном входе используйте сохранённую сервером сессию или вставьте приглашение снова. HTTP loopback разрешён только в разработке; недоверенные сертификаты не обходятся.

Установленный клиент регистрирует протокол `castlink:`. Браузер передаёт приглашение как `castlink://join?url=<encodeURIComponent(полный HTTPS URL)>`; клиент проверяет оболочку и адрес по той же политике, что ручной ввод. Первый запуск обрабатывает аргумент командной строки, уже запущенный клиент получает приглашение через single-instance. Переход из активного подключения требует подтверждения его закрытия. Некорректное приглашение не закрывает текущую комнату, внешние приложения через него не запускаются. Полный URL хранится только в памяти; на диск попадает origin. Web определяет native-клиент по `window.castlinkDesktop` или User-Agent `CastLinkDesktop/1`, чтобы не предлагать открыть его повторно.

Резервные серверы укажите заранее, по одному origin на строку. Неизвестные origins не получают native-мост или media-разрешения. Нажмите F10, чтобы открыть меню и выбрать «Сменить сервер» или «Выйти». Постоянная строка меню удалена. Экран входа поддерживает светлую и тёмную темы; начальная тема следует системной, выбор сохраняется локально. При закрытии рабочего окна запрашивается подтверждение; сворачивание сохраняет соединение. Автозапуска при входе в Windows нет.

При подключении клиент спрашивает разрешение камеры и микрофона. После согласия названия входов и выходов доступны сразу; запрос разрешения сам по себе не запускает захват. При отказе подключение продолжается, а доступ можно разрешить позже через запрос на странице. Согласие хранится только до закрытия/смены сервера; переходы внутри того же origin его сохраняют, другой origin требует нового согласия. Автокопирование ссылок разрешено доверенной основной странице; чтение буфера обмена запрещено. Экран/окно выбираются в отдельном picker. Системный звук в этой тестовой версии отключён: исключение приватного аудио из Windows loopback ещё не доказано.

Нативная STOP-панель и `Ctrl+Alt+Shift+S` работают в самом клиенте, включая сервер без desktop adapter. Клиент отслеживает только потоки getDisplayMedia; остановка через панель уведомляет существующий SDK, а камера и микрофон getUserMedia сохраняются. Если сервер уже поддерживает desktop adapter, его прежний screen-only stop lifecycle получает управление. Закрытие STOP-панели скрывает её; показ останавливается кнопкой или горячей клавишей. Конфликт горячей клавиши отображается в панели. PDF/PowerPoint в текущем серверном коде отключены и этим клиентом не включаются.

## Сборка кандидата

На Windows, из чистого закоммиченного private checkout:

```sh
pnpm desktop:package
```

Результат — `artifacts/desktop/<commit>/`: portable ZIP, NSIS installer, manifest и SHA256SUMS. Версия берётся из корневого package.json. Пакеты имеют отдельные имена `CastLink-Client-*`, чтобы отличаться от EasySetup. При запуске упакованного клиента проверяются независимые публичные каналы `client-v…` и `server-setup-v…`. Уведомление появляется только для более нового полного выпуска. Для одинаковой версии порядок сборок определяется датами публичных выпусков; неизвестная сборка той же версии автоматически не заменяется. Флажок «Отключить автоматическую проверку обновлений» сохраняется отдельно от серверных настроек. Ручная проверка доступна на первом экране и через F10; автоматические проверки можно снова включить в меню F10.

Кнопка «Обновить» сначала скачивает клиентский NSIS-установщик и `SHA256SUMS` из одного выпуска, проверяет SHA256 и только затем отдельно спрашивает согласие на закрытие клиента и установку. Отказ сохраняет текущий сеанс. После согласия открывается обычный пошаговый установщик Windows; запуск обновлённого клиента доступен в завершающем окне. Portable/ZIP также используют этот явный переход к установленной версии, текущий portable-файл не перезаписывается. Пакеты остаются неподписанными: SHA256 подтверждает соответствие опубликованным байтам, а не цифровую подпись.

Серверные уведомления относятся только к подтверждённым собственным установкам: локальный журнал среды и Compose должны совпасть с сохранённой версией; управляемый VPS определяется по сохранённой установке и проверяется через его HTTPS `/api/version`. Обычный выбранный адрес подключения не означает владение сервером и не вызывает предложение обновить castlink.ru. Для серверного обновления открывается прежний мастер с сохранённой папкой; выбор цели, SSH-доступ и подтверждения остаются в мастере. Неизвестный или недоступный VPS автоматически не обновляется. Проверка не запускает загрузку или остановку служб без явного выбора пользователя. Не устанавливайте обновление во время эфира. Скрипт не публикует release и не обновляет production.
