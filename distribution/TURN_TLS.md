# TURN через TLS на TCP 443

TURN/TLS помогает кастерам подключаться из сетей, где заблокирован UDP. Он передаёт медиатрафик до ретранслятора через защищённое TCP-соединение. Это не VPN и не гарантия работы через любой корпоративный фильтр.


Эта процедура относится к текущему **Windows Server Setup `d703726cd50b`** и его новой VPS-установке. Самостоятельный Linux CLI из архива — другой способ установки; команды из [Linux-мануала](LINUX_MANUAL.md) не включают TURN/TLS автоматически.

## Границы сетевой схемы

Эта процедура относится только к обычному **прямому публичному HTTPS**, стандартным TCP **80/443** и отдельному TURN-домену на том же VPS. В быстром режиме сохраняется эта штатная схема. Расширенный HTTP, изменённые веб-порты и внешний HTTPS-прокси не являются автоматической процедурой включения TURN/TLS: не переносите эти шаги на такой профиль.

HTTPS-прокси сайта передаёт HTTP/WebSocket, но сам по себе не передаёт TURN/TLS и не создаёт медиаретранслятор. Не запускайте второй независимый слушатель на TCP 443. Для расширенной сети сверяйтесь с [INSTALL.md](INSTALL.md); поддержка произвольной TURN-схемы здесь не обещается. Сохраните обычные медиапорты и проверьте реальное соединение, а не только страницу сайта.

## Что потребуется

- Публично доступный VPS с CastLink и доступ к его настройкам.
- Два разных домена: например, `studio.example.org` для сайта и `relay.example.org` для TURN. Примеры замените своими адресами.
- A-записи обоих доменов на публичный IPv4 этого VPS. При использовании DNS-прокси выберите режим «только DNS», если прокси не поддерживает TURN. Не добавляйте AAAA-запись без работающего IPv6-маршрута.
- TCP 80 и TCP 443, доступные извне на VPS. В штатной схеме TCP 80 используется для автоматического выпуска и продления сертификата; оставьте его открытым после установки.
- Разрешённые исходящие HTTPS-соединения сервера к источникам пакетов и службе сертификатов, а также доступ к DNS.

На стороне кастера сеть должна разрешать TURN/TLS к TURN-домену по TCP 443. Разрешение только браузерного HTTPS через прокси не всегда достаточно. При необходимости сетевой администратор должен разрешить этот транспорт и исключить его из перехвата TLS.

## Новая установка через Easy Setup

1. Создайте обе DNS-записи и дождитесь их обновления. Проверьте, что оба имени указывают на нужный VPS.
2. В Windows откройте Easy Setup. В карточке **«На Linux Ubuntu»** нажмите **«Настроить Linux Ubuntu»** и укажите данные SSH. Сверьте отпечаток ключа сервера с данными у провайдера.
3. В качестве адреса сайта укажите `studio.example.org`, без `https://` и пути. Для этого сценария нужен домен сайта, а не только IP.
4. При запросе отдельного домена TURN/TLS укажите `relay.example.org`. Пустой ответ оставляет обычный TURN/UDP.
5. Дождитесь завершения установки и проверки сертификата и маршрута TURN/TLS. Сохраните рабочую папку мастера и путь установки на VPS.
6. Выполните проверку медиасвязи ниже. Сообщение об успешной установке не заменяет эту проверку.

Если мастер сообщает, что TURN/TLS пока не готов, проверьте DNS, TCP 80/443 и отсутствие конфликта с другим сервисом на этих портах. Исправьте причину и повторите незавершённую установку в той же папке.

## Если CastLink уже установлен

**TURN/TLS уже был включён:** проверьте DNS, доступность TCP 443 и сертификат, затем выполните проверку связи. Повторно устанавливать сервер не нужно.

**Сервер работает только через TURN/UDP:** открытие TCP 443 само по себе не включает TURN/TLS. Нужна согласованная настройка сертификатов, HTTPS-прокси и медиасервера. При повторном запуске мастер сохраняет ранее выбранный TURN-домен и может не предложить новый.

Не выбирайте новую установку поверх рабочей только ради добавления TURN. Сохраните резервную копию данных и конфигурации и запланируйте перерыв. Для донастройки существующей установки обратитесь к [автору](https://t.me/sklvmax), указав версию CastLink и способ установки. Пароли и приватные ключи в обращении не нужны.

Эта инструкция описывает штатную новую установку VPS через мастер. Для локального Windows-сервера и Linux, установленного по отдельной инструкции без Easy Setup, она не является готовой процедурой включения TURN/TLS на месте. Не копируйте произвольные настройки чужой установки.

## Какие порты оставить

| Назначение | Правило |
| --- | --- |
| Подключение к TURN/TLS и HTTPS | Входящий TCP 443 на VPS; исходящий TCP 443 у кастера |
| Автоматический сертификат в штатной схеме | Входящий TCP 80 на VPS |
| Прямой медиатранспорт и TURN/UDP | Сохранить медиапорты из [общей инструкции](README.md) |

TURN/TLS меняет транспорт между кастером и ретранслятором. Он не отменяет UDP-порты ретрансляции на сервере. При совместном использовании HTTPS и TURN/TLS на одном IP:443 маршрутизацию настраивает мастер; запуск второго независимого слушателя на том же порту вызовет конфликт. Внутренние порты служб наружу открывать не требуется.

## Как проверить

1. Откройте студию, пригласите кастера со второго устройства из внешней сети.
2. В студии выберите для него **«Маршрут кастера» → «Запасной TURN»** и дождитесь подтверждения переподключения. Название блока может различаться между версиями.
3. Проверьте видео и звук кастера, а также обратный поток студии. Для проверки именно TCP/TLS повторите тест из сети, где UDP недоступен, но TURN/TLS на TCP 443 разрешён.
4. Для технического подтверждения в статистике WebRTC проверьте, что выбранный маршрут использует кандидат `relay` и TURN-сервер `turns:relay.example.org:443?transport=tcp`. Отображение полей зависит от браузера. Сам по себе кандидат `relay` не отличает TURN/UDP от TURN/TLS.

Кастер не вводит отдельный TURN-логин и пароль: CastLink получает необходимые параметры подключения автоматически.

## Если соединения нет

- **Не выдан сертификат:** проверьте обе DNS-записи, доступность TCP 80 и правила выдачи сертификатов для домена.
- **Сайт открывается, но TURN не работает:** проверьте разрешение TURN/TLS в сети кастера. Доступность HTTPS не доказывает доступность TURN.
- **Принудительный TURN не передаёт медиа:** проверьте состояние TURN, серверные порты ретрансляции и обратный трафик.
- **Проблема появилась позже:** проверьте срок сертификата, DNS и возможность автоматического продления.
