# Сервер одной командой и мониторинг

[Русский](SERVER_INSTALL.md) · [English](docs/en/SERVER_INSTALL.md) · [简体中文](docs/zh-CN/SERVER_INSTALL.md)

Описанные ниже новые установщики должны входить в **новый проверенный выпуск**.
В прежних опубликованных архивах их нет. Эта разработка не публикует выпуск и
не заменяет уже установленный сервер. Windows/WSL требует проверки на Windows
перед публичным распространением.

## Linux Ubuntu

Поддерживаются Ubuntu22.04/24.04 amd64. В Linux-выпуск добавлен самостоятельный
`install-server.sh` с закреплёнными версией и SHA256 архива. После выпуска возьмите
точную ссылку этого asset (не общий `releases/latest`) и выполните:

```bash
curl -fsSL "$INSTALLER_URL" | sudo bash -s -- --install-runtime
```

`INSTALLER_URL` — HTTPS-ссылка на `install-server.sh` **выбранного нового Linux
выпуска**. Скрипт запросит адрес и отдельный пароль создания комнат, сохранит
пакет/настройки в `/opt/castlink-server`, загрузит включённые образы и запустит
существующий Linux installer. `--install-runtime` разрешает установку зависимостей
и запуск Docker; без этого флага требуется готовый Docker/Compose. Домен, DNS и
правила маршрутизатора не создаются автоматически. [Порты и режимы](LINUX_MANUAL.md).

Повтор команды сохраняет данные, ключи, UUID и работающий выпуск; автоматически
не обновляет и не перезапускает завершённую установку. Он показывает сохранённый
адрес; текущую готовность проверяйте отдельной командой `status` из сохранённого
пакета. Для другого пути используйте `--state-dir /absolute/path` при каждом запуске.
Для автоматизированной установки существуют `--config` и
`--room-creation-password-file` (UTF-8 без завершающего перевода строки).

## Windows без Docker

Нужны Windows11 x64, build22621+, WSL2 версии2.4.13+ и поддержка виртуализации.
Установщик `install-server-windows.ps1` из отдельного канала `server-wsl-v…`
скачивает готовую Ubuntu-среду со всеми серверными компонентами. Docker Desktop,
Docker Engine, сборка исходников и ручная установка Node/PostgreSQL не нужны.
Это WSL-сервер, а не полностью нативные службы Windows.

После публикации скачайте скрипт из **того же выбранного выпуска**, сверив
`SHA256SUMS`, и запустите в PowerShell:

```powershell
& .\install-server-windows.ps1 -Action Install
```

Скрипт запросит адрес и пароль, проверит SHA256 rootfs, создаст только собственный
WSL-дистрибутив и предложит необходимые настройки. Первое включение WSL может
потребовать разрешения администратора и перезагрузки; повторите ту же команду
после неё. Перезагрузка автоматически не запускается. Существующие дистрибутивы,
конфликтующие порты и настройки сохраняются; при конфликте установка остановится
с инструкцией. Mirrored networking — общая настройка WSL; изменение требует
согласия. Установщик не выполняет глобальный `wsl --shutdown`.

Серверный дистрибутив не подключает диски Windows и не запускает Windows-программы.
Конвертер PPTX работает отдельным пользователем без сети, с ограничениями ресурсов.
Порты: TCP80/443/7881; UDP3478/7882/30000–30031. Для доменного сервера нужен также
TURN hostname (`turn.<domain>`), направленный на тот же IP. Доступ извне зависит от
маршрутизатора и внешнего firewall. При локальном CA предлагается доверие только
текущему пользователю Windows; отказ не скрывается. Другим клиентским устройствам
также потребуется доверие CA. Статус HTTPS/БД не доказывает внешний медиазвонок.

Команды управления тем же установщиком: `-Action Start`, `Stop`, `Status`,
`OwnerAccess`. Остановка сохраняет данные. Обновление существующих Docker-серверов
и автоматический перенос их данных в WSL этим установщиком не выполняются.
При прерывании импорта до записи маркера дистрибутив сохраняется для ручной
проверки; установщик не присваивает и не удаляет его автоматически.

Фоновый процесс удерживает только серверный WSL-дистрибутив запущенным, даже когда
окно установщика закрыто. По отдельному согласию можно включить автозапуск при
входе текущего пользователя Windows. Явный `Stop` сохраняет остановленное состояние.

## Графики сервера

Панель в **Super Admin** показывает активные и сохранённые комнаты, подключения,
кастеров, CPU, RAM, диск, входящий/исходящий сетевой трафик, память/uptime web и
проверяемое состояние сервисов. Идентификаторы участников и секреты в метрики не
попадают. Права администратора комнаты не открывают серверную статистику.

Windows-установщик сохраняет одноразовую ссылку владельца в закрытый локальный файл;
`-Action OwnerAccess` создаёт новую при необходимости. В Linux запросите её явно:

```bash
sudo python3 /opt/castlink-server/.castlink-package/scripts/linux-compose-setup.py owner-access \
  --state-dir /opt/castlink-server --owner-access-file /root/castlink-owner-access.txt
```

Ссылка действует15минут, одноразовая, сохраняется с правами0600 и не выводится в
журнал. Прочитайте файл локально и откройте ссылку в браузере; не пересылайте её.

Замеры выполняются примерно каждые 15 секунд независимо от открытого браузера.
Показатели и структурированный журнал событий CastLink сохраняются за последние
24 часа и переживают перезапуск. Старые записи удаляются автоматически. В панели
есть периоды 1/6/24 часа, фильтр уровня событий и страницы по 50 событий. На длинных
периодах показываются явно обозначенные пики, подписи — последний исходный замер.
Число точек ограничено, чтобы суточный график оставался лёгким для браузера.

Данные хранятся в `runtime/server-observability.sqlite` внутри прежнего каталога
данных сервера. Дополнительная служба БД не требуется. Ограничены размер БД/WAL и
число событий; при большом потоке старые записи могут удаляться раньше суток.
Пароли, cookies, токены и тела запросов не записываются. Журнал включает события
приложения и изменения доступности служб; это не копия всех системных журналов ОС.
При недоступной записи панель показывает предупреждение, консольный вывод остаётся.

Нет замера, устаревший замер и нулевая нагрузка отображаются по-разному. Первая
точка CPU/скорости сети ожидает следующего замера. В WSL показываются ресурсы
Linux-среды; в Docker CPU/RAM относятся к ядру хоста, диск — к файловой системе
данных, сеть — к сетевому пространству web-контейнера. Это не суммарный трафик всех
контейнеров и не лимиты контейнера. Отдельные подписи поясняют область измерения.
