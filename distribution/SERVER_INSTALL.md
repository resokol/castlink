# Сервер одной командой и мониторинг

[Русский](SERVER_INSTALL.md) · [English](docs/en/SERVER_INSTALL.md) · [简体中文](docs/zh-CN/SERVER_INSTALL.md)

Руководство для Windows Server Setup и standalone Linux **1.0.5**; Windows Client — **1.0.1**. Версия пакета исходников — **1.0.5**. Доступные выпуски, точные source/build ID и контрольные суммы указаны в [каталоге продуктов](PRODUCTS.md). [Изменения 1.0.5](RELEASE_NOTES_1_0_5.md).

В серверном выпуске **1.0.2** впервые появились [Linux одной командой, история показателей и журнал за 24 часа](RELEASE_NOTES_1_0_2.md). Обычный локальный Windows Server Setup использует Docker Desktop. Windows/WSL2 без Docker остаётся отдельным экспериментальным каналом и не входит в эти стабильные серверные пакеты.

Обновляйте сервер только вне эфира и явным действием, выбрав прежнюю установку, её данные и настройки; для Linux сохраняйте прежний `--state-dir`. Публикация пакета сама не обновляет работающий сервер. После проверки готовности вручную обновите страницы **и студии, и кастера**, включая страницы в Windows Client: клиент отображает интерфейс выбранного сервера.

## Linux Ubuntu

Ниже приведена команда для стабильного выпуска **1.0.5**. Пошаговая установка Windows и Linux: [главная инструкция](../README.md).

Поддерживаются Ubuntu22.04/24.04 amd64. В Linux-выпуск добавлен самостоятельный
`install-server.sh` с закреплёнными версией и SHA256 архива. Выберите закреплённый asset выпуска 1.0.5 (не общий `releases/latest`) и выполните:

```bash
curl -fsSL https://github.com/resokol/castlink/releases/download/linux-v1.0.5-732ad5fe7006/install-server.sh | sudo bash -s -- --install-runtime --lang ru
```

Скрипт из **linux-v1.0.5-732ad5fe7006** запросит адрес и отдельный пароль создания комнат, сохранит
пакет/настройки в `/opt/castlink-server`, загрузит включённые образы и запустит
существующий Linux installer. `--install-runtime` разрешает установку зависимостей
и запуск Docker; без этого флага требуется готовый Docker/Compose. Домен, DNS и
правила маршрутизатора не создаются автоматически. [Порты и режимы](LINUX_MANUAL.md).

Повтор команды сохраняет данные, ключи, UUID и работающий выпуск; автоматически
не обновляет и не перезапускает завершённую установку. Он показывает сохранённый
адрес; текущую готовность проверяйте отдельной командой `status` из сохранённого
пакета. Для другого пути используйте `--state-dir /absolute/path` при каждом запуске.
Для автоматизированной установки существуют `--config` и
`--room-creation-password-file` (UTF-8 без завершающего перевода строки).

## Windows/WSL2 без Docker — отдельный экспериментальный канал

Подготовлен [кандидат установщика 1.0.5-rc.2](https://github.com/resokol/castlink/releases/tag/server-wsl-v1.0.5-rc.2-ccbc0db7e937), пока не опубликованный. Ссылки ниже предназначены для использования после публикации. [Шаги установки и ограничения](../README.md#сервер-на-windows-11).

Нужны Windows11 x64, build22621+, WSL2 версии2.4.13+ и поддержка виртуализации.
Установщик `install-server-windows.ps1` из отдельного канала `server-wsl-v…`
скачивает готовую Ubuntu-среду со всеми серверными компонентами. Docker Desktop,
Docker Engine, сборка исходников и ручная установка Node/PostgreSQL не нужны.
Это WSL-сервер, а не полностью нативные службы Windows.

Скачайте скрипт из **того же выбранного выпуска**, сверив
`SHA256SUMS`, и запустите в PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install-server-windows.ps1 -Action Install
```

Скрипт запросит адрес и пароль, проверит SHA256 rootfs, создаст только собственный
WSL-дистрибутив и предложит необходимые настройки. Первое включение WSL может
потребовать разрешения администратора и перезагрузки; повторите ту же команду
после неё. Перезагрузка автоматически не запускается. Существующие дистрибутивы,
конфликтующие порты и настройки сохраняются; при конфликте установка остановится
с инструкцией. Нужны общие настройки WSL `networkingMode=mirrored` и
`[experimental] hostAddressLoopback=true`: последняя позволяет открыть сервер с
этого ПК по его сетевому IPv4. Установщик изменяет только отсутствующие параметры
после явного согласия. Затем активируйте настройки перезагрузкой Windows либо
дождитесь полного завершения WSL и повторите ту же команду. Установщик не выполняет
глобальный `wsl --shutdown` и не перезаписывает существующее `false`.

Серверный дистрибутив не подключает диски Windows и не запускает Windows-программы.
Конвертер PPTX работает отдельным пользователем без сети, с ограничениями ресурсов.
Порты: TCP80/443/7881; UDP3478/7882/30000–30031. Для доменного сервера нужен также
TURN hostname (`turn.<domain>`), направленный на тот же IP. Доступ извне зависит от
маршрутизатора и внешнего firewall. При локальном CA предлагается доверие только
текущему пользователю Windows; отказ не скрывается. Другим клиентским устройствам
также потребуется доверие CA. Статус HTTPS/БД не доказывает внешний медиазвонок.

Команды управления тем же установщиком: `-Action Start`, `Stop`, `Status`,
`OwnerAccess`. Остановка сохраняет данные. Обновление существующих Docker-серверов
и автоматический перенос их данных в WSL этим установщиком не выполняются.
При прерывании импорта до записи маркера дистрибутив сохраняется для ручной
проверки; установщик не присваивает и не удаляет его автоматически.

Фоновый процесс удерживает только серверный WSL-дистрибутив запущенным, даже когда
окно установщика закрыто. По отдельному согласию можно включить автозапуск при
входе текущего пользователя Windows. Явный `Stop` сохраняет остановленное состояние.

### Обслуживание: обновление, удаление, восстановление

После публикации кандидата скачайте [CastLink-Server-WSL-Maintenance.zip](https://github.com/resokol/castlink/releases/download/server-wsl-v1.0.5-rc.2-ccbc0db7e937/CastLink-Server-WSL-Maintenance.zip) из **этого же выпуска** и распакуйте ZIP целиком. [Контрольные суммы SHA256SUMS](https://github.com/resokol/castlink/releases/download/server-wsl-v1.0.5-rc.2-ccbc0db7e937/SHA256SUMS). Дважды нажмите **CastLink-Maintenance.cmd**. Новая панель открывает тот же инструмент кнопкой **«Обслуживание»**. Для старой 1.0.5-rc.1 это отдельный инструмент: её установщик не обновляется сам.

**Выбор и обновление.** Выберите точный сервер по адресу и папке; не выбирайте автоматически первый из нескольких. В неполной установке адрес может быть неизвестен — сверяйте папку. Выберите целевую версию, нажмите **«Проверить»** и сверьте текущую/целевую версии и требуемое/свободное место. Инструмент загрузит и проверит нужные файлы до остановки сервера. Проверка сама ничего не обновляет; RC выбирается явно. В обычном окне не требуется вводить SHA256 или непрозрачное имя WSL.

Нажмите **«Обновить»** только вне эфира: на время переноса и проверки готовности сервер остановится. В подтверждении показаны адрес, версия и папка выбранного сервера; можно отменить действие. Первый поддерживаемый источник — только `server-wsl-v1.0.5-rc.1-085b087a2458`. Другие исходные версии, миграция Docker и переход на другую основную версию PostgreSQL не поддерживаются. Неполную исходную установку сначала исправьте её прежней версией либо удалите через этот инструмент; обновление не выдаёт её за готовую.

Поддерживаемый переход сохраняет UUID сервера, комнаты и историю, пароли, домен, TLS-материал и сетевые настройки. После успешного обновления временная копия переноса и прежний принадлежащий этой установке дистрибутив удаляются: **постоянной автоматической резервной копии нет**. При ошибке нужные данные восстановления сохраняются. После успеха нажмите **«Открыть панель сервера»** и обновите страницы студии и кастера.

**Удаление.** По умолчанию выбран пункт **«Сохранить архив перед удалением»**. Укажите место вне папки установки и нажмите **«Удалить»**: программа создаст отдельную папку архива и проверит её перед удалением сервера. Либо явно выберите **«Безвозвратно удалить сервер и данные»**. Подтверждение показывает выбранный сервер и исход удаления; отмена не запускает операцию.

Архив восстановления — **папка** с `bundle.json`, полным `distribution.tar` и проверенными файлами той же версии. Это не ZIP обслуживания и не экспорт статистики за 24 часа. Архив содержит пароли, ключи и другие учётные данные: храните всю папку приватно, не публикуйте и не отправляйте её как обычный диагностический файл. Сохраняйте все файлы вместе.

**Восстановление.** В том же окне выберите папку архива и **«Восстановить»**. Для назначения выберите родительскую папку внутри `%LOCALAPPDATA%\CastLinkServer`: диалог предложит имя новой папки. Папка назначения ещё не должна существовать; другую установку в неё не объединяют. Восстанавливается сохранённая версия с прежней идентичностью и настройками; при конфликте существующего сервера или портов действие останавливается. Архив неполной установки восстанавливается как неполная установка, без обещания готовности приложения.

**После сбоя.** Откройте тот же инструмент, выберите тот же сервер и **«Завершить / восстановить операцию»**. Не удаляйте его данные, не запускайте старый ярлык вручную и не используйте повторный Install как восстановление. После переключения на новую версию восстанавливается её работа; старые данные автоматически не возвращаются вместо уже изменённых новых. При неподтверждённой принадлежности программа сохраняет спорный дистрибутив для ручной проверки.

Обслуживание относится только к выбранному серверу. Другие установки, вложенные папки, неизвестные файлы и вручную сохранённые экспорты остаются; общие настройки WSL и firewall не удаляются. Ручное удаление AppData, глобальный `wsl --shutdown` или unregister не являются обычными шагами обслуживания.

## Графики сервера

Панель в **Super Admin** показывает активные и сохранённые комнаты, подключения,
кастеров, CPU, RAM, диск, входящий/исходящий сетевой трафик, память/uptime web и
проверяемое состояние сервисов. Идентификаторы участников и секреты в метрики не
попадают. Права администратора комнаты не открывают серверную статистику.

Windows-установщик сохраняет одноразовую ссылку владельца в закрытый локальный файл;
`-Action OwnerAccess` создаёт новую при необходимости. В Linux запросите её явно:

```bash
sudo python3 /opt/castlink-server/.castlink-package/scripts/linux-compose-setup.py owner-access \
  --state-dir /opt/castlink-server --owner-access-file /root/castlink-owner-access.txt
```

Ссылка действует15минут, одноразовая, сохраняется с правами0600 и не выводится в
журнал. Прочитайте файл локально и откройте ссылку в браузере; не пересылайте её.

Замеры выполняются примерно каждые 15 секунд независимо от открытого браузера.
Показатели и структурированный журнал событий CastLink сохраняются за последние
24 часа и переживают перезапуск. Старые записи удаляются автоматически. В панели
есть периоды 1/6/24 часа, фильтр уровня событий и страницы по 50 событий. На длинных
периодах показываются явно обозначенные пики, подписи — последний исходный замер.
Число точек ограничено, чтобы суточный график оставался лёгким для браузера.

Данные хранятся в `runtime/server-observability.sqlite` внутри прежнего каталога
данных сервера. Дополнительная служба БД не требуется. Ограничены размер БД/WAL и
число событий; при большом потоке старые записи могут удаляться раньше суток.
Пароли, cookies, токены и тела запросов не записываются. Журнал включает события
приложения и изменения доступности служб; это не копия всех системных журналов ОС.
При недоступной записи панель показывает предупреждение, консольный вывод остаётся.

Нет замера, устаревший замер и нулевая нагрузка отображаются по-разному. Первая
точка CPU/скорости сети ожидает следующего замера. В WSL показываются ресурсы
Linux-среды; в Docker CPU/RAM относятся к ядру хоста, диск — к файловой системе
данных, сеть — к сетевому пространству web-контейнера. Это не суммарный трафик всех
контейнеров и не лимиты контейнера. Отдельные подписи поясняют область измерения.
