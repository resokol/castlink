# CastLink — инструкция по установке и работе

[Скачать](https://github.com/resokol/castlink-releases/blob/main/README.md) · [История изменений](https://github.com/resokol/castlink-releases/blob/main/CHANGELOG.md) · [Ручная установка Linux](https://github.com/resokol/castlink-releases/blob/main/LINUX_INSTALL.md)

CastLink — браузерная студия для подключения кастеров, приёма их аудио и видео в vMix/OBS и отдельного просмотра студийного эфира. Сервер устанавливается на ваш Windows-компьютер или Linux VPS. Кастеры открывают ваш адрес в браузере; Docker на компьютерах кастеров не требуется.

Здесь публикуются официальные пакеты и инструкции. Приложение проходит публичное тестирование: перед настоящим эфиром проверьте собственные устройства, сеть и восстановление соединения.

## Мультивью, приглашения и изображение

- В студии появился экспериментальный редактор «Мультивью»: сетки и свободная раскладка, перемещение и изменение размеров слотов, привязка к направляющим, отдельное кадрирование, скругление углов и общая заглушка при отсутствии видео. Сцены можно копировать, удалять, экспортировать и импортировать. После импорта источники назначаются заново. Для вывода в Browser Source OBS/vMix предусмотрена отдельная ссылка с прозрачным фоном; изменения сцены публикуются кнопкой «Применить».
- В разделе «Кастомизировать комнату» можно задать параметры новых приглашений: вход с выключенным микрофоном, только звук без включения камеры при входе, запрет взаимного прослушивания кастеров. Сохранение настроек не меняет уже выданные ссылки и подключённые сессии; выдайте новые приглашения.
- Кадрирование кастера в студии меняется сразу и сохраняется автоматически: зум, сдвиг, поворот, отражение и кроп доступны ползунками и точным числовым вводом. Компактные элементы управления находятся рядом с видео. Преобразования применяются при отображении в студии и индивидуальном видеовыходе; исходный поток кастера не перекодируется. У слотов мультивью собственные настройки.
- Для Studio Return доступен чёрный фон вместо камеры. Отключение звука выхода действует также на `/watch` и демонстрацию экрана; аудиометр показывает сигнал с учётом этого отключения. Личный мониторинг остаётся отдельным.
- Перенос комнаты, аварийный резерв и серверы комнаты объединены в пункте бокового меню «Резервные сервера».

Мультивью остаётся экспериментальной функцией: до 16 сцен и 32 слотов, без гарантии производительности для любого устройства. Начните с сетки 2×2. Сцены хранятся на текущем сервере и автоматически не переносятся на резерв; экспорт/импорт переносит композицию, а источники назначаются заново. Ссылку выхода передавайте только доверенным получателям эфира: она даёт доступ к медиа комнаты. Для звука браузеру может потребоваться нажатие пользователя. Перед настоящим эфиром проверьте собственные камеры, сеть и принимающее ПО.

## Что потребуется

- **Локально:** Windows 10/11 x64, совместимый с вашей версией Windows Docker Desktop с Linux-контейнерами, аппаратная виртуализация и WSL2. Мастер предложит установить отсутствующий Docker Desktop; Windows может запросить права администратора и перезагрузку.
- **VPS:** Ubuntu 22.04/24.04 amd64, публичный IPv4, доступ по SSH с логином `root` и паролем или приватным ключом. Docker Desktop на Windows для установки на VPS не нужен.
- Интернет для загрузки пакетов и образов. Камера и микрофон требуют доверенного HTTPS и разрешения браузера; для разговора рекомендуются наушники.
- **Рекомендация по диску для первого теста:** от 20 ГБ свободного места с запасом для образов, обновлений и резервных копий. Это ориентир, а не измеренный минимальный размер установки.

Проверялся отдельный профиль VPS с 2 ГБ RAM, настроенным swap и ограничениями памяти служб. Это не гарантированный минимум для штатной установки или любой эфирной нагрузки. Число кастеров, зрителей и качество видео требуют собственной проверки ресурсов. Мастер использует готовые образы — собирать приложение на VPS не нужно.

Docker Desktop имеет собственные условия использования. Условия и стоимость вашего VPS, домена и интернет-соединения определяют их поставщики.

## Установить на Windows

1. Распакуйте **весь** `CastLink-Windows.zip` в отдельную папку. Запустите `EasySetup.exe`; `EasySetup.cmd` также открывает графический мастер. Для консольного диалога используйте `EasySetup-Console.cmd`.
2. Выберите **«Установить» → «Локально»** и папку установки.
3. Выберите доступ: **LAN** для устройств в своей сети, **публичный IPv4** для подключения через интернет. Проверьте предлагаемый адрес.
4. Дождитесь подготовки Docker. Если мастер запросит перезагрузку, выполните её и снова откройте мастер: он предложит продолжить незавершённую локальную установку. Сохраняйте выбранную папку; удалять её или данные Docker для продолжения не нужно.
5. Дождитесь завершения установки и проверки HTTPS. Для локального сервера откройте панель кнопкой в мастере или ярлыком **CastLink** на рабочем столе; после запуска служб нажмите **«Открыть CastLink»**.
6. Для локальной установки, включая запуск Windows-сервера по публичному IP, мастер предложит доверять собственному сертификату именно этого сервера. На других устройствах вашей сети также нужно установить его сертификат. Мастер создаёт комплект `CastLink-Certificate`; для другого Windows ПК скопируйте комплект целиком и запустите `Install-Certificate.cmd`. Доверяйте сертификату только своего сервера. После импорта полностью перезапустите браузер.

LAN не требует белого IP. Для доступа к Windows-серверу из интернета нужны публичный адрес, разрешённые порты и при необходимости проброс на роутере: мастер не выдаёт белый IP и не настраивает ваш роутер.

В Windows-мастере и окне управления можно выбрать **Русский / English / 简体中文**. По умолчанию выбран русский; выбор сохраняется для текущей учётной записи Windows. Подробные технические сообщения Windows и Docker остаются на исходном языке.

После успешной локальной установки на рабочем столе появляется **CastLink**. Открытие ярлыка запускает панель управления и службы этой установки. Панель показывает состояние Docker, служб и сайта; кнопка **«Открыть CastLink»** открывает его в браузере.

**Крестик окна и «Скрыть в трей»** оставляют сервер работающим. Кнопка **«Остановить службы»** останавливает эту установку, сохраняя панель открытой. Команда **«Остановить и выйти»** также закрывает панель. Комнаты и настройки сохраняются; Docker Desktop и другие проекты не выключаются. Панель не добавляется в автозапуск Windows: для запуска сервера откройте ярлык. Сон и выключение ПК делают локальный сервер недоступным.

## Установить на Linux VPS из Windows

1. Запустите тот же мастер и выберите **«Установить» → «Внешний сервер»**.
2. Введите IP, SSH-порт и логин `root`. Выберите вход по паролю или укажите файл приватного SSH-ключа (OpenSSH/PEM), при необходимости — его парольную фразу. При первом подключении сверьте показанный отпечаток **ключа сервера** с данными у провайдера. Пароль и парольная фраза используются только для текущего подключения.

   После успешного входа можно создать новый ключ: сохраните приватный файл, затем мастер добавит публичный ключ на VPS и проверит новый вход. Первоначальный пароль или действующий ключ всё равно нужен. Существующие ключи сервера сохраняются. Приватный файл храните у себя: он даёт доступ к VPS. Созданный файл не шифруется парольной фразой; мастер ограничивает доступ к нему текущим пользователем Windows.

3. Домен необязателен. Можно использовать публичный IPv4 или указать собственный домен без `https://` и пути. Для домена заранее создайте A-запись на IP VPS; изменение DNS выполняется в панели регистратора.
4. При новой установке с доменом можно указать отдельный домен TURN, например `relay.example.org`, с A-записью на этот же VPS. Он нужен для запасного медиамаршрута через TCP/443. Пустой ответ сохраняет обычный TURN/UDP.
5. Дождитесь загрузки Linux-пакета, установки зависимостей, запуска служб и проверки HTTPS. Сохраните рабочую папку мастера и показанный путь установки на сервере.
6. Откройте показанный адрес в браузере. Для доступного публичного IP или домена мастер настраивает получение и обновление публичного HTTPS-сертификата; собственный локальный сертификат клиентам устанавливать не требуется.

Для выпуска публичного сертификата сервер должен быть доступен извне. Неверная DNS-запись, закрытые порты или адрес за CGNAT не исправляются выбором публичного режима. К завершённой установке VPS по IP домен можно добавить позднее, повторно запустив мастер для того же сервера.

### Сетевые порты

Для стандартной установки разрешите в firewall сервера и панели провайдера:

| Назначение | Порты |
| --- | --- |
| HTTPS и выпуск публичного сертификата | TCP 443; для VPS с публичным сертификатом также TCP 80 |
| Прямое медиасоединение | TCP 7881, UDP 7882 |
| TURN/UDP | UDP 3478 и UDP 30000–30031 |
| Необязательный TURN/TLS | TCP 443 на том же сервере, отдельный TURN-домен |

Сохраните доступ к вашему SSH-порту. Для Windows LAN нужны соответствующие разрешения Windows Firewall; при подключении через интернет за роутером — также проброс портов. Уже установленный сервер может иметь другой настроенный медиадиапазон: сверяйтесь с его конфигурацией и сообщениями мастера.

## Первая комната и кастеры

1. На главной странице своего сервера выберите **«Создать комнату»**. Укажите название и отдельный **пароль студии** длиной не менее восьми символов. При необходимости задайте пароль кастеров.
2. В открывшейся студии выберите камеру, микрофон и устройство прослушивания. Проверьте предпросмотр, затем включите **ON AIR** для передачи Studio Return.
3. Создайте приглашение кастера в панели студии и отправьте его кастеру лично. Пароль кастеров или приглашение не дают права управлять студией.
4. Кастер открывает ссылку в браузере, разрешает нужные устройства и проверяет звук/видео. Для повторного входа студия использует **«Войти в существующую»**, название комнаты и пароль студии.

Сохраните пароль студии. Приглашения и ссылки просмотра дают доступ к вашей комнате или потоку: не размещайте их в публичном отчёте об ошибке.

### Индивидуальный output для vMix/OBS

В студии скопируйте URL на карточке нужного кастера и добавьте его в vMix как Web Browser либо в OBS как Browser Source. Каждый URL кастера показывает отдельный чистый выход камеры и звука. Для демонстрации экрана используется отдельная ссылка **«Экран кастера»**. Используйте URL целиком, включая его секретную часть; угадывать адрес по имени кастера не нужно.

### Просмотр студии через `/watch`

Студия или администратор комнаты выдаёт отдельную ссылку просмотра Studio Return. Одну ссылку можно открыть нескольким зрителям одновременно; каждый получает собственное подключение. Зрители принимают студийное видео и эфирный звук без камеры, микрофона, управления и потоков кастеров. Браузер может попросить нажать **«Включить звук»**; звук и видео каждый зритель переключает только у себя.

Для зрителей студия отправляет на сервер один дополнительный поток, а сервер доставляет его каждому зрителю. Расход исходящего трафика сервера растёт с числом зрителей и битрейтом. Здесь нет обещания неограниченного количества подключений: ёмкость зависит от вашей сети, сервера и качества видео.

## Соединение через TURN

Обычно оставьте **«Автоматически»**: браузер выбирает доступный маршрут, включая настроенный TURN. Если первое медиаподключение завершается подходящей сетевой ошибкой или тайм-аутом, CastLink один раз повторяет его с обязательным TURN. Это не постоянное переключение при каждой потере пакета.

Если уже подключённому кастеру мешает сеть или VPN, студия может выбрать **«Звук и подключение кастеров» → «Маршрут кастера» → «Запасной TURN»**. Дождитесь подтверждения применения: переподключается только выбранный кастер. Кастер не вводит отдельные TURN-логин и пароль.

TURN/UDP включён в обычную установку. TURN/TLS на TCP/443 полезен для сетей, блокирующих UDP; ему нужны отдельный домен и корректно выданный сертификат. TURN не гарантирует работу через любой VPN или корпоративный фильтр и не восстанавливает выключенный сервер.

## Дополнительный сервер и резерв

В разделе **«Серверы комнаты»** можно установить CastLink на другой VPS или подключить совместимую существующую установку. До эфира проверьте доверенный HTTPS и доступность обоих адресов на устройствах кастеров.

- **Плановый перенос** запускает основная студия вручную. При отказе цели исправный источник продолжает работу.
- **Аварийный резерв** выбирается заранее; одновременно подготовлен один резерв для текущей группы кастеров. Снимок обновляется каждые 30 секунд и действует не более пяти минут.
- **Автоматический аварийный перенос** по умолчанию выключен. Для включения нужна открытая подготовленная вкладка основной студии и подтверждение резерва. Вкладка и резерв независимо подтверждают устойчивый отказ источника; одиночный сбой кастера не переносит комнату. Закрытая или приостановленная браузером вкладка студии не запускает автоматику.
- Подготовленные открытые вкладки кастеров и `/watch` следуют подтверждённому переносу. Выключенный источник не может заново загрузить страницу: во время аварии не обновляйте его вкладку. Если подготовка истекла, нужен доступный источник для её обновления.
- Переход может прервать звук/видео; браузер может потребовать повторного разрешения устройств, выбора экрана или включения звука. Это не бесшовный кластер. Возврат на восстановленный сервер всегда ручной.

Выключение автоматики завершено только после подтверждения резерва. Старые ссылки не становятся постоянными перенаправлениями: новым кастерам и зрителям после переноса выдавайте ссылки целевого сервера.

### SSH-ключ в панели студии

При подключении резерва выберите вход по паролю или приватному SSH-ключу. В блоке создания ключа сначала создайте и скачайте приватный файл, затем нажмите «Установить созданный ключ на VPS». Для этого нужен действующий пароль или уже настроенный ключ, а отпечаток сервера необходимо проверить отдельно. После успешной проверки нового входа выберите скачанный файл для установки или подключения CastLink. Существующие ключи и вход по паролю не удаляются. Созданный приватный файл не защищён парольной фразой — храните его как пароль к серверу.

## Обновление и удаление

1. До обновления разрешите **UDP 7882** в сетевом экране провайдера, системном firewall и, если сервер находится за роутером, настройте проброс этого порта. Сохраните **TCP 80/443/7881**, **UDP 3478** и разрешите **UDP 30000–30031**. SSH-порт должен оставаться доступным. Необязательный TURN/TLS использует **TCP 443** и отдельный TURN-домен.
2. Сохраните резервную копию данных и конфигурации. Полностью распакуйте новый Windows-пакет и запустите `EasySetup.exe`, выберите **«Обновить»** и существующую установку: прежнюю локальную папку или тот же VPS. Ручная Linux-инструкция пока закреплена на прежнем выпуске `easy-setup-8b02e2d4dc3c`: не заменяйте в ней тег и суммы на `latest`. Для перехода VPS на новую схему Easy Setup используйте новый Windows-мастер по SSH.
3. Выполняйте обновление в перерыв эфира: установщик пересоздаёт контейнер LiveKit для применения медиапортов, поэтому текущие медиасоединения прервутся. Обновление существующей установки сохраняет её данные; удалять установку и тома не требуется.
4. После обновления проверьте сайт, новое подключение кастера, звук и видео, индивидуальный выход, `/watch` и используемый резерв из ваших сетей. Откройте обновлённый интерфейс в браузере.

Новая схема Easy Setup: прямое медиа — **UDP 7882 / TCP 7881**; TURN — **UDP 3478** и relay **UDP 30000–30031**. Она заменяет прежние диапазоны **UDP 61000–61100** и relay **UDP 30000–30999**. Разрешения внешних сетевых экранов и проброс роутера устанавливаются отдельно от Docker; одного скачивания нового ZIP недостаточно.

Кнопка **«Обновить» в панели резервного сервера внутри студии обновляет только web-приложение**. Она не пересоздаёт LiveKit и не переводит существующую установку на новые медиапорты. Для этого перехода используйте обновление через новый установщик. Собственные конфигурации сверяйте с их фактическими настройками.

Для удаления выберите **«Удалить»**, проверьте показанный сервер и путь, затем подтвердите выбранное действие вводом **`DELETE`**. На VPS мастер находит установки после подключения по SSH.

По умолчанию удаляются серверные контейнеры выбранной установки, а комнаты, настройки и тома данных сохраняются. **Полное удаление вместе с комнатами и настройками — отдельный выбор с потерей данных.** Восстановление уже удалённых данных возможно только из вашей резервной копии. Сохраняйте рабочую папку и конфигурацию для повторного запуска с оставленными данными; удаление скачанного ZIP не является удалением сервера.

## Как помочь тестированию

Начните с небольшой тестовой комнаты: два браузера, микрофон/камера, выход кастера в vMix/OBS и `/watch`. Затем проверьте другие устройства и сети, переподключение, обновление и выбранный резерв. Не испытывайте удаление или отказ сервера на единственной копии рабочего эфира.

В сообщении об ошибке укажите:

- Версию/идентификатор сборки из интерфейса или `/api/version`, ОС и браузер.
- Где расположен сервер: локально или VPS; тип подключения без конкретных адресов.
- Действия, ожидаемый и фактический результат, повторяется ли ошибка.
- Обезличенный текст ошибки или скриншот; для медиа — устройства и результат проверки другой сети.

Обычные ошибки можно оставить в [Issues публичного репозитория](https://github.com/resokol/castlink-releases/issues) или отправить автору в [Telegram](https://t.me/sklvmax). **Не публикуйте пароли, токены, cookies, приглашения, персональные output/watch-ссылки, полные конфигурации и логи, внутренние IP-адреса или SSH-данные.** Перед отправкой скриншота закройте секретные поля и адресную строку с персональными ссылками. Об уязвимостях сначала сообщайте автору лично в Telegram, без публичного раскрытия секретов и способа атаки.

Мастер рассчитан на Windows 10/11; это не заявление о проверке каждой версии ОС, VPS, браузера и физических устройств. Реальный эфир и длительная нагрузка требуют вашей проверки. Контакт автора: [Telegram](https://t.me/sklvmax) · [GitHub](https://github.com/resokol).
