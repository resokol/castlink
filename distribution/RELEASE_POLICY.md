# Выпуски CastLink

Русский · [English](docs/en/RELEASE_POLICY.md) · [简体中文](docs/zh-CN/RELEASE_POLICY.md)

- Единственный публичный репозиторий `resokol/castlink` хранит собственные исходники по [MIT](../LICENSE), актуальные сборки, контрольные суммы и инструкции.
- Прежнее имя `resokol/castlink-releases` перенаправляется в `resokol/castlink`. Существующие выпуски, их assets, имена и SHA256 сохраняются; старые manifests и установщики используют этот адрес для совместимости. Второго публичного репозитория или зеркала нет.
- Поддерживаемые направления `client`, `server-wsl`, `linux` независимы; `server-setup` оставлен как Legacy без новых сборок. Версии и источник сборки задаёт `release-tracks.json`; для всех направлений используется `main`. Это единственная постоянная ветка; задачи готовят во временных ветках и сливают через PR, затем удаляют слитые ветки. Перед сборкой фиксируют проверенный source SHA.
- Выпуск обозначается точным тегом `<track>-v<version>-<12-char-sha>`. Общий `releases/latest` не определяет все продукты. [Каталог продуктов](PRODUCTS.md) хранит отдельные ссылки, build/source ID и SHA256SUMS.
- GitHub Latest следует последнему проверенному опубликованному Linux-выпуску. Client, Windows/WSL2 и Legacy Server Setup не меняют эту отметку. Она служит общей витриной: обновления и загрузки каждого продукта по-прежнему выбирают собственное направление, точный тег и SHA256SUMS.
- Перенос существующего выпуска сохраняет точные байты всех assets, имена, теги и контрольные суммы. Он не является пересборкой, новой проверкой бинарного пакета или обновлением установленного сервера. Исходные build/source ID внутри старых архивов не переписываются; соответствие текущей истории указывается отдельно.
- Сначала подготавливают проверяемый draft и полный набор assets: пакет, manifest, SHA256SUMS и обязательные материалы сторонних компонентов. Только после сверки состава и SHA256 выпуск становится доступным. Источники copyleft-компонентов и уведомления распространяются вместе с соответствующим выпуском.
- Клиент собирается через `windows-desktop-client.yml`, Linux — через направление `linux` в `easy-setup-packages.yml`. Windows/WSL2 использует отдельную фабрику `server-wsl-package.yml`; её пакеты, manifests, SHA256, соответствующие исходники и результаты нативного Windows CI проверяют перед отдельной ручной публикацией стабильного `server-wsl` тега. Новый Legacy `server-setup` отключён в штатном workflow. Публикация выключена по умолчанию (`publish=false`) и запускается вручную после проверки. Единственное назначение workflow и локального publisher — `resokol/castlink`; выбора primary/public нет. Собирают проверенный коммит `main`; независимые версии и теги продуктов сохраняются. Теги уже опубликованных выпусков не перемещают.
- Исторический Legacy Server Setup содержит собственный `CastLink-Linux.tar.gz` как транспортную зависимость для установки на VPS. Нельзя заменять его архивом независимого Linux-выпуска без проверки соответствующего Server Setup пакета.
- Пользовательские примечания описывают добавления, изменения, исправления и действия при обновлении. Непроверенные функции не объявляют готовыми; приватные журналы разработки не копируют в release notes.
- Инструкции синхронизируются на русском, английском и упрощённом китайском: RU — `distribution/`, EN — `distribution/docs/en/`, 简体中文 — `distribution/docs/zh-CN/`. В статьях сохраняются ссылки выбора языка. Команды, суммы и реквизиты не переводят. Лицензии и оригинальные уведомления не заменяют переводами.
- Опубликованные архивы не заменяют ради уточнения документации. Фиксированные теги сохраняют ссылки скачивания и исходную provenance. Ветки с уникальными коммитами не удаляют как часть выпуска.
