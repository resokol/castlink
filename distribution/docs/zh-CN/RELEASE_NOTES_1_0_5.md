# CastLink Server Setup 与 Linux 1.0.5 · 源代码 1.0.5

本说明适用于服务器软件包及源代码归档 **1.0.5**。Windows Client 保持 **1.0.1**，显示所选服务器的界面。可下载的发行版、准确的源代码与构建编号、链接及校验和以[产品目录](PRODUCTS.md)为准。先前发布的 1.0.4 归档及其 SHA256 保持不变。

## 变更

服务器包包含最新网络网页修复，[这些修复已于11月16日记入当前源代码的说明](RELEASE_NOTES_1_0_4.md)：

- 当前等级使用最近 **10 秒**的测量，会话丢包历史单独保留；先显示百分比，再显示丢包数量。
- 分别显示**参与者 → 服务器**与**服务器 → 演播室**。上传同时测量音频与视频；只发送麦克风音频的参与者也有等级。不累加不同链路的计数或百分比。
- 总等级采用最差的有效测量；“良好”要求所有活动链路都有最新数据。缺失反馈、首次基准采样、过期、重复或乱序的消息不会变成新的零丢包测量；信令重新连接后，仍会拒绝旧消息。
- 接收数据的有效期上限为 **6 秒**，上传反馈为 **12 秒**。重复读取缓存的 RTCP 报告不会延长有效期。更换轨道后，历史与当前测量仍分别保留；参与者新会话重新开始自己的历史。
- 复用已有 WebRTC 报告与发送周期，不增加 RTC 轮询或定时器；更新指标保留视频、菜单与焦点。

更新网站或文档不会将网页修复加入已经下载的安装归档。Windows Client 不内置独立的网页演播室；这些修复需要更新服务器。

## 更新

1. 请在**停播时**更新，并保存所需的数据与配置备份。
2. Windows Server Setup：将新包解压到独立目录，运行 `EasySetup.exe`，选择**更新**及原有本地安装或同一 VPS。独立 Linux：从新包运行 `check-updates` 与 `update`，继续使用**原有 `--state-dir`**：[说明](INSTALL.md)。保留 UUID、密钥、设置与数据卷，无需删除数据后重装。发布软件包不会自动更新运行中的服务器。
3. 就绪检查通过后，手动刷新**演播室和参与者双方的页面**，包括 Windows Client 中的页面。双方都需要加载新网页代码，演播室才能接收参与者的上传测量。
4. 检查音视频、无摄像头的参与者、独立输出，以及您使用的 `/watch` 输出。

## 平台

普通 Windows 本地 Server Setup 使用 **Docker Desktop**；独立 Linux 与 VPS 安装使用 **Docker/Compose**。无 Docker 的 Windows/WSL2 仍是独立实验渠道，本版本不会将其升级为稳定产品，也不会把 Docker 安装数据迁移到该渠道。
