# Windows/WSL2 Server 1.0.8 与 CastLink Updater 1.0.1

此版本针对 Windows/WSL2 服务器目录和受支持的迁移操作。**Linux Server 保持 1.0.7，Windows Client 保持 1.0.1，Windows/Docker 保持 Legacy 1.0.4。**这不是所有产品的统一发行版。准确软件包、标签、源码及校验值请查看[目录](PRODUCTS.md)；旧归档和标签保持不变。

## 变更

- 全新安装会询问目录，也可通过 `-InstallRoot` 明确指定。默认目录仍为 `%LOCALAPPDATA%\CastLinkServer`。
- **移动服务器…**会迁移活动 WSL 虚拟磁盘、数据、面板及属于此安装的文件。保留标识、URL、版本、房间、历史、密码、证书、设置及自动启动偏好。迁移不会更新版本。
- CastLink Updater 1.0.1 可发现 AppData 之外已登记的安装，显示不可用磁盘，并为选中的 WSL 服务器打开独立迁移操作。
- 大型工作归档及后续更新版本的工作目录使用所选卷。AppData 保留少量受保护的安装索引和操作日志。手动保存的备份归档位置另行选择。
- 支持恢复中断的迁移。**取消移动**仅在核实 WSL 磁盘仍位于原目录且取消安全时恢复原状态，不会回滚已经迁移的 VHD。

## 安装或迁移

1. 在[目录](PRODUCTS.md)中选择对应渠道的官方软件包，并验证 `SHA256SUMS`。全新安装时选择 **Installation folder**，或传入 `-InstallRoot 'D:\CastLink\Server 2'`。常规网络及安装要求仍适用。
2. 对现有服务器保留独立备份并安排停机。**必须先在原位置明确将 1.0.7 更新到 1.0.8，再迁移。**支持的准确 1.0.7 来源标签为 `server-wsl-v1.0.7-0d16de2e782c`。不要修改旧安装程序。通过 Updater 操作需要 Updater 1.0.1 或后续兼容版本。
3. 在维护工具或 Updater 中按地址和目录选中服务器，点击**移动服务器…**并输入尚不存在的新目录。核对地址、源/目标目录及所需/可用空间，再确认停机。拒绝确认不会开始迁移。操作期间保持窗口打开和磁盘连接。
4. 操作中断后，重新打开维护工具并选择**恢复事务**。如果未完成的迁移提供**取消移动**，可以选择并确认返回原位置；工具会重新核对 VHD 实际位置，若已无法取消则拒绝操作，此时应使用恢复。不要通过结束进程来取消。
5. 成功后，打开新目录中的 `CastLinkServer.lnk`，检查地址、服务器状态及连接。原先运行的服务器恢复运行，已停止的服务器保持停止。版本更新后刷新演播室及参与者页面。全新安装后可通过 `native-panel\CastLinkServer.exe` 再次打开面板。

## 要求与限制

使用同一台计算机及同一 Windows 用户、可用本地 **NTFS** 磁盘，并确保空间充足。支持空格、西里尔字母及盘符固定的外接 NTFS 磁盘。不支持 UNC/网络路径、FAT/exFAT、磁盘根目录、系统目录及符号链接或 junction/reparse point；不会接管无关文件。私有权限应用于安装目录，不改变父目录权限。安装需要 **WSL 2.4.13+**；迁移需要 **WSL 3.0.1+** 并支持官方 `--manage --move`。

**不保证可从任意旧版本更新。**目标 manifest 列出准确支持来源，包括 1.0.7 及受支持的早期 RC；仅版本号相同并不代表兼容。未完成或被修改的安装应先恢复。含限定 AppData 的固定安装程序的旧归档，须先恢复到 `%LOCALAPPDATA%\CastLinkServer` 下，明确更新，然后才能迁移。

在资源管理器中拖动目录，或手动删除 VHD、WSL 注册信息，不属于迁移或恢复。外接磁盘应按原盘符重新连接，然后刷新列表；不可用的安装不会被视为已删除。报告冲突时请保留数据和日志。迁移不是备份。不支持自动 Docker → WSL2 迁移。
