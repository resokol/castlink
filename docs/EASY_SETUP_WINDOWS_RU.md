# CastLink Easy Setup для Windows 10–11

## Панель после установки и обновления (13.10.2026)

Успешная локальная установка оставляет проверенные службы работающими и автоматически открывает панель CastLink. Повторная остановка/запуск в конце не требуется. Крестик скрывает панель в трей; эфир продолжается. Используй «Остановить службы» для остановки выбранной установки и «Запустить службы» для возобновления. Пункт трея «Остановить и выйти» завершает и службы, и панель, сохраняя данные. Это новое поведение заменяет описанное в исторических разделах закрытие с остановкой.

В заголовках мастера и панели отображаются версия и сборка. Мастер показывает собственный выпуск; панель — метаданные установленного сервера, сверенные с образом Compose. Они доступны и после остановки служб. Для старой установки без метаданных версия отмечается как неизвестная.

Docker Desktop запускается с фоновым режимом, без принудительного закрытия уже открытого пользователем окна. Первичная настройка Docker и запросы прав Windows могут потребовать участия. Графический EasySetup скрывает окно PowerShell; консольный EasySetup-Console.cmd остаётся отдельным вариантом для диагностики.


Один мастер устанавливает сервер CastLink на этот компьютер или на Linux VPS. Он загружает текущий опубликованный выпуск из публичного репозитория [resokol/castlink-releases](https://github.com/resokol/castlink-releases/releases). Учётная запись GitHub и токен не нужны.

## Состояние — 7 октября 2026



На новой главной любой посетитель создаёт собственную комнату или входит гостем по названию. Управлять комнатой можно только с её отдельным паролем студии.
## Скачать и запустить

1. Открой Releases и скачай `CastLink-Windows.zip` из актуального выпуска Easy Setup.
2. Распакуй всю папку и запусти `EasySetup.exe` или `EasySetup.cmd`: откроется графический мастер. Консольный вариант сохранён в `EasySetup-Console.cmd`.
3. Выбери установку на этот компьютер или на Linux VPS.

Мастер проверяет контрольную сумму скачанного пакета по `SHA256SUMS`. Один выпуск содержит Windows-пакет мастера и Linux-пакет сервера `CastLink-Linux.tar.gz`; версии серверного приложения в них совпадают. Linux-пакет для VPS мастер получает сам.

Если выпуск отсутствует или загрузка не удалась, установка должна сообщить причину. Исходники ветки и артефакт незавершённой CI-сборки не считаются опубликованным выпуском.

## Установка на этот компьютер

В выборе места установки есть два пункта: **«Локально»** и **«Внешний сервер»**. Для локального варианта мастер спрашивает папку установки на этом ПК.

1. Выбери «Локально» и папку установки.
2. Выбери доступ внутри локальной сети, через публичный IP или только с этого ПК; проверь обнаруженный IP и при необходимости измени его.
3. Мастер проверит необходимое ПО. Если Docker Desktop отсутствует, предложит скачать и установить его; установленный Docker запустит автоматически. Windows может запросить права администратора, включение WSL2 или перезагрузку. После перезагрузки снова открой мастер.
4. Мастер скачает пакет, подготовит настройки, запустит службы и базу данных.
5. В конце он покажет адрес главной страницы и краткие инструкции по созданию и входу в комнаты. Для локального HTTPS предложит добавить сертификат этого сервера в доверенные на текущем ПК.

Белый IP для локальной сети не требуется. Открывай адрес сервера с устройств в той же сети. На других устройствах также потребуется доверие локальному сертификату, чтобы браузер разрешил камеру и микрофон. Импорт сертификата выполняется с подтверждением владельца устройства.

Для доступа из интернета нужен доступный извне адрес; если ПК находится за роутером, потребуется проброс портов. Выбор публичного режима сам по себе не создаёт белый IP и не меняет настройки роутера. Доверенный публичный HTTPS по домену требует корректной DNS-записи и доступности сервера для выпуска сертификата.

Docker нужен на компьютере, где работает сервер. Участники открывают CastLink в браузере и ничего не устанавливают. Мастер использует существующий Docker Desktop и сохраняет его данные и выбранное место хранения виртуальной машины.

В Windows PowerShell5 исправлена передача JSON в подготовку базы: UTF‑8 BOM консоли больше не добавляется к данным команды. Если прежний выпуск остановился на «Подготавливаю базу данных…» с пустым «Docker:», открой текущий Windows пакет и повтори установку в той же папке с прежним адресом. Не удаляй состояние или тома ради повторного запуска. При отказе мастер теперь показывает шаг migrations/seed, exit code и известный безопасный диагноз; произвольный stdout команды не выводится.

## Установка на Linux VPS

1. Выбери внешний сервер и введи его IP, SSH-порт, логин `root` и пароль. Пароль вводится скрыто и используется в памяти во время подключения.
2. При первом подключении проверь показанный SSH fingerprint сервера.
3. Домен необязателен: нажми Enter, чтобы открыть сервер по его публичному IPv4, или введи домен. Папку Windows выбирать не нужно: пакет, состояние и SSH-кэш сохраняются автоматически в `D:\CastLink\Remote\<IP>-<SSH-порт>` (если диска D нет — `CastLink\Remote` в домашней папке). Повторный запуск с тем же IP/портом использует прежнее состояние; другой сервер получает отдельную папку. Мастер из прежней сохранённой папки использует её для совпадающего сервера. Сам CastLink размещается на Linux в `/opt/castlink-easy-<идентификатор>`; мастер показывает этот путь. Поддерживаемый первоначальный сценарий — Ubuntu 22.04 или 24.04, x86_64.
4. Мастер проверит доступ, предложит установить недостающие зависимости, загрузит Linux-пакет и развернёт приложение.
5. После успешной установки он покажет адрес главной страницы для создания и входа в комнаты. Docker Desktop на Windows для установки на VPS не требуется.

Если используешь домен, в DNS-панели создай его A-запись на IP VPS. Мастер настраивает домен в сервере, но изменение DNS у регистратора требует доступа к его панели. Неверная AAAA-запись при неработающем IPv6 может мешать открытию сайта и выпуску сертификата.

Для публичного IPv4 Caddy запрашивает сертификат Let’s Encrypt с профилем `shortlived` и автоматически обновляет его в сохранённом томе. Импорт собственного CA не нужен. IP должен быть публичным и доступным извне; адреса LAN, localhost и CGNAT для этого режима не подходят.

Для HTTPS и прямого медиасоединения нужны TCP 80, 443, 7881 и UDP 61000–61100. Сохрани доступ к SSH. Если провайдер ограничивает входящие подключения, разреши эти порты в его панели. TURN пока не входит в этот сценарий: из некоторых сетей с ограничениями прямое медиасоединение может не работать.

## Добавить домен к установленному VPS

Снова открой `EasySetup.cmd` из той же сохранённой папки и выбери **Установить / обновить → Внешний сервер** с прежним IP и SSH-портом. В поле необязательного домена введи домен и направь его A-запись на IP VPS. Мастер проверит DNS, изменит только Caddy и проверит HTTPS прежнего приложения. UUID, комнаты, пароли, база, тома и версия приложения сохраняются; приложение и база этим действием не обновляются. Добавление доступно для завершённой работающей установки по IP. На прежней установке по домену Enter сохраняет домен.

При сбое нового HTTPS мастер возвращает прежний Caddyfile и проверяет старый IP. Если восстановление по SSH также не удалось, он сообщает об этом и сохраняет прежнюю локальную конфигурацию; повтори мастер с прежним IP, не удаляя состояние или тома. Если Caddyfile на VPS изменён вручную, мастер откажется его заменять до согласования с сохранённой копией.

Проверено: регрессии выбора пустого домена/повторного запуска, перехода IP → домен без изменения данных и отката. Закреплённый Caddy 2.10.2 действительно выпустил сертификат IP через временный ACME Pebble с профилем `shortlived` и реальной проверкой HTTP-01; HTTPS прошёл обязательную проверку цепочки CA и IP SAN. Выдача сертификата production Let’s Encrypt на реальной VPS в этой проверке не выполнялась.

## Настройки и работа с комнатой

Настройки установки сохраняются в локальной выбранной папке или автоматической рабочей папке внешнего сервера; внутренние файлы мастер заполняет сам. Вводить профили, манифесты и отдельные команды подготовки не нужно. `EasySetup.cmd` в этой папке позволяет обновить существующий сервер; данные и прежние файлы доступа сохраняются. Для удаления внешнего сервера знать Windows-папку не требуется: мастер подключается по SSH и сам показывает установки на VPS. Явный параметр `-InstallFolder` остаётся доступен для прежних рабочих папок.

Открой показанный адрес `https://<IP или домен>/`. Выбери «Создать комнату»: введи название, пароль студии (не менее 8 символов) и при необходимости отдельный гостевой пароль. Studio панель откроется на этой же главной странице. Создатель управляет только своей комнатой; серверное Super Admin управление для этого не требуется.

Для возвращения после закрытия браузера или с другого устройства нажми «Войти в существующую» и введи название и пароль студии. Для гостевого входа достаточно названия и гостевого пароля, если он задан; гостевые приглашения также ведут на главную. Гостевой пароль не даёт права студии. Не публикуй пароли и файлы настроек. Переименовать комнату можно при выключенных эфире/предпросмотре и без гостей или другого персонала; последнюю комнату сервера удалить нельзя.

Ранее созданные комнаты и legacy ссылки продолжают работать со своим прежним доступом. Они не становятся собственностью первого посетителя. Повторная установка применяет аддитивные SQL-миграции, но не сбрасывает базу и не выдаёт новых Super Admin приглашений.
## Если установка остановилась

Сохрани сообщение об ошибке и папку установки. Не удаляй данные Docker или существующий сервер ради повторного запуска. Если мастер просит действие Windows, DNS или панели провайдера, выполни указанное действие и затем продолжи установку. Сообщение о скачивании пакета или запуске Docker ещё не означает готовность CastLink.

## Удалить установленный CastLink

В том же `EasySetup.cmd` выбери **Удалить → Локально** для выбора прежней установки на ПК. Для **Удалить → Внешний сервер** введи IP, SSH-порт, логин и скрытый пароль. Мастер подключится к VPS, найдёт установки в `/opt/castlink-easy-<UUID>` и покажет адрес и Linux-путь каждой. Выбери одну установку; Windows-папка или прежний компьютер для поиска не нужны. Для подтверждения удаления введи ровно `DELETE` заглавными буквами. Показанные сервер и Linux-путь помогают проверить выбранную установку. Пароль используется только в памяти.

По умолчанию мастер останавливает и удаляет контейнеры выбранной установки, но **сохраняет комнаты, настройки, тома базы и первоначальные пароли**. Для восстановления через установщик используй прежнюю полную папку мастера с прежним адресом. Если удаление выполнено с другого ПК, конфигурация и секреты остаются в показанной папке VPS; сохранённый Compose позволяет восстановить тот же сервер без экспорта секретов. Папка выбора удаления на новом ПК не является полным состоянием переустановки. Полный вариант **«удалить сервер вместе с комнатами и настройками»** удаляет четыре тома этой установки и известные файлы её конфигурации. Перед выполнением нужно ввести ровно `DELETE`; другой регистр, пробелы или прежний адрес отменяют действие. Если остановка или удаление томов не завершились, состояние и конфигурация сохраняются для повторного запуска. Полное удаление может выполниться частично; уже удалённые тома автоматически не восстанавливаются.

Удаление не скачивает Release/образы и не устанавливает Docker или WSL. Для локальной установки оно может открыть уже установленный Docker Desktop; если нужный движок недоступен, мастер сообщает ошибку. Для VPS мастер автоматически загружает только необходимые SSH-модули, если их ещё нет, и при необходимости предлагает .NET для SSH. Даже после удаления контейнеров с сохранением данных установка остаётся в списке по её серверной конфигурации. Исходная локальная копия состояния используется только при совпадении SSH-сервера и UUID выбранной установки.

Полное удаление дополнительно очищает неизменённые файлы и пакеты, созданные этим мастером, его образы, которые больше нигде не используются, и собственный импорт сертификата Windows. Учёт ведётся перед установкой; существовавшие ранее или изменённые пользователем файлы сохраняются. Общие образы и зависимости сохраняются, пока нужны другой установке, контейнеру, сохранённой конфигурации или приложению. Docker Desktop или пакеты Docker на VPS удаляются только при подтверждённой установке мастером и отсутствии других ресурсов/потребителей. Для старых установок без такого учёта распознаются точные пакеты CastLink; происхождение системных компонентов не угадывается.

WSL, .NET, Python, curl и системные CA сохраняются как общие компоненты; сама VPS, другие проекты и посторонние файлы также остаются. Linux использует удаление собственных Docker-пакетов без глобального autoremove/purge: общие транзитивные зависимости и пакетные настройки могут остаться. Мастер сообщает причину сохранения компонентов. Учёт общих зависимостей хранится отдельно, чтобы удаление одной установки не потеряло происхождение ресурсов, используемых второй. Legacy установки прежнего native/private installer этим действием не удаляются.

Файлы, из которых ещё работает мастер, очищаются отдельным процессом после его закрытия. Сообщение «очистка запланирована» ещё не означает завершение. При успехе служебные файлы очистки удаляются, пустые созданные мастером папки убираются; при отказе сохраняется отчёт `.castlink-cleanup-result.json` для повторной диагностики. Папка с посторонними файлами не удаляется целиком. При ошибке удаления системных зависимостей состояние сохраняется для повторного запуска.

Проверено в облачной среде: настоящий Compose keep → повторный запуск с сохранёнными данными → purge; ошибочный `COMPOSE_PROJECT_NAME` не меняет цель. Дополнительно проверяются отсутствующие/чужие ресурсы, отмена, отказ команды и несовпадающий VPS. Пользовательские ПК/VPS для этой проверки не удалялись. Genuine Windows PowerShell5 проверка включена в Release CI. Для нового удаления VPS также прошёл изолированный облачный цикл с настоящим Docker: поиск активной установки → keep → повторный поиск без контейнеров → восстановление прежних данных → purge с сохранением постороннего файла. SSH-пути в этом тесте отображались в отдельный временный облачный каталог; пользовательские VPS не удалялись.

Если прежний мастер сообщал «Не удалось проверить ресурсы выбранной установки», скачай текущий Windows пакет и снова выбери удаление прежней папки. Исправлен разбор массивов Docker inspect в Windows PowerShell5: проверяется каждый контейнер и том, а не вложенный массив как один ресурс. До этой ошибки команда удаления не выполнялась; проверки UUID, количества ресурсов и принадлежности проекту сохраняются.

## Уже запущенный сервер и занятые порты

После выбора «Установить / обновить» или «Удалить» мастер спрашивает **«Локально»** или **«Внешний сервер»**. Локально затем выбирается папка; при установке внешнего сервера рабочая папка Windows выбирается автоматически по IP и SSH-порту. Для удаления внешнего сервера мастер подключается по SSH и предлагает выбрать найденную установку на VPS; папка Windows не запрашивается. Если локальный Docker уже работает, мастер определяет прежние установки по Compose project/working_dir и UUID сохранённой конфигурации. Можно выбрать найденную установку для обновления или удаления; для новой локальной установки выбери другую папку. Установки без контейнеров/с недоступным Docker могут потребовать ручного выбора прежней папки.

**LAN** означает доступ по адресу ПК с других устройств этой сети; может понадобиться Windows Firewall и доверие HTTPS сертификату на этих устройствах. **Localhost `127.0.0.1`** доступен только на самом ПК. LAN режим слушает обычные сетевые интерфейсы, а доступ извне также зависит от роутера/NAT/firewall; он не является автоматической гарантией изоляции.

До загрузки большого GitHub пакета локальный мастер проверяет TCP443/7881 и UDP61000–61100. Если порт занимает другой найденный CastLink, он показывает папку/сервер и предлагает **остановить его службы, сохранив комнаты и настройки**. При ответе «нет» установка не продолжится; при ответе «да» останавливается только выбранный проверенный Compose проект и порты проверяются повторно. Другие приложения не останавливаются, порты автоматически не меняются. При обновлении того же UUID проекта его существующие порты не считаются чужим конфликтом.

На VPS проверка выполняется после SSH и подготовки Docker, до передачи/импорта образов и запуска Compose. Для конфликтующей прежней стандартной `/opt/castlink-easy-<UUID>` установки также доступно предложение остановить только её службы с сохранением данных. Автоматический список установок для удаления доступен также на VPS: после SSH проверяются Compose-метки и сохранённые каталоги `/opt/castlink-easy-<UUID>`, включая остановленные установки без контейнеров.

При удалении выбранный сервер показывается отдельно, и мастер явно предупреждает об остановке его служб. Удаление данных остаётся отдельным выбором. Прежние и частично запущенные установки не чистятся автоматически.

## Вход в комнату и мобильные элементы управления

На главной странице вкладка возврата называется **«Войти в существующую»**. В гостевой комнате кнопки микрофона и камеры на мобильной ширине имеют компактную высоту 44 px; кнопка выхода размещается в обычном потоке, чтобы не перекрывать настройки. Проверены настоящий React/LiveKit интерфейс и сохранённая DOM-регрессия Chromium на ширинах 320, 390, 591 и 1440 px. Прежний снимок с сильно вытянутыми кнопками точно не воспроизведён; исправлены явные размеры и воспроизведённое перекрытие выхода. Физические мобильные устройства и медиатранспорт этой проверкой не проверялись.

## Перенести локальный сертификат на другое устройство

После локальной установки мастер показывает папку `CastLink-Certificate` (при обновлении сертификата возможен суффикс). Скопируй её целиком на флешку и открой на другом Windows ПК `Install-Certificate.cmd`. Подтверди доверие только если сертификат получен от твоего сервера. Пароль администратора не нужен: импорт выполняется в доверенные корневые сертификаты текущего пользователя. Затем открой показанный HTTPS адрес CastLink.

В комплекте находится только публичный сертификат, без закрытого ключа CA. `README.txt` содержит инструкции для других систем и Firefox. `Remove-Certificate.cmd` удаляет только импорт, записанный этим комплектом на данном ПК для данного пользователя; существовавшее ранее доверие не затрагивается. Доверие на других устройствах не устанавливается автоматически.

Проверки этого обновления: focused PowerShell fixtures отмены/DELETE, принадлежности файлов, старого кэша, общих образов и отказа деинсталлятора; пакетная сборка; сертификатный комплект с двойниками хранилища. Реальный дочерний процесс в облачном Linux PowerShell7 дождался закрытия родителя, удалил только свои файлы, сохранил посторонние и оставил отчёт при настоящем отказе доступа. Это не проверка блокировок Windows: совместимость Windows PowerShell5 проверяется Release CI. Пользовательские ПК/VPS и реальные системные зависимости в этом обновлении не удалялись. Графический мастер оборачивает те же PowerShell5 команды установки и удаления. Пароль SSH остаётся в памяти; вопросы, согласия, подтверждение DELETE и доверие сертификату показываются в окне. Прервать можно на вопросе; во время активной операции мастер просит дождаться завершения. После запланированной очистки файлов доступно только закрытие: очистка начинается после выхода из процесса, а её отказ сохраняет отчёт.

## Графический мастер и скорость загрузки

Штатные Windows PowerShell5, .NET Framework и WPF запускают окно без Node/Electron/WebView. `EasySetup.exe` пока не подписан: Windows может показать предупреждение о неизвестном издателе. В окне видны вопросы, контекст SSH/DNS/занятых портов, журнал и конечный адрес сервера. Поэтапный прогресс общий для окна и консоли. Загрузки Windows/Linux пакетов, Docker Desktop, .NET и SSH-библиотек показывают реальные байты, доступный общий размер и измеренную скорость МБ/с. Для внутренней работы apt/установщиков показывается ожидание, точная скорость их загрузок не выдумывается.

Ранний Windows CI успешно скомпилировал Framework `.exe`, запустил настоящий WPF с невидимой консолью, передал SecureString и проверил точные байты JSON в дочернем процессе. Мост проверен также на ошибке, отмене, вложенном текущем выпуске и требовании закрыть окно перед очисткой. HTTP-загрузчик проверен на настоящем локальном сервере: известный/неизвестный размер, скорость, отказ и сохранение прежнего файла. Пользовательский ПК/VPS в этой GUI-проверке не изменялся; Windows10 на физическом устройстве не проверялся.

## Окно мастера: ввод, загрузки и HTTPS

«Назад» меняет предыдущие ответы только до начала установки зависимостей, загрузки или подключения SSH. После начала выполнения кнопка скрыта: завершённые действия не повторяются. Во время работы поля ввода и выбор папки скрыты.

Каждый запуск проверяет текущий выпуск на GitHub. Если распакованный пакет совпадает с текущим commit и контрольными суммами скриптов/архива образов, мастер использует его без повторного скачивания Windows ZIP. В рабочей папке сохраняется один распакованный payload для последующих запусков; исходный скачанный ZIP и папку, из которой запускался мастер, пользователь может удалить после установки. Старый или повреждённый пакет обновляется обычной проверенной загрузкой. Проверенный Linux TAR также используется повторно.

Предложение доверять локальному сертификату выбирает «Да» по умолчанию, но требует явного продолжения. Системное подтверждение Windows может потребовать отдельного ответа. При отказе сервер остаётся установленным, а мастер сообщает, что доверие не добавлено. После успешного импорта полностью перезапусти браузер. На другом устройстве нужен комплект сертификата именно этой установки; прежний сертификат после удаления данных не подходит. Отсутствие предупреждения в браузере не выводится только из наличия нескольких Caddy CA в хранилище. Окна подтверждения собственного процесса выводятся вперёд по возможности; ограничения Windows/защищённого рабочего стола сохраняются.

Контейнеры используют `restart: unless-stopped`: возобновляются после запуска Docker, если не были остановлены вручную. Для восстановления после входа в Windows включи в Docker Desktop → Settings → General пункт **Start Docker Desktop when you sign in**. Мастер не изменяет глобальный автозапуск без выбора пользователя и не обещает работу до входа в учётную запись.

Проверки этого изменения: реальные PowerShell runspace fixtures для возврата и запрета повторения эффектов; bundled payload SHA/tamper fallback; отказ импорта через exit7; scoped local/remote removal, target/ports/bootstrap/runtime scopes и упаковка. Native Windows PS5/WPF screenshot и Linux image smoke выполняются отдельными обязательными gates выпускного workflow на зарегистрированном self-hosted Windows runner.
