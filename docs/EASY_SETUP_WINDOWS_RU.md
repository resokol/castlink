# Easy Setup на Windows: локальный сервер и свой VPS

## Состояние проверки — 7 октября 2026

Это инструкция к подготавливаемому приватному выпуску, а не подтверждение завершённой установки.

- На Windows пользователя продуктовый `EasySetup.ps1 -Target local -PrepareOnly` сам открыл закрытый Docker Desktop, дождался Linux engine и завершился успешно. Следующая проверка настоящего Windows CLI (`doctor`) прошла. Папка Docker на D: и существующие данные сохранены.
- Установка Docker на чистую Windows пока не проверена: в мастере предусмотрена установка через официальный пакет winget, сообщения о WSL2 и перезагрузке.
- Продолжение сохранённой установки CastLink остановилось при проверке Docker-ресурсов (`imageRecoveryStage: 9`). Службы, база, приглашение владельца и браузерный звонок пока не подтверждены. Причина уточняется; повторная загрузка образов и сброс данных не выполняются.
- CI собрал приватный серверный образ и проверил четыре образа выпуска для Linux amd64. Реальная установка этого выпуска на VPS, выпуск публичного сертификата и звонок пока не проверены.
- Сценарий подготовки Ubuntu проверен тестами исходников; SSH-подготовка на настоящем VPS ещё не запускалась.

## Что входит в папку выпуска

`EasySetup.cmd` запускает консольный мастер двойным щелчком. `Prepare-VPS.cmd` подготавливает SSH и предпосылки своего VPS. `Continue-local.cmd`, если включён в личную сборку, продолжает её сохранённый локальный профиль. В `app` находятся CLI и встроенный Node.js, в `server/release.json` — закреплённый выпуск для VPS. Распаковывать нужно всю папку.

Рабочий каталог на ПК — `D:\GitHub\SL\studiolink`. Конкретный каталог профилей указан в `README_RU.txt` личной сборки. Сохраняй его при обновлениях: там находятся настройки установки и SSH-ключ. Не копируй содержимое профилей в GitHub и не отправляй закрытые ключи или приглашения в чат.

## Этот компьютер

1. Запусти `EasySetup.cmd`, выбери «на этом ПК».
2. Мастер найдёт и запустит Docker Desktop. Если Docker отсутствует, предложит установку. Подтверди запрос Windows; если потребуется перезагрузка или настройка WSL2, заверши её и снова открой мастер.
3. Выбери профиль и локальный режим. Loopback доступен только с этого ПК и не требует белого IP. Участники, которые открывают опубликованный сервер в браузере, Docker не устанавливают.
4. После установки мастер покажет адрес сервера и путь к закрытому файлу приглашения владельца. Приглашение одноразовое, действует 15 минут. Его истечение не устраняется повторным созданием прежнего установочного приглашения.
5. Для обычного браузера локальному сертификату Caddy нужно отдельное доверие. Экспорт сертификата и выдача свежего приглашения после приёмочной проверки остаются задачами передачи готового выпуска. Успешный `doctor` этих шагов не подтверждает.

Существующий Docker Desktop использует папку `D:\Docker\wsl\DockerDesktopWSL`. Мастер не сбрасывает её и не переносит виртуальную машину.

## Свой VPS

1. Подготовь Ubuntu 22.04 или 24.04 x86_64, доступ по SSH от root и Python3. Создай DNS A-запись домена на публичный IPv4 VPS. Если IPv6 не настроен, не оставляй неверную AAAA-запись.
2. В панели провайдера разреши TCP 80, 443, 7881 и UDP 61000–61100. Сохрани доступ к выбранному SSH-порту. Правила внешнего firewall мастер не изменяет.
3. Запусти `Prepare-VPS.cmd`. Он создаст отдельный SSH-ключ в каталоге профилей. Добавь показанный **публичный** ключ через панель/консоль провайдера. При первом соединении сверь fingerprint сервера. Если ключ защищён паролем, потребуется `ssh-agent`; мастер проверяет возможность последующего входа без ручного ввода.
4. Мастер проверит Docker Engine и Compose. Если они не готовы, предложит установку из официального apt-репозитория Docker или запуск службы. Работающий Docker не перезапускается. Новый `/opt/castlink` создаётся с правами 700; существующий несовместимый каталог не перезаписывается.
5. Приватному выпуску нужен доступ VPS к `ghcr.io/resokol/castlink-easy-web`. В предложенном SSH-терминале `docker login ghcr.io` введи GitHub username и PAT classic с `read:packages` и доступом к пакету. Токен не передаётся в аргументах команды и не нужен в чате. Docker сохраняет вход на VPS.
6. Открой `EasySetup.cmd`, выбери «Свой VPS», укажи те же адрес, root и SSH-порт, затем домен и публичный IPv4. Docker Desktop на Windows для удалённой установки не требуется.
7. Дождись результата установки, затем отдельно проверь вход владельца, HTTPS и звонок между двумя браузерами.

Этот выпуск использует прямое медиасоединение. TURN пока не входит в проверенный сценарий; для сетей, блокирующих прямое подключение, потребуется отдельная настройка TURN.

## Если мастер остановился

Сохрани сообщение и код завершения. Повтори тот же профиль только после устранения указанной причины; не удаляй его каталог, Docker volumes или журнал ради нового запуска. Код 3 после сообщения о проверенных службах означает, что браузер и медиа ещё требуют проверки. Сообщение об ошибке раньше этого этапа нельзя считать успешной установкой.

## Исполнители и проверка

Основной координатор и интегратор — GPT-6.1 Sol high. Детерминированные проверки на Windows выполняет GPT-6.1 Sol medium; Astra подключалась для проверки неоднозначного поведения native bridge. Подтверждённые результаты выше относятся к конкретным выполненным этапам, а не ко всему мастеру.
