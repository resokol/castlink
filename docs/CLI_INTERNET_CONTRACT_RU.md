# CLI Internet/TURN: защищённый контракт конфигурации

Это source-контракт для последующей интеграции setup, а не готовый Internet installer. CLI options, frozen setup cursor и реконструкция входа lifecycle ещё не подключены. Реальные DNS, ACME, публичная цепочка HTTPS и TURN allocation/relay-only media здесь не проверялись.

`BundleInput` для `network: 'internet'` требует точный объект `internet: {domain, publicIPv4, turnDomain}`. Домены — различные канонические ASCII FQDN в нижнем регистре, без URI/портов/управляющих символов; IPv4 — явный public unicast. Это декларации оператора: сами строки не доказывают владение доменом или доступность адреса. `bindIPv4` остаётся явным unicast-адресом интерфейса цели и может отличаться от публичного адреса при NAT. Для loopback/LAN дополнительные Internet поля запрещены; прежние конфигурационные байты сохранены.

Local Node и remote Python CONFIG принимают новый объект в точной схеме, сохраняют его в защищённом receipt и связывают с теми же конфигурационными fingerprints и target association. Проверка существующей конфигурации не переписывает файлы, не меняет credentials/IID и отказывает при изменении домена/адреса/renderer. Старые receipts не принимаются как Internet-конфигурация и не ремонтируются автоматически.

Кандидат renderer сохраняет четыре core-службы web/postgres/livekit/caddy и `forward_auth /api/media-admission`. Caddy использует app domain для обычного публичного HTTPS, HTTP 80 для ACME и отдельный TURN domain с ответом 503 как кандидатом ACME issuance. LiveKit получает фиксированный public IPv4 при `use_external_ip: false`, TURN TLS TCP 5349, UDP 443 и relay UDP 30000–30999. TURN/TLS TCP 443 не обещается; HAProxy, host network, author relay и NAT forwarding не добавлены. Портовый диапазон записан одной Compose range, чтобы оставаться внутри существующих ограничений CONFIG payload/file.

TURN certificate/key — только фиксированные read-only bind references в соседнем `.castlink-turn-<IID>`, с `create_host_path: false`. Эти файлы здесь не создаются и не считаются проверенными. Caddy ACME сам по себе не предоставляет их LiveKit. Отдельные защищённые bootstrap/renewal, SAN/chain/key-match/expiry POST и порядок первого ACME→LiveKit старта ещё должны быть реализованы под общей target lease.

Поэтому prerequisite readiness возвращает fail с диагнозом отсутствующего TURN TLS bootstrap/rotation до любых runtime probes. Service contract и wrapper отказывают с code 4 до executor. Фиксированные Node/Python SERVICES и START также читают защищённый receipt и отказывают с `internet-turn-tls-prerequisite-unverified` до Compose и UP/START, удерживая lease. Поле вызывающего кода вроде `certificateVerified` не принимается. Наличие вручную положенного сертификата не снимает этот отказ: проверяемая TLS стадия отсутствует.

Проверки Sol medium: новая Internet family — 12 PASS; Node/Python фактические CONFIG retry и SERVICES/START отказ выполнялись на временных POSIX fixtures с локальным фиксированным Docker shim. Native Windows Internet fixtures не реализованы и имеют явный SKIP на Windows. Отдельно проверены существующие network/bundle/prerequisite/CONFIG/remote/services/target контракты; доказательства и точные команды сохранены в `/tmp/castlink-internet-*.log`. Эти проверки не запускали Docker, сеть, DNS, ACME или устройства.
