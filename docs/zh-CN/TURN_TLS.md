# 通过 TCP 443 使用 TURN over TLS

TURN/TLS 帮助出镜者从阻止 UDP 的网络中连接。它通过加密的 TCP 连接将媒体传输到中继服务器。它不是 VPN，也不能保证穿过所有企业网络过滤器。

## 适用的网络结构

本流程仅适用于常规**直接公共 HTTPS**、标准 TCP **80/443**，以及同一 VPS 上的独立 TURN 域名。快速安装保留这一标准结构。高级 HTTP、自定义网站端口和外部 HTTPS 代理并不是自动启用 TURN/TLS 的流程，不要将以下步骤直接用于这些配置。

网站 HTTPS 代理传输 HTTP/WebSocket，本身不会转发 TURN/TLS 或建立媒体中继。不要在 TCP 443 上启动第二个独立监听器。高级网络请参阅 [INSTALL.md](INSTALL.md)；这里不承诺支持任意 TURN 结构。保留常规媒体端口，并验证真实连接，而不只是能否打开网页。

## 准备条件

- 一台运行 CastLink、可从公网访问且具有管理权限的 VPS。
- 两个不同的域名，例如网站使用 `studio.example.org`，TURN 使用 `relay.example.org`。请替换为自己的域名。
- 两个域名的 A 记录均指向该 VPS 的公网 IPv4。如果 DNS 代理不支持 TURN，请使用“仅 DNS”模式。没有可用的 IPv6 路由时，不要添加 AAAA 记录。
- VPS 允许 TCP 80 和 TCP 443 入站。标准配置通过 TCP 80 自动签发和续期证书，安装后也应保持开放。
- 服务器可通过 HTTPS 出站访问软件包来源和证书服务，并能访问 DNS。

出镜者的网络必须允许通过 TCP 443 连接 TURN 域名的 TURN/TLS。仅允许经代理访问浏览器 HTTPS 可能不够。网络管理员可能需要单独允许该传输，并将其排除在 TLS 拦截之外。

## 使用 Easy Setup 新建安装

1. 创建两个 DNS 记录，等待生效，并确认都指向正确的 VPS。
2. 在 Windows 打开 Easy Setup，在**在 Linux Ubuntu 上**卡片中点击**设置 Linux Ubuntu**，并填写 SSH 信息。与服务商提供的信息核对服务器主机密钥指纹。
3. 网站地址填写 `studio.example.org`，不含 `https://` 和路径。此方案需要网站域名，不能仅使用 IP。
4. 提示输入独立的 TURN/TLS 域名时，填写 `relay.example.org`。留空会保留普通 TURN/UDP。
5. 等待安装及证书、TURN/TLS 路由检查完成。保留向导的工作文件夹和 VPS 上的安装路径。
6. 执行下方的媒体连接验证。安装成功提示不能替代实际音视频测试。

如果向导提示 TURN/TLS 尚未就绪，请检查 DNS、TCP 80/443 以及是否有其他服务占用这些端口。排除原因后，在同一文件夹中重试未完成的安装。

## 已有安装

**已经启用 TURN/TLS：**检查 DNS、TCP 443 和证书，然后测试媒体连接，无需重新安装。

**服务器仅使用 TURN/UDP：**只开放 TCP 443 不会自动启用 TURN/TLS。需要协调配置证书、HTTPS 代理和媒体服务器。再次运行向导时，它会保留已保存的 TURN 域名，可能不会提示输入新的域名。

不要为了添加 TURN 而在正在工作的服务器上启动一次全新安装。请先备份数据和配置，并安排维护时间。已有安装需要调整时，请向[作者](https://t.me/sklvmax)说明 CastLink 版本和安装方式。无需提供密码或私钥。

本指南介绍通过向导在 VPS 上进行标准新建安装。它不是本地 Windows 服务器或按独立 Linux 指南安装（不使用 Easy Setup）后原地启用 TURN/TLS 的操作流程。不要随意复制其他安装的配置。

## 应保留的端口

| 用途 | 规则 |
| --- | --- |
| TURN/TLS 和 HTTPS | VPS 允许 TCP 443 入站；出镜者允许 TCP 443 出站 |
| 标准配置中的自动证书管理 | VPS 允许 TCP 80 入站 |
| 直接媒体传输和 TURN/UDP | 保留[主指南](GUIDE.md)中列出的媒体端口 |

TURN/TLS 改变的是出镜者与中继之间的传输方式，并不会取消服务器上的 UDP 中继端口。向导负责在同一 IP:443 上配置 HTTPS 和 TURN/TLS 路由；另一个独立服务同时监听该端口会产生冲突。无需向公网开放内部服务端口。

## 如何验证

1. 打开演播室，邀请另一台使用外部网络的设备作为出镜者加入。
2. 在演播室中为该出镜者选择 **出镜者路由 → 备用 TURN**，等待重新连接确认。所在区域的名称可能随版本不同而变化。
3. 检查出镜者的音视频和演播室回传流。要专门验证 TCP/TLS，请在 UDP 不可用、但允许 TCP 443 上 TURN/TLS 的网络中重复测试。
4. 如需技术确认，在 WebRTC 统计中检查选中的 `relay` 候选地址，以及 TURN 服务器 `turns:relay.example.org:443?transport=tcp`。字段显示方式因浏览器而异。仅有 `relay` 候选地址不能区分 TURN/UDP 和 TURN/TLS。

出镜者不需要单独填写 TURN 用户名和密码，CastLink 会自动获取连接参数。

## 故障排查

- **证书未签发：**检查两个 DNS 记录、TCP 80 的可访问性和域名证书签发策略。
- **网站可访问但 TURN 不工作：**检查出镜者网络是否允许 TURN/TLS。HTTPS 可访问不代表 TURN 可用。
- **强制 TURN 后无媒体：**检查 TURN 状态、服务器中继端口和返回流量。
- **使用一段时间后失效：**检查证书有效期、DNS 和自动续期所需的访问权限。
