# Меню устройств Кастера — 09.11.2026

Публикация разрешена владельцем для castlink.ru. База: фактически работающий
`ce172f4c24925fcb71b6e8feb46e493fd589ed20` (RC9). Исходное дерево восстановлено
точно по Git blobs/modes, root tree `dfa7bf1d5f7618f6aef297ce15d7da2e7bd10386`.
Сохранены последующие исправления сессий, диагностики, панелей, мобильной сцены и Multiview.

У микрофона и камеры отдельные нативные popover со стрелками, открывающими и
закрывающими своё меню. Кнопки закрытия внутри них удалены. Микрофон содержит
выбор входа/выхода, кнопку шумоподавления с антиэхо и локальный тест PCM-уровня.
Камера содержит выбор устройства и прежние эффекты. В mute обе части кнопки красные.

Повторно использован актуальный `GuestNoiseSuppressionControl` с подтверждением
нативной обработки и pending/unsupported состояниями; выбор устройств использует
существующий lifecycle. При закрытии меню picker остаётся смонтированным для
маршрутизации выхода. Тест микрофона локальный, не публикуется и не меняет mute;
при закрытии/смене устройства/блокировке захват завершается, включая поздние разрешения.

Chromium: изолированные меню в обеих темах на 320×844, 844×390 и 1440×900 PASS;
реальный синтетический PCM, позднее разрешение и cleanup PASS. Гидратированная
панель Кастера на восьми размерах в обеих темах PASS: все основные действия,
файловый picker/меню, Exit, mute, resize, сохранение media DOM и отсутствие overflow.
TypeScript PASS. Следы проверок в `/tmp/castlink-media-menus-*` и
`/tmp/castlink-caster-toolbar-*` текущей cloud-сессии.

Сборка и серверная публикация фиксируются отдельной квитанцией в приватном
`studiolink-ha-ops/caster-media-menus-20261109` на доверенном Windows ПК.
Возможность реального переключения физических устройств пользователя не проверялась.
Исполнитель и проверяющий: основной агент Codex. Публичные пакеты и node2 в объём не входят.
