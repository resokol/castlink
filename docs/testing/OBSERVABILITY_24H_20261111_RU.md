# Проверка истории и журнала за 24 часа — 11.11.2026

Пользователь выбрал историю показателей и журнал событий/ошибок. Реализация
расширяет локальный этап `8e86c68`, без публикации и изменения production/Windows ПК.

## Реальное поведение

Фоновый sampler работает примерно раз в 15 секунд, независимо от браузера.
Приватный SQLite-файл `runtime/server-observability.sqlite` находится внутри
существующего каталога данных. В API доступны только последние 24 часа, максимум
5760 исходных точек и 20000 структурированных событий. Срок скользящий, не календарный.
Старые физические строки удаляются небольшими порциями, не останавливая сервер;
число строк и размер файла ограничены независимо от давности.

Лимиты по умолчанию: DB 48 MiB, WAL 8 MiB, очередь 256 KiB, один сброс очереди в
секунду, до 100 событий за проход с меньшими внутренними транзакциями. Checkpoint
выполняется до и после записей. При закреплённом внешнем reader и занятом/полном
файле запись останавливается с явным unavailable; консольный вывод сохраняется.

Журнал хранит только разрешённые скалярные поля: коды/статусы/длительности/requestId.
Тела запросов, свободный текст исключений, URL, имена и идентичности участников,
пароли/секретные ключи и токены исключаются или маскируются, включая распознаваемые
credentials под формально разрешёнными именами полей. Это структурированный журнал
приложения и переходов доступности служб, а не сбор всех stdout/OS журналов.

Самплер и обработчики ошибок регистрируются однократно; unhandled rejection без
прежних framework handlers сохраняет штатное завершение процесса. При обработчиках
Next повторные ошибки наблюдаются без изменения их поведения. В build/edge сбор
не запускается. API не выполняет новые измерения и проверяет платформенную сессию
до доступа к файлу. Комнатные роли доступа не получают.

## Проверки

- Production Next сборка и TypeScript прошли. Артефакт действительно запущен на
  закреплённом Node 22.23.3 из существующего образа, с read-only исходниками и
  отдельным `/tmp` data directory. До первого HTTP-запроса БД содержала 10 замеров.
- После настоящего restart исходная точка сохранилась побайтно, сбор продолжился,
  SQLite-файл остался 0600. Оба настоящих HTTP API возвращают гостю 403/no-store.
- Реальные SQLite-тесты проверяют reopen/retention/rowcaps/размер/повреждения,
  SQLITE_FULL и занятый WAL, постраничность, секреты и очередь. Повторены также на
  Node 22 тесты storage, worker и дочерние процессы с ошибками.
- Профильные backend/API/UI/server-logging/Super Admin/i18n suites прошли.
  Независимый GPT-6.1 Sol high review завершён; материальные замечания исправлены
  с регрессионными тестами (WAL, скрытые raw gaps, секреты и обработчики ошибок).
- Chromium production без обхода CSP: desktop 1366/dark, mobile 390/light,
  периоды 1h/6h/24h, точные 30 sec/2 min подписи, фильтр error, cursor pages,

  продолжении серверного сбора. Stale-службы не подписываются как здоровые.
  На mobile уровень события виден без горизонтального скролла: учтён конфликт
  с динамической темой, задававшей таблицам min-width 980px. Журнал ограничен
  по высоте; проверены вычисленные границы и итоговый скриншот.
  Вход/overview подставлены только браузерным тестом; OS-замеры настоящие,
  journal fixtures синтетические и находятся только в отдельном тестовом data.

пользовательские данные. Скрипт: `apps/web/tests/server-observability-benchmark.cjs`.

| --- | --- |
| Запись точки | 2.70 мс |
| Пакет 100 событий | 11.06 мс |
| Чтение 24 ч | 56.71 мс |
| Страница ошибок | 3.32 мс |

DB 6803456 байт (~6.5 MiB), DB+WAL+SHM 6836224 байта. Ответ 24 ч — 298623 байта,
до 720 пиковых точек. Пики RAM/диска сохраняют согласованную пару used/total;
разрывы исходного сбора передаются отдельным gapBefore, а не соединяются линией.
Это измерение хранения на тестовых данных; LiveKit RPC и характеристики целевого
сервера влияют на общий расход. Нет дополнительной службы БД или npm-зависимости.
Для разработки нужен Node 22.13+ (в пакетах закреплён 22.23.3); минимальная версия
отражена в engines/README из-за встроенного SQLite.

## Ограничения

При большом потоке журнал может быть короче 24 часов из-за размерных лимитов; это
подписано в интерфейсе. При редком откате после вытеснения записей под давлением
на диск счётчик пропусков может быть консервативно завышен; на сохранность данных,
политику доступа и работу сервера это не влияет. Целевой Windows/WSL proof и
публикация установщиков остаются отдельными gate прежнего этапа.
