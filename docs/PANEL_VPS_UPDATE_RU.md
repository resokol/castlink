# Обновление VPS из панели студии

Кнопка «Обновить» относится к уже подключённой установке VPS в разделе «Серверы комнаты». Она не создаёт вторую установку. Доступ — создатель комнаты; общие серверы, настроенные при установке, через эту кнопку не обслуживаются.

Это отдельный путь обновления через студию и `server-provision-vps.py`. Его backup/maintenance/rollback ниже не описывают поведение пользовательского Windows-мастера или standalone Linux CLI `update`: для них действуют [INSTALL](../distribution/INSTALL.md) и [Linux manual](../distribution/LINUX_MANUAL.md). Опубликованные пакеты перечислены в [каталоге продуктов](../distribution/PRODUCTS.md).

## Порядок

1. Обновить локальный CastLink до выпуска с этой кнопкой и открыть студию.
2. У нужного сервера нажать «Обновить». IP и идентификатор берутся из сохранённого подключения. SSH-порт можно изменить, если он отличается от 22.
3. Проверить SSH fingerprint; ввести пароль root либо выбрать приватный ключ. Данные SSH не сохраняются.
4. Запустить обновление вне эфира. В панели отображаются этапы и результат.
5. После успешного обновления заново подготовить резерв и включить автоматику; дождаться подтверждения готовности.

Проверяется текущий официальный выпуск и его контрольная сумма. Меняется только приложение web существующей установки; UUID, профили связи, инфраструктурные сервисы и их настройки сохраняются. Перед заменой создаётся закрытая резервная копия. Обновление с несовместимыми SQL-миграциями требует отдельной процедуры и автоматически не выполняется.

На время замены сервер закрывает новые подключения. При неудачной проверке нового приложения до открытия доступа восстанавливаются прежнее приложение и его данные. Если результат снятия режима обслуживания неизвестен, требуется проверка состояния вместо автоматического отката уже доступного приложения.

Потеря связи с панелью не означает отмену удалённой операции. Не запускайте повторную установку поверх неизвестного состояния. Если автоматическое восстановление не удалось, сохранённая копия остаётся на VPS для восстановления оператором.

## Проверки

Тесты с подменённым Docker не являются проверкой обновления настоящего VPS. Действующий AdminVPS пользователя этим этапом автоматически не обновляется.
