# CastLink Desktop: выходы для vMix

> **For agentic workers:** Use superpowers:executing-plans and superpowers:test-driven-development. Work on the isolated `codex/desktop-vmix-outputs` branch of `resokol/castlink`.

**Goal:** Windows CastLink Desktop передаёт видео и звук постоянного слота в штатный вход vMix.

**Architecture:** Клиент получает разрешённые треки существующего слота. Отправитель каждого слота живёт отдельно от просмотра студии и использует постоянный адрес или имя. SRT использует H.264 и AAC-LC в MPEG-TS, NDI и OMT получают отдельные адаптеры SDK.

**Spec:** Согласованный макет «Слоты кастеров → Выходы для vMix» от 28.11.2026. Выбор NDI, OMT и SRT. Для SRT предусмотрены режим, адрес, задержка, пароль, длина ключа, отдельные порты и необязательные Stream ID.

## Общие условия

- Основная студия явно запускает и останавливает выходы. Подписка проверяет существующее назначение и права слота.
- Настройки и состояние локальны для Desktop. Пароли и подписанные ссылки не попадают в телеметрию или сообщения об ошибках.
- Смена кастера сохраняет имя источника и порт. Потерянный или освобождённый слот прекращает показывать устаревшее видео и воспроизводить звук.
- Обычный состав включает двоих или троих кастеров. Изменение состава во время эфира меняет назначение слотов. Третий слот может опустеть или снова заполниться без пересоздания входа vMix и остановки остальных слотов.
- Браузерные ссылки выходов продолжают работать. Публикация пакета и изменение работающего сервера требуют отдельного этапа.

## Проверки

- [x] **SRT.** Настройки проверяют режим, адреса, UDP-порты, задержку, шифрование и Stream ID. Для Caller и Listener используется FFmpeg. В режиме Rendezvous FFmpeg передаёт MPEG-TS локальному компоненту srt-live-transmit, который поддерживает разные адреса сторон.
- [x] **Передача.** Независимые приёмники получили H.264 и AAC-LC через зашифрованный SRT. Rendezvous проверен на двух loopback-адресах с одинаковым UDP-портом.
- [x] **Подписка на медиа.** Три выхода 1080p30 с настройкой до 8000 кбит/с приняли разные видео и звуковые сигналы при переходе пара → тройка → другая пара. Пустой третий вход переключился на чёрный кадр и тишину. Проверены SID, поколение допуска, источник и отзыв ссылки.
- [x] **Управление.** Проверены интерфейс Chromium, права главного окна, повторное открытие панели без остановки выходов и дочерний процесс в Electron 45.4.1.
- [x] **Нативные адаптеры.** NDI и OMT проверены через их C ABI с тестовыми библиотеками. Временная упаковка зависимостей содержала нативные файлы LiveKit и Koffi для Windows x64.
- [ ] **Windows и vMix.** Собрать установщик и проверить штатные входы vMix, обнаружение настоящих отправителей NDI и OMT, четыре одновременных выхода, синхронизацию и повторное подключение.

## Настройки для пилота

Откройте «Слоты кастеров → Выходы для vMix» в полной версии CastLink Desktop. Подготовьте три постоянных слота, чтобы третий вход можно было заполнить позже. Для vMix на том же ПК используйте CastLink SRT Listener и vMix SRT Caller, адрес 127.0.0.1, отдельный UDP-порт для каждого входа и начальную задержку 200 мс. По умолчанию выход формируется в 1080p30 с пределом 8000 кбит/с на слот.

Для SRT выберите установленный FFmpeg с libx264, AAC и SRT. Для Rendezvous дополнительно укажите srt-live-transmit и при необходимости локальный IP. NDI использует установленный NDI Runtime. Для OMT выберите libomt.dll из совместимого Windows x64 runtime рядом с его библиотекой libvmx. Пароль SRT и Stream ID вводятся для запуска и на диск не записываются.
