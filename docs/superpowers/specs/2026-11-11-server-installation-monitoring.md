# Установка сервера и мониторинг

Пользователь поручил установку серверной части Linux одной командой и Windows без
Docker. После обсуждения выбран отдельный WSL2-дистрибутив с готовым сервером:
Windows 11 22H2+ x64, актуальный WSL2, mirrored networking. Первое включение WSL
может требовать перезагрузки. Полностью нативный Windows не входит в этот этап.
Дополнительно нужны графические показатели комнат, кастеров и потребления ресурсов.

## Подходы

- Linux: загрузчик поверх существующего проверяемого Compose-пакета; сохраняются
  init/start, пароль создания комнат, TURN/TLS и существующие имена данных.
- Windows: отдельный готовый Ubuntu24.04 rootfs с systemd, Node/Next, PostgreSQL,
  LiveKit, Caddy, HAProxy и изолированным PPTX worker. Docker используется только
  производителем при сборке, в пользовательском дистрибутиве Docker отсутствует.
- Native Windows потребовал бы нового sandbox PPTX и TCP443 мультиплексора;
  отклонён для этого этапа, чтобы сохранить работающую серверную архитектуру.

## Обязательное поведение

Установщики привязаны к одному выпуску, репозиторию и SHA256. Не выполняют исходный
код из приватного репозитория, не выбирают общий releases/latest. Загрузка,
проверка и запуск образуют полный путь; ошибка передаётся ненулевым exit code.
Повторная установка сохраняет UUID/секреты/данные и не обновляет работающий сервер
автоматически. Чужие файлы, дистрибутивы и службы не присваиваются и не удаляются.

Linux bootstrap сохраняет пакет и state по стабильному абсолютному пути. При
curl|bash интерактивный ввод идёт через терминал. Установка Docker выполняется
только явно выбранным режимом подготовки. Завершённая установка не перезапускается.

Windows installer проверяет ОС и WSL2, импортирует только собственный дистрибутив,
показывает необходимость перезагрузки. Не выключает все WSL-дистрибутивы и не
переписывает чужие настройки сети. Службы непривилегированные; конвертер без сети,
с ограничением памяти/CPU/PID и приватными временными файлами. Адрес и пароли
вводятся при настройке; секреты не выводятся в журналы. Медиадоступ и TURN/TLS443
сохраняются. Готовность HTTPS/БД отличается от доказательства реального медиазвонка.

Мониторинг расширяет существующий Super Admin с его авторизацией. Серверные
показатели не выдаются гостям или владельцу отдельной комнаты. История ограничена,
графики используют реальные образцы и время замера. Нет замера/устаревание/ошибка
отличаются от нуля. CPU, память, диск и сеть подписаны по фактической области
замера (WSL guest / container / Linux); host и process не смешиваются.

## Проверка и выпуск

Тесты проверяют выбор выпуска, суммы, архивы, повторный запуск, конфигурации служб,
сохранность данных и отрицательную авторизацию метрик. Отдельно проверяются
PowerShell parser/fixtures и сборка web. Настоящая Windows/WSL установка,
перезагрузка, внешний HTTPS и принудительный TURN требуют целевой Windows.
Отсутствие такой проверки явно фиксируется. Пакеты и документация не объявляют
неопубликованный выпуск доступным. Публикация и изменение production в задачу
не входят. Пользовательские инструкции обновляются RU/EN/zh-CN.
