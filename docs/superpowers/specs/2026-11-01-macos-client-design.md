# Полный перенос CastLink Client на macOS
Дата: 2026-11-01. Согласовано владельцем 2026-11-02 с обязательной поддержкой Intel x64 наравне с Apple Silicon arm64. Реализации пока нет.

## Требования владельца
Перенести весь Windows-клиент, без сокращения функциональности. Использовать только публичный resokol/castlink и самый последний выпуск клиента. Собирать и тестировать через GitHub Actions. Целевой пользовательский Mac — M1, сейчас не подключён.

## Подтверждённая исходная база
Публичный client-v1.0.0-rc.9-a994895c5fa9 от 2026-10-26, полный SHA a994895c5fa976a073965f845ba23a4f61f94387. Проверены GitHub release list, tag ref и файлы через GitHub API. Копия получена напрямую из публичного репозитория.
main на момент проверки: 48478006e4348f1e185fb8066ee6233481a8a6a2, на 13 коммитов впереди. Это не последний выпущенный клиент. По указанию владельца функциональный эталон — тег клиента; интеграция с актуальным main требует явного разбора diff, а не подмены базы.
Прежний адрес castlink-releases перенаправляет в castlink. Приватный репозиторий и локальный studiolink не являются источником этой работы.

## Подход
Рекомендация разработчика: сохранить Electron 44.9.0, интерфейс и общие протоколы; заменить только платформенные реализации.
Полная перепись на SwiftUI дублирует веб-клиент и повышает риск потери поведения. Wine/виртуализация не дают самостоятельного macOS-клиента с системными разрешениями и интеграциями. Поэтому они не предлагаются как путь переноса.
Swift/Objective-C helpers и фиксированные Automation-команды — кандидаты для нативных адаптеров, не уже подтверждённые реализации.
Обязательные архитектуры — Apple Silicon arm64 (включая M1) и Intel x64. Для обеих нужен полный одинаковый функциональный объём, отдельные нативные сборки и проверки GitHub Actions. Проверки arm64 не доказывают поддержку Intel через Rosetta. Минимальную macOS определить по необходимым API захвата и нативным проверкам, зафиксировать до первого кандидата; поддержка Intel сама по себе не обещает работу на всех старых версиях macOS.

| Область | Что должно сохраниться | Работа для macOS |
| --- | --- | --- |
| Общий клиент | Вход, роли, приглашения, комнаты, камера/микрофон, выбор устройств, чат, резервирование, настройки, языки | Общая Electron/WebRTC основа, macOS меню/клавиши/жизненный цикл и системные разрешения |
| Демонстрация | Экран/окно, точный выбор источника, отдельные Stop/Hide, плавающая панель | Захват с проверкой Retina, мониторов, Spaces и полноэкранного режима |
| Звук презентации | Только выбранное приложение, независимость микрофона/приватной связи | Проверить ScreenCaptureKit application audio filter, исключение собственного приложения, существующий формат PCM |
| PowerPoint | PPTX prepare/start/status/goto/animation-step, делегирование, привязка к выбранному показу | Проверить PowerPoint for Mac Automation и идентичность окна; не заменять оригинальный показ PDF-конверсией ради объявления паритета |

| Управление ПК | Выдача/запрос/отзыв, mouse/keyboard/text, безопасная остановка | Native helper на CGEvent/Accessibility, геометрия, раскладки, физические удержания, watchdog |

| Серверный мастер в клиенте | Установка, обновление, удаление своей локальной установки и Ubuntu по SSH | Заменить WPF/PowerShell GUI; повторно использовать проверяемые серверные операции, подтвердить Docker/runtime на M1 |
| Обновления клиента | Ручная/отключаемая автоматическая проверка, подтверждение скачивания и установки, сохранение настроек | Выбор macOS/архитектуры, SHA256, установка app, корректный отказ/повторный запуск |

Публично проверены Windows-only guards в package.cjs, setup.cjs, process-audio.cjs и Windows ресурсы native-presentation-desktop.cjs. В публичном package.json есть только package:win. Существующий macos-desktop-provenance.yml проверяет Docker Desktop, ограничен private repo/другой веткой и не собирает CastLink: нужен отдельный workflow.
Остальные области таблицы подлежат построчной сверке публичных исходников перед реализацией. Полноту определяет инвентаризация всех пользовательских действий Windows-клиента, не только эта стартовая таблица.

## Неизменяемые контракты
Сохранить публичные CRITICAL_INVARIANTS, trusted top-frame IPC, origin checks, явное локальное согласие, привязку capture/session/grant, серверные сроки полномочий и защиту от повтора.
Native helper не получает произвольные shell-команды; утрата идентичности/геометрии или истечение полномочий запрещают ввод и освобождают удержания. Отзыв управления не останавливает исправные камеру/микрофон/демонстрацию.
Hide панели не означает Stop. Загрузка файла не запускает показ. Запрос системных прав не заменяет согласие на управление.
Никаких скрытых замен звука приложения общим системным звуком и никаких capability=true без доступной реализации.
Настройки и пользовательские данные сохраняются при обновлении/удалении согласно существующим правилам; серверы пользователя для тестов не используются.

## Проверки и критерий готовности
GitHub Actions macOS arm64 и Intel x64: отдельные нативные jobs, чистая установка закреплённых зависимостей, сборка native helpers и app, unit/contract/security regression, запуск упакованного приложения, проверка ресурсов/URL схем и доступные реальные native fixtures. Все результаты привязаны к source SHA и архитектуре. Отсутствие успешной проверки любой архитектуры блокирует заявление о готовности полного двухархитектурного выпуска.
Windows regression остаётся обязательной для общего кода; Linux/source tests покрывают общие протоколы. Проверять готовый пакет, а не только исходники.
Для PowerPoint нужен реально установленный и работоспособный Office. Доступность GUI/TCC/аудиоустройств на hosted runner проверяется экспериментально. Отсутствие устройства или разрешения — NOT VERIFIED, не успешный тест. Не обходить TCC для имитации пользовательской приёмки.
Отдельные критерии приёмки: PPTX с анимациями и медиа, звук только выбранного приложения, переключение окон/Spaces, Retina/масштаб/мониторы, grant/revoke/Stop/disconnect/сон/блокировка, установка/обновление с сохранением настроек.
Если часть интерактивных сценариев не воспроизводится на GitHub runner, она остаётся явно непроверенной до доступной интерактивной macOS-среды соответствующей архитектуры; это не повод исключать функцию из реализации.
Полный перенос готов только после прохождения матрицы функций; промежуточная запускаемая app — кандидат, не обещание паритета.

## Порядок работ и выпуск
Сначала проверить наиболее рискованные API: PowerPoint animation-step/source binding, изолированный звук, точный native input и среду GitHub runner. Затем реализовать общие платформенные границы и нативные адаптеры, мастер/обновления, упаковку и полную регрессию.
Промежуточные сборки хранить в GitHub Actions artifacts. Не заменять существующие assets/теги. Публичный release — отдельный проверяемый шаг после готовности; создание кандидата не означает публикацию.
Apple Developer credentials сейчас не проверены: неподписанный/ad-hoc кандидат годится для технических проверок, не объявляется notarized.
Открытые технические вопросы решает разработчик по результатам проверок; невозможность эквивалентной функции сообщается как конкретное ограничение, без молчаливого урезания объёма.
