# Постоянный обновлятор CastLink

Статус: проект для согласования, код продукта пока не изменяется.
Дата: 21.11.2026. Автор: Codex.

## Что выбрал владелец

Обновлятор нужен для всей поддерживаемой линейки: Windows Client,
Windows/WSL2 Server и Linux/Ubuntu Server. Он запускается на каждом компьютере,
а не управляет удалёнными серверами из общего окна. Пользователь один раз
получает точку запуска, затем не скачивает вручную новый инструмент для каждого
выпуска. Node2 владелец обновляет самостоятельно.

## Варианты

1. **Выбран: постоянная точка запуска на каждом компьютере.** Использует
   существующие средства обновления продуктов, получает их актуальные версии
   автоматически. В Windows — общий ярлык, в Linux — команда. Не требует
   постоянного агента, новых сетевых портов или учётных данных других машин.
2. **Отклонён владельцем: общее окно управления машинами.** Добавляет SSH,
   сохранённые подключения и удалённые задания; удобно для централизованного
   администрирования, но это иной объём работы.

## Предлагаемое поведение

- Windows: постоянный ярлык «Обновить CastLink». Показывает обнаруженные локальные
  Windows Client и WSL-серверы, их текущие и доступные версии. Для нескольких
  серверов показывает адрес и папку; выбор всегда относится к конкретной установке.
- Linux: `castlink check-updates` и `castlink update`. При единственной
  зарегистрированной установке каталог определяется автоматически; при нескольких
  требуется выбор или явный `--state-dir`. Указанный каталог сверяется с настоящим
  состоянием установки, а не создаётся заново.
- Кнопка обновления клиента и кнопка обслуживания WSL используют тот же механизм,
  что и постоянный ярлык. Пользователь без Windows Client также может обновить WSL.
- При запуске проверяются стабильные выпуски своего продукта. Проверка сама
  не останавливает службы и не устанавливает серверный пакет. Перед применением
  показываются продукт, установка, текущая/новая версия и примечания, затем
  запрашивается подтверждение. Отмена оставляет работающую установку как есть.
- Проверку при запуске можно отключить; ручная проверка доступна всегда.
  Новый системный таймер или фоновая служба не добавляются. Существующие
  пользовательские настройки автоматической проверки сохраняются.
- Уже актуальная версия сообщает «Обновлений нет». Ошибка связи сообщает об ошибке,
  а не об отсутствии обновлений. После исправления сети используется тот же ярлык
  или команда. Само приложение продолжает работать.
- Интерфейс, сообщения и инструкции синхронизируются на RU/EN/zh-CN.

Это предложенные автором детали поведения; владелец пока выбрал охват и
размещение обновлятора, но отдельно эти детали ещё не утверждал.

## Существующая основа

- `apps/desktop/src/updates.cjs`: поиск отдельных каналов, сравнение версий,
  скачивание установщика клиента, проверки и подтверждение установки.
- `scripts/server-wsl-maintenance.ps1` и `server-wsl-maintenance-ui.ps1`:
  обнаружение установок, выбор выпусков, проверки совместимости, обновление,
  восстановление прерванных операций. Новые guest helpers проверяются по manifest.
- `scripts/package-server-wsl.mjs`: нынешний `CastLink-Maintenance.cmd` запускает
  bootstrap, закреплённый за manifest своего ZIP. Это полезный инструмент точного
  выпуска, но не механизм получения новой версии Windows-части обслуживания.
- `scripts/linux-compose-setup.py`: `check-updates` и `update` уже скачивают
  полный Linux-пакет с проверками и сохраняют прежний state-dir.
- `scripts/install-server.sh`: первоначальная установка; повтор запуска над
  завершённой установкой не заменяет штатный `update`.

## Архитектура

Постоянный небольшой запускатель отдельно от версионированного кода обновления.
Windows использует имеющийся Windows PowerShell, Linux — shell и уже требуемый
Python 3. Не добавляем Node/Electron как обязательную зависимость сервера.
Общий контракт обнаружения выпусков и одинаковые контрольные примеры проверяются
на обеих платформах; одинаковый исполняемый файл для разных ОС не требуется.

Обновлятор имеет независимый канал `updater` в существующем репозитории
`resokol/castlink`, со своей версией и явно перечисленными платформенными файлами.
Manifest объявляет schema/protocol version, платформу, точный source commit,
размеры и SHA256 файлов. Пакет не содержит серверные данные. Публикация updater
не меняет GitHub Latest другого продукта и не требует пересборки приложения.

Запускатель получает каталог GitHub Releases через HTTPS, выбирает новейший
стабильный совместимый `updater` по версии, закрепляет числовой release ID,
тег и хеш manifest из GitHub asset metadata. Получает ограниченный набор
файлов этого выпуска, проверяет размеры/хеши/пути, затем атомарно активирует
его в своём каталоге. Не исполняет содержимое ветки main или непроверенный
текст ответа сети. При неизвестной версии протокола останавливает обновление
с понятным сообщением, сохраняя установленные продукты.

Новая версия инструмента запускается из собственного каталога, без перезаписи
работающего процесса. Постоянная точка входа не содержит номер целевого
серверного релиза. Обновляемый инструмент выбирает пакет конкретного продукта:
`client`, `server-wsl` или `linux`, независимо от общего `/releases/latest`.
Проверяются версия, стабильный статус, соответствие продукта/архитектуры,
полнота пакета и совместимость с текущей установкой. Неподдерживаемый прямой
переход объясняется пользователю; неподтверждённая цепочка миграций не строится.

Windows Client обновляется существующим проверяемым установщиком. WSL использует
проверенные средства обслуживания целевого выпуска, включая Windows-часть,
а затем существующую транзакцию обслуживания. Linux использует штатный путь
`update` с прежним абсолютным state-dir. Обновлятор не дублирует перенос базы,
переключение WSL-поколений или управление Docker новым самостоятельным механизмом.

## Однократное подключение существующих установок

На сайте и GitHub появляются постоянные ссылки «Обновлятор Windows» и
«Обновлятор Linux». Для уже установленных 1.0.7/Client 1.0.1 пользователь один
раз скачивает и запускает маленький установщик обновлятора. Он регистрирует
точку входа и обнаруживает либо предлагает явно указать существующую установку.
Подключение обновлятора не запускает первоначальную установку сервера, не меняет
его версии и не перезапускает его. Будущие установщики включают регистрацию
этой точки входа. Старые опубликованные архивы сохраняют точные байты и хеши.

Legacy Windows/Docker распознаётся как Legacy и не подменяется WSL или Linux.
Существующее обслуживание Legacy сохраняется; новые Legacy-пакеты и автоматическая
миграция не входят в задачу. macOS не является опубликованным поддерживаемым
каналом и в этот проект не включён. Удалённый SSH и автоматический обход машин
не добавляются.

## Данные, ошибки и права

Обновлятор хранит только собственные файлы, версии, настройки и ссылки на
установки; секреты и копии пользовательских данных в свой реестр не переносит.
Установки проверяются по существующим идентификаторам и квитанциям владения.
Не выбирается автоматически первая найденная папка. Права администратора/root
запрашиваются только для действий, которым они действительно нужны.

Проверенные загрузки кешируются; повреждённая или неполная загрузка не исполняется.
Один экземпляр обслуживает конкретную установку, предотвращая конкурирующие
обновления. Очистка касается только принадлежащего обновлятору кеша, сохраняет
текущую и предыдущую рабочие версии инструмента. Общий Docker prune не используется.
Сбой скачивания/проверки оставляет продукт неизменным; сбой применения обрабатывает
штатный механизм восстановления продукта. Универсальный автоматический откат
любых изменений базы данных не обещается.

Первый bootstrap получает доверие так же, как нынешние установщики: официальный
GitHub/HTTPS и опубликованные контрольные суммы. SHA256 доказывает соответствие
файлов опубликованному выпуску, а не наличие цифровой подписи издателя.

## Критерии готовности

1. Однажды установленный запускатель получает две последовательные тестовые версии
   самого updater и две версии пакета без повторного ручного скачивания запускателя.
2. Windows Client, WSL и Linux выбирают только свой стабильный совместимый канал;
   RC, чужой продукт, понижение версии и неполный выпуск не применяются автоматически.
3. Повреждённый файл, подмена manifest, неверная архитектура, небезопасный путь,
   неподдерживаемый протокол, сетевая ошибка и одновременный запуск проверены тестами.
4. Несколько установок не смешиваются; обновление сохраняет UUID, адрес, настройки,
   учётные данные и серверные тома по контрактам соответствующего продукта.
5. Проверка, отмена и подключение обновлятора не перезапускают продукт. Сбой
   активации инструмента сохраняет предыдущую рабочую версию и повторяемый запуск.
6. Проверены Windows PowerShell/запуск интерфейса, Linux-команды и упаковка.
   Реальные обновления проверяются на отдельных тестовых установках; изменение
   node2 остаётся за владельцем. Недоступные физические сценарии обозначаются явно.
7. После сборки и проверки публикуются отдельный стабильный updater, постоянные
   ссылки, патчноуты и инструкции трёх языков. Выпуск не изменяет старые архивы.

## Оставлено исполнителю

Точные имена внутренних файлов, небольшие функции/модули, формат локального
реестра, разбиение тестов и техническое представление журнала операций.
Внешние команды, продукты, сохранность установок и обязательное подтверждение
применения определены выше. Новые продуктовые функции не добавляются.
