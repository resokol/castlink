# Параметры камеры в карточке гостя

## Поведение

В карточках основной студии, администратора и модератора добавлены стандартный и пользовательский режимы камеры, разрешение и FPS. Изменения сначала остаются черновиком; «Применить» отправляет команду, «Отмена» возвращает полученное состояние. Режим недоступен без поддержки браузера или при старой вкладке гостя. Команда не включает выключенную камеру.

Параметры — запрошенные ideal-значения. Камера вправе выдать ближайшее поддерживаемое разрешение/FPS. «Камера · факт» показывает getSettings() активного трека, отдельно от запроса. Список FPS: максимум устройства, 60, 50, 30, 29.97, 25, 24, 20, 15, 10, 5, 2. Максимум требует getCapabilities(); отсутствующие, нечисловые и превышающие предел 1000 значения отвергаются. YUY2/MJPEG/цветовое пространство остаются настройками драйвера/OBS, поскольку браузер их не предоставляет.

## Совместимость с текущей камерой

Источник capture intent — доверенная серверная metadata участника. Существующий staff-only API комнаты записывает cameraCapture после проверки текущего SID и до доставки команды. Настройка сохраняется в серверном кеше сессии и metadata следующего подключения. Локальные choices.cameraCapture/height не определяют публикацию. Предварительная AV-проверка без room metadata запрашивает нативные пропорции, height1080 и30FPS.

Без явного cameraCapture сохраняется прежний height-only preset из metadata videoHeight720/1080; отсутствие значения означает1080. Width/aspectRatio не добавляются, resizeMode none запрашивается с прежним совместимым повтором без resizeMode. Пользовательский width/height задаёт только явный выбор персонала. Стандартный режим устройства очищает размер/FPS, сохраняя запрос resizeMode none.

Быстрый переключатель720/1080 удаляет cameraCapture и возвращает height-only/30FPS. Обратный выбор пользовательских параметров имеет приоритет над сохранённым videoHeight. Когда действуют параметры из карточки, быстрый переключатель показывает отдельный пункт, чтобы не выдавать прежние720/1080 за текущий запрос.

Настройка metadata означает запрос, а не доказательство поддержки камеры. Ошибка применения/доставки не выдаётся за успешный ACK; серверный запрос остаётся сохранённым, аналогично существующему быстрому разрешению. Оператор может заменить его другим режимом или быстрым пресетом. Actual-поля остаются измерением, а не копией желаемых значений.

## Очередь и границы

Capture, camera enable/disable, codec, device change и восстановление используют существующую очередь камеры. Проверяются поколение/SID и актуальность capture intent перед повтором или восстановлением constraints. Команда старой сессии не меняет камеру новой; быстрый staff override отменяет прежний custom retry/rollback. Внутреннее восстановление reconnect использует вариант InTask, без вложенного ожидания той же очереди.

Capture-команда не перепубликует камеру, не выбирает другое устройство, не меняет микрофон, аудио, экран, Studio Return или комнату. При выключенной камере настройка ждёт следующего явного включения. Битрейт сохраняет прежний бюджет; только явно заданный capture использует фактический FPS камеры. Валидация Studio Return не расширяется без специального opt-in.


## Проверка

Используйте профильные `guest-camera-capture`, `guest-camera-resolution-ui`, `guest-video-codec`, `guest-device-switch` и `guest-resume` тесты. Отдельно проверяйте реальную камеру, дробный FPS, аппаратный fallback и разрешения в целевых браузерах; source fixtures не подтверждают поддержку устройства.
