## Система
- Бренд CastLink. Основной публичный адрес https://castlink.ru. Локальный публичный адрес https://caster.em.studio. lunkaonline.ru допустим только для обратной совместимости/перенаправления.
- Одна основная студия публикует Studio Return. Дополнительные администраторы и модераторы не захватывают её lease, не перезапускают устройства и не прерывают эфир.
- Микрофон — вход звука; наушники/динамики — выход. Личный мониторинг не меняет эфир. Камера, микрофон и выход выбираются отдельно.
- Администратор может явно выбрать устройства компьютера основной студии через studio-control: только из её актуального списка и в своей комнате. Камеру/микрофон менять при выключенном эфире; выход — если браузер студии поддерживает setSinkId. Выбор не захватывает primary lease. Список устройств не выдавать гостям/ограниченным модераторам; старые команды устройств не повторять при изменениях FPS/битрейта/усиления.
- Studio Return: целевые значения по умолчанию 1920×1080, 60 FPS, 12000 кбит/с для новых студийных настроек; FPS 25/30/50/60; выбор битрейта студии и /watch: 500, 1000, 2000 … 12000. Сохранённые параметры текущего эфира не повышать автоматически. Источники вроде vMix нельзя ошибочно отклонять из-за неточного описания capabilities. Настройки качества меняются во время эфира.
- Измеренный битрейт/FPS не подменять заданными лимитами. Различать отсутствие замеров, устаревшие замеры и офлайн. Администратор получает замеры основной студии.
- Пароль комнаты проверяется на сервере. Гостевые инвайты допускают вход без пароля. Инвайты ролей проверяются сервером, имеют срок и отзыв; секреты не писать в логи, GitHub, git или URL query.
- Перенос серверов переносит только участников текущей сессии, не перенаправляет будущих гостей старой комнаты. Сохранять выбранные устройства и роль. Для локальных подключений с внешних IP 79.120.36.254 и 79.104.52.243 предусмотрен локальный маршрут 192.168.53.68. Не менять MikroTik во время работы.
- Приватное обращение доставляется только выбранному получателю; скрытие/приглушение на чужом клиенте не является приватностью.
- Обновление страницы основной студии может прервать эфир: не обновлять принудительно. Сохранять rollback и данные, контролировать дисковое место, не выполнять общий prune без разбора.

## Эталон подтверждён пользователем
Текущая основная страница `/studio` — источник оформления. Страницы входа (`/`, `/room`, `/studio`, `/admin`, `/moderator`) используют те же токены цвета/формы полей и кнопок; рабочие панели — одну структуру навигации, меню комнаты и участники отдельным блоком. `/output/*` остаётся чистым выходом видео без служебных кнопок, иначе ломается использование в режиссёрском ПО. `/transfer` — краткий статус с теми же цветами и полями. Роли определяют доступные элементы, но не меняют общий визуальный язык.

## Ссылка просмотра Studio Return
Основная студия и администратор комнаты выдают ссылку `/watch`. Одинаковая ссылка допускает несколько зрителей одновременно: каждый получает отдельную идентичность. Зрители имеют только подписку в изолированной комнате; микрофон, камера, управление и медиапотоки гостей им недоступны. Передаются видео и обработанный эфирный звук основной студии. При зрителях добавляется один исходящий поток студии независимо от количества зрителей; без зрителей он останавливается. Срок ссылки — 30 дней; смена пароля комнаты отменяет её. Браузер может потребовать нажатия «Включить звук». При переносе сервера выдаётся новая ссылка на целевом сервере.

## Безопасность гостевого доступа (требование 27.09.2026)
Гость с открытым DevTools считается недоверенным клиентом: он может читать весь полученный JavaScript/JSON, менять запросы, отправлять сообщения LiveKit и запрашивать чужую identity. Скрытые кнопки и клиентская фильтрация не являются контролем доступа. Пароли, административные настройки и серверная история статистики проверяются на сервере по роли и комнате. Служебные сведения об устройствах/команды качества не должны широковещательно доставляться гостям. Нельзя доверять роли, имени или identity только потому, что их прислал клиент. Собственная статистика WebRTC и параметры реально полученного гостем медиа технически доступны его браузеру и не считаются закрытой серверной статистикой.

Обнаруженное ограничение: режим «Гости могут видеть только студию» в текущей архитектуре ограничивает стандартный UI, но не подписку изменённого клиента на чужие публичные треки своей комнаты. Не называть его гарантией приватности. Строгая изоляция требует отдельной архитектурной работы. Приватный talkback и отдельный `/watch` имеют собственную проверенную изоляцию.

## Согласованное управление /watch (27.09.2026)
Студия и администратор выбирают общий лимит видеобитрейта для основного эфира и отдельного /watch. Выбор 500, 1000 … 12000 кбит/с; новые настройки по умолчанию 12000. Это лимит каждой передачи, не суммарная пропускная способность соединения: при зрителях две передачи по 12 Мбит/с дают до 24 Мбит/с видео плюс звук/накладные расходы. Фактический битрейт зависит от картинки, кодировщика и сети. Зритель /watch независимо включает/выключает только свой звук и видео; это не меняет эфир или других зрителей. Изменение общего качества должно применяться к зрительскому кодировщику без переподключения комнаты. Проверено 27.09.2026 в браузере на синтетическом источнике: независимые звук/видео; лимит отправителя 12→6→12 Мбит/с с неизменным SSRC и продолжающимся ростом счётчика кадров. Исходные треки студии остаются живыми. Проверочные страницы удалены до сборки. Выпуск `0.9.22-watch-controls` установлен на VPS и локальном сервере: оба HTTPS `/api/version` подтвердили версию; `/watch` отвечает 200, временные QA-маршруты — 404. ## Simple self-hosted: открытая комната и собственная студия — 07.10.2026

По явному решению владельца любой посетитель simple self-hosted сервера создаёт свою комнату на `/`. Это заменяет прежнюю owner-only политику создания только для нового простого сценария; legacy platform/studio-owner маршруты и данные сохраняются. Отдельный пароль студии выдаёт только права этой комнаты, гостевой пароль не повышает роль. Сервер проверяет подписанную сессию по неизменяемому creator UUID и текущему hash, а не по URL, названию или mode. Rename сохраняет UUID; delete/recreate меняет его. Публичные имена не используют внутренние media namespaces; queued mutations проверяют прежнюю creator association внутри store operation.

Основная Studio/Guest панель работает на `/`, без обязательного `/studio` и Super Admin invitation. Creator не получает server-global health/license/route или глобальных модераторов. Перенос разрешён только для собственной комнаты по неизменяемому creator UUID на подключённый для неё сервер; это не даёт управления другими комнатами или всей установкой. Для комнаты можно подключить несколько серверов, но аварийные полномочия текущей группы участников выдаются одному выбранному резерву. Смена резерва требует подтверждённого разоружения прежнего. Потеря связи не запускает перенос: его вручную включает основная студия. Подготовленные открытые вкладки могут обратиться к резерву при полном отказе источника; новая загрузка страницы с выключенного источника невозможна. Недоступность резерва не останавливает источник, а краткое пересечение медиасессий при разделении сети допустимо. Legacy admin/moderator/guest ограничения, primary lease и last-room rule остаются. Simple установщик показывает главную Create/Join; не выдаёт owner-access, не удаляет прежние owner files. PostgreSQL migration004 добавляет nullable creator credentials; повторная установка применяет additive migrations и не повторяет bootstrap seed.
