# CastLink: обязательный контекст перед изменениями

## Конференция и мобильные кнопки — уточнение владельца 21.10.2026

Русские режимы называются «Окно» и «Плитка» (уточнение владельца 21.10.2026). На desktop в режиме «Окно» вертикальный разделитель между основной плиткой и правой лентой меняет их размеры как с камерой, так и с демонстрацией. Это не полоса прокрутки; принудительно видимая полоса не требуется. На мобильном изменение размеров отключено в обеих ориентациях. В браузере/десктопе разделитель доступен и без демонстрации экрана; источники сохраняют пропорции. Основной кадр не прокручивается, гости закреплены справа на большом экране и снизу на портретном телефоне; длинная лента гостей имеет свою прокрутку. Нижняя мобильная панель оставляет отступ над системной зоной жестов. Веб-управление презентацией следует компактному native-образцу: файл/управляющий, навигация и управление, статус и независимый Stop. Ключи и смонтированные video nodes, разрешения и жизненный цикл медиа сохраняются.


Выбор по сравнительным рендерам21.10: на desktop сохранить крупные миниатюры PR75 с постоянными пропорциями16:9 независимо от числа гостей; на мобильном — компактную раскладку PR77. Демонстрация экрана мятная, совместная презентация голубая; итоговые цвета проверяются на настоящих компонентах, не на кнопках-заглушках.

## Пользовательские обновления и хранение — решение владельца 21.10.2026

Для распространяемых Windows Server Setup и standalone Ubuntu CLI автоматические бэкапы при обновлении не создаются. Это заменяет прежние требования сохранять production-бэкап и несколько предыдущих выпусков для обычного пользовательского обновления. Сборочные и QA-материалы разработчика остаются в приватной рабочей области и не входят в публичные пакеты; секреты и данные пользователей не коммитятся.

После проверки готовности новой версии хранится только текущий набор образов служб этой установки. Удалять только доказанно принадлежащие ей прежние теги и временные архивы; сохранять тома, конфигурацию, чужие образы и ссылки других установок/контейнеров, включая остановленные. Общий prune и принудительное удаление не используются. При сбое старые образы сохраняются для повторного запуска; автоматический откат данных не обещается.

Windows-клиент проверяет отдельные каналы клиентского EXE и управляемого сервера; Ubuntu CLI — Linux-канал. При доступной новой версии запуск предлагает обновить или остаться, автоматическую проверку можно отключить, ручная проверка остаётся. Скачивание и установка не начинаются от одного факта появления релиза; нужен выбор пользователя. Обычное подключение к чужому серверу не даёт права его обновлять. Старые опубликованные пакеты получают поведение только после установки нового выпуска.

## Установщики и выпуски — выбор владельца20.10.2026

Server сохраняет card-мастер PR66 с вариантом «На Linux Ubuntu». Windows Client сохраняет пошаговый NSIS с выбором папки: oneClick=false, allowToChangeInstallationDirectory=true. Quick/advanced и saved update/network PR67 сохраняются.

Сайт: Windows Client → Windows Server → Linux Ubuntu; внутри Ubuntu выделенная ссылка на единый manual с установкой из коробки и расширенным режимом. Footer: «Что нового в последних релизах». Три продукта имеют независимые теги/версии; общий releases/latest не определяет все три. Ссылки на архив и SHA256SUMS берутся из одного направления/выпуска.

## Обратная связь кастера — 20.10.2026

Отсутствующий профиль микрофона кастера означает raw: шумоподавление/эхоподавление выключены. Явный сохранённый speech сохраняется. Свой предпросмотр меняет только локальную видимость, без команды публикации камеры и без расширения разрешённых подписок. В studio-only доступна своя локальная камера, остальные гости скрыты.

Crop мультивью маскирует края исходных пикселей после object-fit, сохраняя исходные пропорции, положение, масштаб и центр трансформации; редактор/миниатюры/выход используют общую геометрию. Удаление самостоятельного инвайта проверяет полномочия и отсутствие привязки в одной транзакции со слотами.

## Вход и дизайн — утверждение владельца 20.10.2026

Согласованные рендеры `design-preview/entry-approved/` — основной предпочтительный эталон: минимализм, информативность кнопок, подписей и расположения. Вход сначала разделяет студию и кастера; валидный инвайт пропускает выбор роли. Студийный hosted-токен не требуется гостю: его доступ подтверждает действительное приглашение/гостевой пароль и точная admission-сессия. Приложение Windows открывает только проверенные ссылки, не прерывает занятую комнату новым инвайтом без подтверждения. Установку нельзя достоверно определить таймером; браузерный путь остаётся доступным. Камера на рендере off — пример состояния, прежний разрешённый предпросмотр сохраняется.

## Панели сайта и PR60 — уточнение владельца20.10.2026

Пользователь включил PR60 и плавающие browser-панели в общий выпуск. Панели перемещаются за заголовок внутри доступной области страницы. Явное действие открывает Document Picture-in-Picture при поддержке/разрешении браузера; без API/при отказе сохраняется inline. STOP и слайды независимы; скрытие/закрытие UI никогда не останавливает медиа/не отзывает grant. Поздние callbacks и старые кнопки не управляют новым grant. Native bridge Windows имеет приоритет. Физический PowerPoint, фокус и исключительный fullscreen ОС проверять отдельно.

PR60 расширяет двухпозиционную camera-политику: персонал своей комнаты задаёт custom размеры и FPS через доверенную серверную metadata. Guest-local choices не могут её переопределять. Быстрый720/1080 сбрасывает custom размеры; без custom действует default1080/нативные пропорции ниже. Точный текущий SID/epoch, off-состояния, mic/audio/screen и восстановление intent сохраняются.

## Разрешение камеры — решение владельца20.10.2026

Разрешение камеры задают только основная студия, администратор или модератор своей комнаты. У кастера нет собственного переключателя; прежнее локальное choices.height не определяет публикацию. Серверная metadata videoHeight принимает720/1080, без заданного staff-значения запрашивается1080. Меняется текущая камера точного SID, настройка сохраняется при восстановлении сессии. Выключенная камера не включается настройкой разрешения. Применение не меняет микрофон, аудио, устройство или экран; width не фиксируется, нативные пропорции и resizeMode none сохраняются. Это заменяет прежний скрытый guest default720 и локальный выбор высоты. Запрошенное разрешение отличать от фактического: браузер/камера могут выдать меньший кадр.

## Серверные роли и слоты — уточнение владельца 18.10.2026

- Кастер входит сразу с прежней проверкой доступа. Слот не разрешает вход и не управляет публикацией.
- Предпросмотр гостя автоматически удерживает разрешённые включённые камеру/микрофон на AV check до входа; без автоматического join. Ошибка одного входа не блокирует другой. Явные off-состояния, stale/StrictMode cancellation, очистка при выходе и transfer restoration сохраняются.
- Уточнение владельца: отдельная схема серверных ролей и вход владельца удалены. Выдача admin/moderator восстановлена в настройках комнаты из обычной студии, с прежними комнатными правами и отзывом. Прежние инструкции о новом блоке «Доступ к серверу» отменены.
- Назначение, замена, перенос и освобождение меняют только маршрутизацию выходов и никогда не удаляют участников комнаты. Отдельная команда отключения гостя сохраняется.
- Выходы связаны с постоянной ассоциацией комнаты и slot ID. Имя, инвайт и назначение сохраняют URL. Перевыпуск меняет только выбранный URL.
- Вывод проверяет серверную identity, подписанную сессию, generation и реальный SID. Reconnect той же сессии обновляет SID; camera/mic и screen/screen audio разделены.
- Старые открытые вкладки проходят прежний admission API автоматически, без ожидания модератора. Старые подписанные маркеры назначения сохраняются при продлении JWT.
- Slot output наследует прежний read-only room subscription grant; фильтр источника не является конфиденциальностью между источниками комнаты.

## Медиа и значения по умолчанию — 18.10.2026
Новые настройки (уточнение владельца 21.10.2026): студия H.264/10000 кбит/с/60 FPS; кастер предпочитает H.264 при поддержке браузером, прежние 4000 кбит/с и политика FPS сохраняются. VP9 доступен вместо VP8 в новом выборе; сохранённый VP8 поддерживается. VP9 и AV1 публикуются с явной SVC-конфигурацией без скрытого резервного кодека. Сохранённые явные настройки не перезаписывать; legacy studio state без codec сохраняет VP8. Неподдерживаемый явно выбранный кодек сообщает ошибку; только отсутствующий гостевой выбор использует поддерживаемый fallback. Лимит студии до25000 — потолок каждой из двух передач (комната и /watch), не требование постоянного битрейта. График показывает измеренный поток с подписью направления;60замеров не гарантируют точные2минуты. Временная HTTPошибка служебного опроса не должна останавливать исправную RTCпередачу; авторитетный отказ доступа закрывает её. SDKreconnect не отменять принудительнымdisconnect.

## Автоматический резерв — решение владельца 12.10.2026 (реализовано, OFF по умолчанию)

Владелец разрешил включаемое/выключаемое автоматическое переключение при подтверждённом отказе основного сервера; обычный перенос остаётся ручным, возврат после восстановления — вручную. Открытые подготовленные `/watch` должны следовать переносу без расширения прав зрителей. Это заменяет прежнее требование «потеря связи никогда не запускает перенос» только для явно включённой автоматики; существующие комнаты по умолчанию сохраняют ручной режим. Одиночный обрыв одного гостя или недоступный резерв не должны переносить исправную комнату. Остальной функционал и медиасхема сохраняются. Пока реализация не проверена и не выпущена, не утверждать, что это уже работает. Текущее состояние — [WORKING_STATE_RU.md](WORKING_STATE_RU.md).

## Система
- Бренд CastLink. Основной публичный адрес https://castlink.ru. Локальный публичный адрес https://caster.em.studio. lunkaonline.ru допустим только для обратной совместимости/перенаправления.
- Одна основная студия публикует Studio Return. Дополнительные администраторы и модераторы не захватывают её lease, не перезапускают устройства и не прерывают эфир.
- Микрофон — вход звука; наушники/динамики — выход. Личный мониторинг не меняет эфир. Камера, микрофон и выход выбираются отдельно.
- Администратор может явно выбрать устройства компьютера основной студии через studio-control: только из её актуального списка и в своей комнате. Камеру/микрофон менять при выключенном эфире; выход — если браузер студии поддерживает setSinkId. Выбор не захватывает primary lease. Список устройств не выдавать гостям/ограниченным модераторам; старые команды устройств не повторять при изменениях FPS/битрейта/усиления.
- Studio Return: целевые значения по умолчанию 1920×1080, 60 FPS, 12000 кбит/с для новых студийных настроек; FPS 25/30/50/60; выбор битрейта студии и /watch: 500, 1000, 2000 … 12000. Сохранённые параметры текущего эфира не повышать автоматически. Источники вроде vMix нельзя ошибочно отклонять из-за неточного описания capabilities. Настройки качества меняются во время эфира.
- Измеренный битрейт/FPS не подменять заданными лимитами. Различать отсутствие замеров, устаревшие замеры и офлайн. Администратор получает замеры основной студии.
- Пароль комнаты проверяется на сервере. Гостевые инвайты допускают вход без пароля. Инвайты ролей проверяются сервером, имеют срок и отзыв; секреты не писать в логи, GitHub, git или URL query.
- Перенос серверов переносит только участников текущей сессии, не перенаправляет будущих гостей старой комнаты. Сохранять выбранные устройства и роль. Для локальных подключений с внешних IP 79.120.36.254 и 79.104.52.243 предусмотрен локальный маршрут 192.168.53.68. Не менять MikroTik во время работы.
- Приватное обращение доставляется только выбранному получателю; скрытие/приглушение на чужом клиенте не является приватностью.
- Обновление страницы основной студии может прервать эфир: не обновлять принудительно. Сохранять rollback и данные, контролировать дисковое место, не выполнять общий prune без разбора.

## Дизайн
- Уточнение владельца20.10.2026: на desktop кастера кадры целиком вписываются в доступную видеозону с пропорциями16:9, без обрезания и внутренней прокрутки. При нехватке высоты уменьшается вся плитка равномерно, а не растягивается на полную ширину с потерей нижнего края. Один кадр центрируется; несколько образуют вписанную сетку. Мобильная раскладка сохраняет прежний естественный поток; чат имеет отдельную прокрутку сообщений.
- Эталон по умолчанию — текущая основная страница студии; единые цвета, тёмная/светлая темы, кнопки и выпадающие списки на всех страницах.
- Монитор студии сверху; настройки комнаты компактно в меню «Комната»; устройства компактно; перенос серверов внизу.
- ON AIR имеет красную кнопку/индикатор. Исходящий поток и график рядом с монитором на широком экране, ниже на узком.
- Администраторы красные, модераторы бирюзовые, гости белые; персонал отдельным блоком над гостями.
- Раскладка адаптивная: без обрезания элементов и глобального горизонтального скролла; участники доступны вертикальным скроллом/свайпом; элементы не зависят от фиксированного разрешения.
- Повторное подключение не создаёт дубли участников/видеоэлементов. Ушедшие участники удаляются сразу.

## Хранение выпусков (обновлено владельцем 08.10.2026)
- На сервере хранить текущую успешно проверенную версию CastLink и две предыдущие. Более старые сборки и образы удалять при обслуживании; это заменяет прежнее правило «текущая и одна предыдущая».
- По новому разрешению владельца более старые сборки и образы можно удалять без обязательного переноса в локальный архив. Перед удалением сверять точные образы трёх сохраняемых выпусков и зависимости работающих контейнеров. Сохранять необходимые сведения для восстановления контейнеров и резервные копии данных; секреты не публиковать в Git или журналах. Незавершённый архив не считать резервной копией.
- Во время обновления прежний работающий выпуск становится предыдущим только после проверки нового. Не выполнять общий Docker prune и не удалять действующие LiveKit/Caddy, их данные или тома.
- Лимит относится к сохранённым выпускам приложения, а не к данным, резервным копиям БД или служебным зависимостям. Образ, который нужен работающему контейнеру, не удалять ради соблюдения количества версий; отдельно учитывать такую зависимость до её штатного обновления.

## Согласованные требования текущей работы (27.09.2026)
- Модератор: без статистики/графиков; переключатель «Гости могут видеть только студию» сверху; видит/слышит гостей; управление их звуком и видео; видит пароль комнаты; говорит всей комнате или лично гостю.
- Статистика администратора подтверждена пользователем 27.09.2026: заработала после обновления страницы основной студии. Не считать её неисправной и не менять сбор измерений по прежнему сообщению.
- Администратор: статистика основной студии; видит/слышит гостей и модераторов; приглашает/удаляет модераторов; говорит комнате или лично гостю/модератору.
- Делегирование администратором не должно неявно расширять его собственную область доступа. Существующий модератор владельца имеет доступ ко всем комнатам сервера.
- Включение устройств учитывает разрешения браузера и отсутствие устройства; ошибки отображать явно, не сообщать об успехе без подтверждения.

## Ссылка просмотра Studio Return
Основная студия и администратор комнаты выдают ссылку `/watch`. Одинаковая ссылка допускает несколько зрителей одновременно: каждый получает отдельную идентичность. Зрители имеют только подписку в изолированной комнате; микрофон, камера, управление и медиапотоки гостей им недоступны. Передаются видео и обработанный эфирный звук основной студии. При зрителях добавляется один исходящий поток студии независимо от количества зрителей; без зрителей он останавливается. Срок ссылки — 30 дней; смена пароля комнаты отменяет её. Браузер может потребовать нажатия «Включить звук». При переносе сервера выдаётся новая ссылка на целевом сервере.

## Безопасность гостевого доступа (требование 27.09.2026)

Плановый перенос с переподключением и аварийное восстановление проверяются отдельно. Изолированный новый экземпляр с отдельной БД и временным входом через старый сервер ещё не является перенесённой production-студией или независимым горячим резервом. Подробные критерии и текущие блокеры находятся в #16 и #53, подтверждённые операции — в VERIFIED_RUNBOOK_RU.md.


## Доверенный локальный компьютер: запуск Windows CLI — решение владельца 06.10.2026

Владелец явно разрешил запуск распакованного CLI из обычного, в том числе доступного для записи каталога на своём ПК/VPS. Локальный компьютер и его файловое хранилище считаются доверенными; прежнее требование защищённой ACL всей цепочки каталога пакета не является условием запуска. Не добавлять защиту от злонамеренного локального пользователя, новые bootstrap-подсистемы или изменения чужих ACL ради запуска.

Штатные файлы и каталоги Windows сохраняют проверку OS owner/DACL; штатные файлы допускают положительное число hardlinks. Не-OS каталоги запуска сохраняют physical identity, canonical/nonreparse и held stability, без ACL-предусловия. Файлы встроенного publisher inventory и точный текущий EXE сохраняют physical/canonical/single-link/held stability и существующие проверки целостности, без ACL-предусловия. Остальные не-OS файлы (Docker, Compose, context) сохраняют owner/DACL/signature/broker binding. Роли назначает native registration, не пользовательский флаг; dedup не повышает роль файла. Это не гарантия неизменяемости первоначального EXE против другого локального писателя.

Создание приватных рабочих каталогов, сохранность данных, scoped target lease/effect guards, серверная авторизация и сетевые права сохраняются. Запуск из обычной папки не разрешает изменение глобальных ACL, PATH, чужих проектов или production.


## Simple self-hosted: открытая комната и собственная студия — 07.10.2026

По явному решению владельца любой посетитель simple self-hosted сервера создаёт свою комнату на `/`. Это заменяет прежнюю owner-only политику создания только для нового простого сценария; legacy platform/studio-owner маршруты и данные сохраняются. Отдельный пароль студии выдаёт только права этой комнаты, гостевой пароль не повышает роль. Сервер проверяет подписанную сессию по неизменяемому creator UUID и текущему hash, а не по URL, названию или mode. Rename сохраняет UUID; delete/recreate меняет его. Публичные имена не используют внутренние media namespaces; queued mutations проверяют прежнюю creator association внутри store operation.

Основная Studio/Guest панель работает на `/`, без обязательного `/studio` и Super Admin invitation. Creator не получает server-global health/license/route или глобальных модераторов. Перенос разрешён только для собственной комнаты по неизменяемому creator UUID на подключённый для неё сервер; это не даёт управления другими комнатами или всей установкой. Для комнаты можно подключить несколько серверов, но аварийные полномочия текущей группы участников выдаются одному выбранному резерву. Смена резерва требует подтверждённого разоружения прежнего. Потеря связи не запускает перенос: его вручную включает основная студия. Подготовленные открытые вкладки могут обратиться к резерву при полном отказе источника; новая загрузка страницы с выключенного источника невозможна. Недоступность резерва не останавливает источник, а краткое пересечение медиасессий при разделении сети допустимо. Legacy admin/moderator/guest ограничения, primary lease и last-room rule остаются. Simple установщик показывает главную Create/Join; не выдаёт owner-access, не удаляет прежние owner files. PostgreSQL migration004 добавляет nullable creator credentials; повторная установка применяет additive migrations и не повторяет bootstrap seed.


## Локальная панель: новое правило закрытия — 13.10.2026

По новому указанию владельца крестик окна панели означает скрытие в трей, без остановки служб. Отдельные кнопки запуска и остановки управляют только выбранной установкой. Явный пункт трея «Остановить и выйти» останавливает её службы и завершает панель после проверки остановки. Это заменяет прежнее правило «закрытие окна останавливает службы». После успешной установки/обновления локальные службы остаются запущенными; GUI передаёт управление панели после освобождения блокировки установщика. Отказ запуска панели не должен маскироваться как ошибка установки сервера или как подтверждённая передача управления. Автозапуск при входе в Windows не включается.


## Приватная связь и программа — решение владельца18.10.2026

У основной студии приватная связь убрана; говорить приватно могут только администраторы и модераторы комнаты. Старт и завершение служебного разговора не меняют звук Studio Return, демонстрации, /watch или других гостей. Кастер отвечает кнопкой «Ответить приватно» с удержанием: только его микрофон исключается из программы на время ответа. Перед приватной публикацией требуется подтверждённое исключение из основного эфира; перед восстановлением — остановка приватного трека. После отпускания возвращается прежнее состояние микрофона, если не пришла отдельная команда mute. При неопределённом результате/обрыве микрофон не возвращается автоматически, интерфейс сообщает состояние. Это заменяет прежнее выключение всей программы на время приватного разговора.

При принятии гостем роли администратора/модератора сервер сначала проверяет назначение по текущему гостевому SID. Затем клиент завершает гостевую камеру, микрофон, демонстрацию и подключение, и только после этого открывает панель персонала в той же вкладке. Отдельная гостевая передача не должна оставаться в эфире: иначе микрофон служебного разговора может попасть в программу. Ошибка остановки не разрешает обход через вторую вкладку.

## Уточнение PR71: родительские Docker-образы

Собственные стадии Dockerfile.web и turn-tls получают `ru.castlink.image.owner=castlink`, `ru.castlink.image.ownership=castlink-build-v1`, полный `ru.castlink.image.source` и `ru.castlink.image.stage` до RUN. Официальный producer передаёт полный source commit обеим сборкам. Стандартные Node/HAProxy/Postgres/LiveKit/Caddy bases сами по себе собственностью CastLink не объявляются.

Учёт родителей хранит точный image ID, source и stage. Регистрация требует явных labels и совпадения полного source с проверенным выпуском. Одного родства, имени или совпадения слоёв недостаточно. Перед удалением labels повторно сверяются с записью. Сохраняются чужие/неучтённые образы, любые теги/digests, текущие release roots и их родители, все running/stopped container roots и их родители. При пустом Parent совпадение префикса RootFS.Layers используется только для сохранения; неполные сведения также запрещают удаление родителей.

Удаление каждого проверенного старого тега или собственного dangling parent выполняется с `docker image rm --no-prune`, без force и общего prune. Старые немаркированные родители сохраняются. Учёт относится к пользовательским установкам; build cache производителя и builder stages вне runtime ancestry автоматически не присваиваются и не чистятся.

Проверки уточнения: Linux parent ownership/graph — 10 тестов, updater — 16, installer — 17; producer labels/build args — 2 теста. Docker-команды проверяются на подставных inventory/graph данных; реальные production Docker/VPS не изменялись. Windows/SSH/legacy проверки и независимое ревью завершены: см. итог в testing/PRODUCTION_UPDATES_20261021_RU.md.
