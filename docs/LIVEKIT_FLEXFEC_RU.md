# Восстановление потерянных пакетов камеры с FlexFEC

Официальный LiveKit Server 1.13.11 умеет принимать от издателя защитные пакеты FlexFEC-03 и восстанавливать часть потерянного видео до пересылки подписчикам. Опцию выбирает оператор медиасервера для всех комнат этой ноды. В стандартной установке приём выключен. При нехватке полосы у одного кастера студия также может уменьшить «Лимит камеры» в его карточке.

## Включение и откат

Для основной ноды, на которой требуется принимать защитные пакеты, задай параметр явно. Проверь версию работающего SFU. Для стандартного media Compose следующая команда выполняется из его каталога с обычными параметрами и именем проекта этой установки.

```sh
docker compose -f docker-compose.media.yml exec -T livekit /livekit-server --version
```

В файл проекта `.env` рядом с `docker-compose.media.yml`, `docker-compose.yml` или сгенерированным Easy Setup `compose.json` добавь строку, сохранив прежнее значение для отката.

```dotenv
LIVEKIT_RTC_FLEXFEC_UPSTREAM_ENABLED=true
```

Новые шаблоны передают параметр только медиасервису. В перерыве между эфирами примени конфигурацию штатным запуском установки. Команда для стандартного media Compose приведена ниже. Его участники переподключатся.

```sh
docker compose -f docker-compose.media.yml up -d --no-deps livekit
```

Для отката восстанови прежнее значение в `.env` и окружении запуска, затем повтори ту же команду. Если шаблон Compose ещё не поддерживает переменную, у официального SFU с конфигурацией, которую ведёт оператор, добавь подраздел `flexfec` под существующим ключом `rtc` файла LiveKit:

```yaml
rtc:
  flexfec:
    upstream_enabled: true
```

Сохрани остальные параметры `rtc`. После изменения файла перезапусти или пересоздай медиасервис в согласованное окно. При генерируемом Easy Setup изменение `livekit.json` вручную теряется при следующей генерации.

## Совместимость и проверка

Браузер решает, предлагать ли `flexfec-03` и отправлять ли защитные пакеты. Сервер продолжает принимать обычное видео от остальных издателей. В тестовой комнате сначала проверь согласование в SDP издателя. Затем внеси короткие серии потерь только на пути от кастера и посмотри прирост `livekit_fec_total` по меткам `type="received"` и `type="recovered"`, если нода собирает Prometheus. Счётчики общие для ноды. Защитные пакеты расходуют дополнительную полосу отправителя.

На локальном стенде с Chromium 154, VP8 и двумя выходами браузер в штатном режиме согласовал FlexFEC и за период потерь передал обычное видео без защитных пакетов. С экспериментальным режимом отправителя в Chromium тот же сервер за 10 секунд принял 54 защитных пакета и восстановил три потерянных медиапакета. Такой результат относится к измеренному сочетанию браузера и канала. [Конфигурация LiveKit 1.13.11](https://github.com/livekit/livekit/blob/v1.13.11/config-sample.yaml)
