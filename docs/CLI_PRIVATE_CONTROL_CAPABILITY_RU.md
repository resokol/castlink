# Manifest2: private .2 CONFIG/SERVICES research contract

Это opt-in source capability, а не подтверждение полной установки на всех платформах.

Schema1 сохраняет исходные поля, четыре CONFIG файла и legacy receipts. Schema2 допускает только фиксированный `castlink-idleseal-private-v2`, `.2` version/imageID/binarySHA, amd64, UID/GID1000. Первичная реализация — локальный Linux research; actual Node facts включают Linux/x64/UID/GID и distribution/version. Все endpoint, engine, Compose и port checks продолжают действовать. Native/remote capability adapters отказывают до CONFIG эффекта. Main/args/CLI manifest loading не изменены.

CONFIG под настоящим target lease резервирует private700 control root и empty600 config slot до CREATE. Durable attempt вне profile запрещает регенерацию удалённой попытки. Обычный receipt содержит schema2 release и actual scope; renderer/materializer/verify используют одинаковые bytes. POST проверяет первоначальные physical root/control/slot identities. Verify-only не переписывает credentials, slot или markers, и проверяет сохранённую фазу.

SERVICES под тем же lease проверяет actual engine/endpoint, config/image contract и immutable private image, создаёт ровно четыре конечных stopped services без build/pull/recreate. Внешний full64 CID, actual imageID, runtime UID, entrypoint/environment, mounts и physical slot связывают private config; hostname является дополнительным свойством, а не authority. Secret создаётся только в private config, digest остаётся в private binding marker. Slot заполняется через исходный inode.

Одноразовый initializer — отдельный owned transient CID, не пятая служба: immutable imageID + `--pull=never`, network none, user1000, read-only rootfs, cap-drop ALL, exact private binds. Выполняются create/inspect/start-attach/wait/reap/remove/absence proof. Только после actual anchor/state проверки записывается initialized marker, запускается Postgres и после health остальные три службы. Финальный private status требует CLOSED, нулевые Pending/Live/Unknown и один actual process nonce при повторной POST проверке. Engine drift, loss/partial replies, image/CID/user/mount mismatch оставляют lease UNKNOWN; никакого автоматического repair/recreate.

SQL migrations/seed, owner и completion остаются отдельными существующими фазами. Источник не публикует host descriptor, не открывает admission и не объявляет READY. Данный slice выполняет fresh bootstrap и уже-running CLOSED verification. Stopped initialized restart через этот private branch пока отказывает до effect; controlled host-controller restart/activation — следующий отдельный slice.

Следующая Windows граница: Docker Desktop bind permissions, видимые Linux guest, не равны native DACL; private Go initializer требует POSIX private regular files/directories. Нельзя принять исходный bind по одному host ACL. Нужен отдельный versioned storage/mapping capability и actual guest-mode/UID/image/bind proof; возможный Docker-owned named volume должен иметь controlled pre-CREATE initializer/authority и не менять legacy receipt. До независимого review и actual mapping proof Windows schema2 отказ сохраняется.
