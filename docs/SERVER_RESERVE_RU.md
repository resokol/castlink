# Дополнительные серверы, перенос и автоматический резерв

Функция относится к self-hosted CastLink. Для комнаты можно подключить несколько серверов. Плановый перенос запускает основная студия. Для аварии можно заранее включить автоматический перенос на один подготовленный резерв. По умолчанию автоматика выключена.

## Подключение сервера

В конце EasySetup либо в студии, в разделе «Серверы комнаты», доступны два способа:

- **Установить CastLink на пустой VPS** — мастер скачивает совместимый текущий Linux выпуск из `resokol/castlink-releases`, проверяет SHA256, готовит Docker и разворачивает сервер.
- **Подключить установленный CastLink** — мастер обнаруживает существующую совместимую установку EasySetup. Её комнаты и службы сохраняются. Если установок несколько, нужен UUID выбранной установки.

Для первого выпуска поддерживаются Ubuntu 22.04/24.04 x86_64, публичный IPv4, SSH root и пароль. Сначала мастер показывает ключ SSH сервера: сверьте его с данными VPS и подтвердите доверие. Пароль используется только для текущей операции и не сохраняется. Веб-интерфейс не разрешает произвольный доступ к внутренней сети сервера; внутренние адреса требуют настройки владельцем установки.

Подключения из установщика доступны комнатам этой установки. Подключения из студии принадлежат только её комнате. Создатель комнаты не получает права управления другими комнатами или сервером-источником. Устаревшую установку без поддержки подключения резервов нужно обновить.

HTTPS каждого сервера должен быть доверенным на устройствах участников. При собственном сертификате доверие к первому серверу не означает доверия ко второму. Прямое соединение браузера с резервом проверяется до аварии; недоверенный сертификат или недоступный адрес не должны отображаться как готовый резерв.

## Плановый перенос

В разделе «Перенос комнаты» выберите доступный целевой сервер и нажмите «Перенести». Сначала цель проверяет LiveKit и возможность принять комнату. Занятая другой сессией комната не заменяется. При отказе цели текущая комната продолжает работать.

Переносятся подключённые участники текущей сессии: основная и дополнительные студии, гости, персонал комнаты и подготовленные открытые зрители `/watch`. Зрители сохраняют только просмотр; доступ к гостевым потокам или управлению им не выдаётся. Их роли и сроки прав сохраняются. Новые посетители старой ссылки не перенаправляются автоматически.

## Аварийный резерв

Заранее выберите один сервер в разделе «Аварийный резерв». Для текущей группы участников одновременно подготовлен только один аварийный резерв. Остальные серверы остаются в списке доступных подключений. Смена аварийного резерва требует подтверждения прежнего сервера; при недоступности прежнего одновременно активные полномочия на другой сервер не выдаются.

Открытые вкладки получают собственные короткоживущие полномочия перехода и проверяют резерв напрямую. Снимок обновляется каждые 30 секунд; готовность действует не более пяти минут и не дольше исходных прав участника. Состояние и возраст снимка показываются в студии.

Ручной вариант: при отказе основного HTTPS-сервера или LiveKit основная студия нажимает «Перенести на аварийный резерв» в уже открытой вкладке. Подготовленные вкладки участников и `/watch` увидят подтверждённую операцию на резерве и перейдут туда.

Автоматический вариант: включите «Автоматический аварийный перенос» и дождитесь подтверждения. Пока вкладка основной студии открыта и активна, она проверяет основной сервер; резерв отдельно проверяет его со своей стороны. Переход запускается после устойчивого отказа, подтверждённого обоими наблюдателями. Кратковременный обрыв, сбой у отдельного гостя или недоверенный сертификат не являются достаточным основанием. Проверки занимают десятки секунд: это не бесшовное переключение.

Выключение считается выполненным только после подтверждения резерва. При потере ответа интерфейс покажет, что изменение не подтверждено, и предложит повторить запрос; текущая вкладка сразу прекратит новые автоматические попытки. Если перенос уже завершился, выключение не отменяет его. Недоступный основной сервер может помешать передать настройку резерву; не считайте локально снятую галочку подтверждённым выключением.

Новая выбранная цель и комната после переноса начинают с выключенной автоматикой. Обратный перенос после восстановления основного сервера всегда ручной. Для планового переноса действующий аварийный резерв сначала должен подтвердить снятие подготовки.

Не перезагружайте вкладку основного сервера во время аварии: выключенный сервер не может выдать страницу заново. Для нового входа используйте адрес резерва. Если готовность истекла до запуска переноса, потребуется доступный основной сервер для повторной подготовки. Закрытая, выгруженная или приостановленная браузером вкладка основной студии не запускает автоматику. Обычное сворачивание окна тоже может замедлить проверки, если браузер приостанавливает таймеры.

## Переподключение медиа

Во время перехода возможен перерыв звука и видео. Браузер может повторно запросить разрешения камеры, микрофона или выбор аудиовыхода на новом адресе. При невозможности однозначно восстановить выбранное устройство участник подтверждает его вручную. Для показа экрана требуется новый выбор окна или экрана. Зрителю `/watch` браузер может предложить снова включить звук: перенос сохраняет выбор пользователя, но не обходит правила автозапуска браузера. Новые зрители используют ссылку просмотра с целевого сервера; старая ссылка не становится постоянным редиректом.

При разделении сети некоторое время могут работать старые и новые медиасессии. Данная функция не является автоматическим кластером с гарантией единственного активного медиасервера. Недоступный резерв не останавливает исправный основной сервер. Отзыв прав на источнике во время разрыва связи не может мгновенно изменить уже выданные резерву полномочия; их срок ограничен готовностью снимка.
