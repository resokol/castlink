# 06. Эксплуатация: установка, миграции, обновление и восстановление

[Оглавление](../MANUAL_RU.md) · [Разработка](05_DEVELOPMENT_RU.md) · [Приёмка](07_ACCEPTANCE_RU.md)

Эта глава предназначена владельцу сервера. Часть команд изменяет БД или заменяет приложение. Сначала прочитайте процедуру целиком, определите сервер, каталог, версию и окно обслуживания. Примеры с `castlink.example` и `RELEASE_IMAGE` требуют ваших значений; это не готовые секреты или рабочий адрес.

## Опубликованные пользовательские установщики

Для новой установки используйте [Server Setup](../../distribution/INSTALL.md) на Windows/Ubuntu по SSH либо [standalone Linux-пакет](../../distribution/LINUX_MANUAL.md). Это отдельные направления выпуска. Windows Client подключается к готовому серверу и сам по себе сервер не устанавливает. Самостоятельная установка не зависит от аккаунта или hosted-токена castlink.ru.

Новый Linux `init` скрыто запрашивает с подтверждением **пароль создания комнат**; он отличается от задаваемых позже паролей студии и гостей конкретной комнаты. При noninteractive `init --config` передайте `--room-creation-password-file` с UTF-8 паролем без завершающего перевода строки. Сохраняются только его хеш и инфраструктурные секреты установки.

Если старый работающий standalone Linux сообщает «Создание комнат пока недоступно», распакуйте новый пакет и из него выполните `python3 scripts/linux-compose-setup.py creation-password --state-dir <прежняя-папка-состояния> --lang ru`, подставив настоящий путь. При первоначальном `init` без `--state-dir` это `castlink-install` в исходном рабочем каталоге. Recovery задаёт только отсутствующий пароль; уже настроенные пароли, комнаты, ключи, release и Compose сохраняются. Службы не перезапускаются; после успеха обновите страницу браузера. Одна ручная правка `web.env` не является устойчивой настройкой: обычный render/start/update генерирует этот файл заново.

Обычное обновление standalone Linux — `update` с той же папкой состояния. В Windows-мастере выберите прежнюю установку через «Обновить». Завершите эфир до обновления; автоматических резервных копий и автоматического отката пользовательских данных эти установщики не создают. Нужные копии сохраняет владелец.

Ниже описан **отдельный операторский/legacy production-процесс** из исходного репозитория. Его `/opt/studiolink*`, `production-update.sh`, backup и rollback нельзя автоматически переносить на standalone-папку или установку Windows-мастера.

## Что должно быть подготовлено

Для публичной установки нужны Linux/VPS с достаточными CPU, RAM, диском и каналом, доступ владельца, домен/DNS и настроенный сетевой вход. Для домашнего сервера дополнительно важны NAT, доступность входящих портов и допустимость использования канала. Внутренний VPN для управления сервером не делает медиапорты автоматически публичными.

Разделите web/control plane, PostgreSQL и медиа. PostgreSQL нельзя открывать всему интернету ради подключения браузера. Браузер работает с API, а не с SQL-паролем. Секреты создаются для конкретной установки и остаются на ней.

Проверенный состав конфигурации: `infrastructure/production/docker-compose.yml`, отдельные `web.env` и `postgres.env`, media/ingress-конфигурация LiveKit/Caddy/HAProxy. Файлы `.example` являются шаблонами. Реальный `.env` нельзя заменять шаблоном при каждом обновлении.

## Сначала узнайте, что реально запущено

Команды чтения на нужном сервере:

```bash
hostname
docker ps --format '{{.Names}} {{.Image}} {{.Status}}'
docker inspect studiolink-web --format '{{json .Mounts}}'
docker inspect studiolink-web --format '{{json .Config.Labels}}'
curl -fsS http://127.0.0.1:3000/api/version
```

Mounts показывают, где живут данные. Compose labels помогают найти настоящий compose-файл. Не выводите целиком `Config.Env`: там секреты. Просмотрите labels перед передачей третьим лицам — они содержат инфраструктурные пути.

В проверенной установке этого проекта web запускается из конфигурации `/opt/studiolink-rc/infrastructure/production`, а данные подключены из `/opt/studiolink/data`. Это **наблюдение конкретного VPS**, а не универсальное значение для всех установок. Старый каталог `/opt/studiolink` может содержать не ту версию скриптов, которой развёрнут runtime.

Если требуется проверить активный эфир, одного `ps | grep chrome` недостаточно: генератор нагрузки может находиться на другом компьютере. Смотрите LiveKit rooms/participants, действующие lease и согласование с оператором. Открытый UDP-сокет сам по себе не доказывает активный soak.

## Карта всех эксплуатационных скриптов

| Скрипт | Назначение | Класс воздействия |
|---|---|---|
| `linux-compose-setup.py` | Опубликованный standalone Linux: установка, обновление и `creation-password` | Только собственная установка по сохранённому `--state-dir`; [мануал](../../distribution/LINUX_MANUAL.md) |
| `install-ubuntu.sh` | Bootstrap Linux-установки и конфигурации | Изменяет хост и конфигурацию; только на подготовленном стенде |
| `install-windows.ps1` | Bootstrap Windows/Docker-сценария | Изменяет конфигурацию; не является native Studio |
| `production-preflight.mjs` | Проверка env/compose/версии/секретов без их печати | Предварительная проверка |
| `production-update.sh` | Backup, замена web, проверка health, попытка возврата предыдущего image при отказе | Изменяет runtime |
| `production-rollback.sh` | Возврат предыдущего web image из backup manifest | Изменяет runtime; не восстанавливает БД |
| `storage-backup.mjs` | Копия постоянных файлов и manifest | Создаёт backup |
| `storage-restore.mjs` | Восстановление файлов по явной процедуре | Потенциально разрушительная операция |
| `postgres-backup.sh` | `pg_dump`, проверка читаемости и SHA-256 | Создаёт приватный dump |
| `postgres-restore.sh` | Явное восстановление PostgreSQL | Потенциально заменяет данные; нужен `--confirm-replace` |
| `postgres-migrate.mjs` | Миграции node-local storage | Меняет схему БД |
| `postgres-import-rooms.mjs` | Перенос комнат из legacy JSON в PostgreSQL | Меняет данные; отдельно от обычного update |
| `control-plane-migrate.mjs` | Последовательное применение SQL central control plane | Меняет схему; нужна актуальная папка миграций |
| `control-plane-seed-default.mjs` | Начальные default organization/studio/node и metadata комнат | Меняет центральный реестр |
| `control-plane-register-node.mjs` | Регистрация ноды и её capacity/endpoint | Меняет реестр, не запускает физический сервер |
| `node-heartbeat.mjs` | Однократный сбор и подписанная отправка состояния ноды | Читает LiveKit, пишет телеметрию в control plane |
| `support-bundle.mjs` | Ограниченный диагностический JSON и сетевые проверки | Создаёт файл; не содержит полный dump конфигурации |
| `turn-preflight.mjs` | Проверка TURN-конфигурации/предпосылок | Сначала читать профильный документ |
| `turn-stage2-preflight.mjs` | Проверка второй схемы TURN/TLS/SNI | Не заменяет реальную медийную проверку |
| `turn-stage2-deploy.sh` | Развёртывание сетевой схемы TURN stage 2 | Может затронуть ingress/media; не запускать ради web-фикса |
| `super-admin-owner.mjs` | Первая/восстановительная одноразовая ссылка владельца | Меняет platform access; ссылку пишет только в закрытый файл |
| `build-manual-index.mjs` | Обновление каталога файлов и связей руководства | Только документация, не runtime |

Точные параметры каждой команды находятся в её исходнике и профильном документе. Не все скрипты реализуют `--help`: у простого позиционного скрипта такая строка может стать именем файла. Перед неизвестной командой сначала прочитайте код.

## Backup до изменений

Сохраните и проверьте две части: файловые данные и PostgreSQL. Запишите текущий образ, digest, версию, compose-путь и предыдущие настройки. Размещайте backup вне публичной папки сайта. Проверка наличия файла недостаточна: dump должен читаться `pg_restore --list`, а checksum — совпадать.

Для проверенной структуры VPS пример запуска из runtime-каталога:

```bash
cd /opt/studiolink-rc
export CASTLINK_ROOT=/opt/studiolink-rc
export CASTLINK_DATA_DIR=/opt/studiolink/data
export CASTLINK_WEB_IMAGE='RELEASE_IMAGE'
bash scripts/postgres-backup.sh /opt/studiolink-rc/backups/manual-UNIQUE.dump
```

`RELEASE_IMAGE` заменяют на проверенный образ. В compose требуется это значение даже при обращении только к PostgreSQL. Имя backup должно быть новым. `UNIQUE` не является встроенной подстановкой — выберите уникальное имя сами.

Для полного файлового backup используйте `storage-backup.mjs` по [инструкции хранения](../PERSISTENT_STORAGE_RU.md). Во время записи runtime-данных нужно понимать согласованность снимка; файловая копия не является автоматически атомарным снимком всех сервисов.

## Миграции: отдельно от запуска контейнера

Сначала проверяют миграцию на тестовой БД, затем наличие нужной структуры в production. Не меняйте чужую БД и не запускайте интеграционные тесты на боевом `DATABASE_URL`.

Для creator-only Super Admin обязательна `004_platform_credentials.sql`. В ней нет удаления существующих таблиц. Но новый runtime без этой таблицы работать не сможет. После её применения проверяют таблицу и индекс, а не только HTTP `200` главной страницы.

Штатный script `control-plane-migrate.mjs` ожидает переменную `CASTLINK_CONTROL_PLANE_DATABASE_URL` или `DATABASE_URL` и рабочий каталог с `infrastructure/control-plane`. Эти значения передаются процессу штатной конфигурацией; не печатайте их в консоль. В новом image нужные scripts и SQL включены, в старом их может не быть.

**Важное ограничение:** текущий `production-update.sh` сам не гарантирует применение всех control-plane миграций. Сначала миграция и проверка совместимости, затем замена web. Старое правило «контейнер healthy — значит всё установилось» здесь недостаточно.

## Сборка и публикация image

CI проверяет исходники. Workflow `Build RC image` собирает image из определённой версии. Имя содержит product version и Git SHA; digest дополнительно фиксирует байты образа. Не используйте `latest` как доказательство конкретного релиза.

Workflow image не выполняет production deploy. Публикация Git-тега также не означает, что все тесты прошли. Перед установкой сверьте SHA успешного CI и SHA публикуемого образа. Для секретного репозитория пользуйтесь авторизованным GitHub-интерфейсом, а не извлечением PAT из credential store.

## Замена web без перезапуска медиасервиса

После проверенных CI, image, backup, миграции и согласованного окна:

```bash
cd /opt/studiolink-rc
CASTLINK_WEB_IMAGE='RELEASE_IMAGE' \
  node scripts/production-preflight.mjs infrastructure/production

CASTLINK_ROOT=/opt/studiolink-rc \
CASTLINK_DATA_DIR=/opt/studiolink/data \
  bash scripts/production-update.sh 'RELEASE_IMAGE'
```

Новый image должен уже быть получен из registry. Скрипт работает с web/PostgreSQL compose; LiveKit/Caddy/HAProxy — отдельные сервисы и ради этого update не перезапускаются. Но в момент замены web возможны краткие ошибки control API; «не перезапускаем SFU» не равно «никаких рисков для активного эфира».

После update проверьте `/api/version`, container health, ошибки запуска, отрицательные access-тесты, чтение actual topology, создание тестовой комнаты и реальный медиасценарий. Статус `200` страницы `/super-admin` не означает, что запрещённому пользователю закрыты API.

## Первый вход владельца в новую Super Admin

Эта процедура относится **только к новому коду после миграции 004**, а не к старому bootstrap. Команду выполняет владелец сервера в его консоли. Она не требует создания Studio и не использует Studio password.

В новом контейнере, где scripts включены в image:

```bash
docker exec -w /app studiolink-web \
  node scripts/super-admin-owner.mjs \
  --origin https://castlink.example \
  --output /tmp/castlink-owner-invite-UNIQUE.txt
```

Укажите реальный HTTPS-origin сервиса и новое имя файла. Команда пишет ссылку в файл с правами `0600`; в stdout выводится только сообщение об успехе, **не ссылка**. Файл находится внутри контейнера. Владелец безопасно забирает его в приватный каталог/менеджер секретов, открывает ссылку в своём браузере и удаляет временную копию после использования.

Не кладите файл в `apps/web/public`, не отправляйте его в issue и не выводите через общий CI. При необходимости `docker cp` используйте приватный каталог на хосте и проверьте права файла. Путь и лог команды не должны превращаться в публичную передачу доступа.

Ссылка одноразовая на 15 минут. Успешный обмен создаёт независимую сессию до 12 часов. Внутри панели можно выдать приглашение доверенному человеку. Для аварийного отзыва всех v2-приглашений/сессий CLI имеет `--revoke-all`; это осознанно отключит и самого текущего Super Admin, поэтому используйте только при необходимости.

Эта модель не даёт роли Super Admin право включать эфир/камеру/микрофон. Для эфирной работы человек должен отдельно получить соответствующий доступ Studio. Пароли и ссылки этих двух контекстов не смешиваются.

## Откат и авария

`production-rollback.sh` читает `previous-web-image.txt` и возвращает image. Он не восстанавливает БД. Если новый релиз изменил права или данные, сначала оцените совместимость.

**Для этой миграции безопасности откат на старый RC-2 потенциально возвращает Studio bootstrap и старый глобальный доступ.** Не выполняйте такой rollback вслепую. Безопасный план — исправленный образ с новой границей доступа либо временное закрытие платформенных маршрутов до восстановления. Это отдельное операторское решение, не автоматическое удаление новых таблиц.

Нельзя чинить неисправный UI очисткой PostgreSQL или удалением `/data`. При аварии сначала сохранить логи/идентификатор сборки и определить, сломались ли web, БД, ingress, SFU или клиент. Восстановление backup выполняется отдельно с подтверждением и проверкой tenant isolation.

## Диагностическая шпаргалка

| Симптом | Сначала проверить | Чего не делать первым действием |
|---|---|---|
| `relation ... does not exist` | Нужную БД, schema, SQL-миграцию и версию image | Перезапускать LiveKit |
| Страница есть, данные не грузятся | API status, роль, request ID, migration | Делать API публичным |
| Верхняя сводка есть, комнат нет | Node-local inventory, registry, assigned/observed node, свежесть topology | Переносить активные комнаты вслепую |
| Картинка обрезана | Native размеры, rotation, contain/cover, DOM parent | Увеличивать битрейт |
| `429` | Период лимита, Retry-After, trusted proxy chain, клиентский цикл запросов | Бесконечно повторять запрос каждую миллисекунду |
| Нет screen share на телефоне | Наличие браузерного API и его поддержка | Обещать, что разрешение исправит отсутствующий API |
| Медиапоток пропал | Track state, ICE/TURN, сеть, mute, подписку | Подменять реальные метрики нулями/целевыми значениями |
| Backup не найден | Реальный mount/compose/root | Создавать пустую data-папку, чтобы preflight замолчал |

## Поддержка без утечки секретов

`node scripts/support-bundle.mjs /private/path/report.json` создаёт ограниченный диагностический JSON. Он делает сетевые проверки по конфигурации процесса. Перед передачей всё равно просмотрите файл. Это не полный дамп сервера и не доказательство, что звонок проходит end-to-end.

В журнале работ записывайте дату, SHA, image digest, применённые миграции, backup-путь, выполненные тесты, результат и оставшиеся ограничения. Успешные команды добавляйте в [проверенный runbook](../VERIFIED_RUNBOOK_RU.md), а неподтверждённые идеи отмечайте как непроверенные.
