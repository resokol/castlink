# 05. Первые шаги в коде и безопасная разработка

[Оглавление](../MANUAL_RU.md) · [Данные и доступ](04_DATA_ACCESS_RU.md) · [Далее: сервер](06_OPERATIONS_RU.md)

## Что установить для изучения

Нужны Git, редактор, Node.js и pnpm. В текущем CI используется Node 22, в `package.json` закреплён pnpm 9.15.0. Для повторяемого результата ориентируйтесь на версии репозитория, а не на установку всего «самого нового».

TypeScript, React, Next.js и LiveKit устанавливаются как зависимости проекта. Их не нужно отдельно копировать с сайтов в папку приложения. `pnpm-lock.yaml` фиксирует выбранные версии и связи пакетов.

Полноценный локальный стенд требует отдельно LiveKit, БД и конфигурацию секретов. Проверка типов и большинство unit-тестов не требуют реальной камеры и production сервера. Docker нужен для контейнерных сценариев, а не для чтения исходников.

## Терминал: где выполняется команда

PowerShell — оболочка Windows, Bash — другая оболочка, обычно Linux/Git Bash. Кавычки, переменные и переносы строк в них различаются. Bash-конструкция `$(...)` внутри PowerShell-строки может выполниться не там, где ожидалось.

Перед командой смотрите текущую папку. В PowerShell используйте `Get-Location`, в Bash — `pwd`. Команда `git status` безопасно показывает ветку и изменения. Не открывайте случайно вторую копию проекта и не считайте её тем же рабочим деревом.

Для SSH-операций со сложным shell-кодом лучше передать проверенный файл скрипта, а не строить несколько уровней вложенных кавычек. Процедуры конкретной установки находятся в runbook; приватный SSH-ключ не копируют в чат.

## Сделайте отдельное место для обучения

После обычного клонирования репозитория или в уже существующем checkout можно создать отдельный worktree:

```powershell
git fetch origin
git worktree add -b learning/first-change ../castlink-learning origin/main
Set-Location ../castlink-learning
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test:ci
```

`fetch` получает историю, но не разворачивает её на VPS. `worktree` создаёт отдельную рабочую папку и ветку; это помогает не мешать другой задаче. `--frozen-lockfile` запрещает незаметно пересчитать версии зависимостей при установке.

Не выполняйте эти команды повторно без проверки: существующая ветка/папка может содержать вашу работу. `git reset --hard`, принудительное удаление worktree и `git clean` не являются универсальными средствами «починить ошибку».

## Как открыть проект в редакторе

В репозитории есть `studiolink.code-workspace` и `.vscode/tasks.json`. Они помогают запускать команды, но не заменяют понимание папок. Откройте каталог исходников, а не `.next` и не `node_modules`.

Для документа Markdown используйте предпросмотр редактора. Для TypeScript переход к определению функции часто полезнее поиска по всему проекту. Каталог [FILE_MAP_RU.md](FILE_MAP_RU.md) показывает прямые импорты и кто использует файл.

## Как найти место исправления

Начните с наблюдаемого действия. «Кнопки соприкасаются» — сначала разметка контейнера и CSS `display/gap`. «На VPS появилась SQL relation error» — схема/миграция и запрос серверного модуля. «Камера включилась, но не публикуется» — LocalTrack lifecycle и подтверждение публикации.

Пример пути для карточки гостя: `app/studio/page.tsx` передаёт props в `GuestVideoCard`; `RemoteVideoPreview` прикрепляет track; `video-rotation.ts` вызывает геометрию из `video-fit.ts`. Правка только `GuestVideoCard` может не затронуть настоящую причину кропа.

Пример пути для новой команды: кнопка → обработчик `fetch` → `app/api/.../route.ts` → проверка origin/access/scope → библиотечная функция → SQL/LiveKit API → ответ → обновление UI. На каждом шаге определите, какие данные доверенные, а какие пришли от клиента.

## Прочитайте небольшой пример

```ts
function doubled(value: number): number {
  return value * 2;
}
```

`function` объявляет функцию. `value` — входной аргумент; `: number` — ожидаемый тип. `return` возвращает результат. Такая функция удобна для теста: она не зависит от браузера и сети.

В `video-fit.ts` похожим образом сначала выделена чистая математика, затем отдельная функция применяет результат к HTML video. Это позволяет проверять геометрию без камеры, но не отменяет визуальную проверку браузера.

## Упражнения по возрастанию риска

Первое: исправьте опечатку в учебной копии Markdown и посмотрите `git diff`. Второе: найдите CSS-переменные `--action-gap` и `--section-gap`, объясните, какие контейнеры их используют, но пока не меняйте все глобальные кнопки. Третье: добавьте тест геометрии для источника 1080×1920 и поворота 90°.

Четвёртое: проследите `POST /api/participants` от кнопки до server-side guard, не отправляя команду в production. Пятое: разберите SQL-миграцию на отдельной тестовой БД. Шестое: пройдите локальную комнату с синтетическими источниками, затем с реальными устройствами.

До работы с авторизацией нужно уметь написать отрицательный тест: гость не может выполнить административное действие; Studio A не может использовать идентификатор Studio B; старый отозванный доступ не принимается. «В правильном случае работает» — только половина проверки.

## Локальные проверки

```powershell
pnpm typecheck
pnpm test:ci
pnpm build
git diff --check
```

`typecheck` ищет ошибки типов. `test:ci` запускает перечисленные стабильные тесты. `build` проверяет сборку Next.js. `diff --check` находит ошибки форматирования патча. Ни одна из этих команд отдельно не доказывает отсутствие визуального кропа или безопасность всех ролей.

Некоторые тесты запускают `bash -n` для проверки shell-скриптов. На Windows нужен доступный Git Bash. Для текущей проверенной машины достаточно временно добавить каталог Git Bash в PATH **этого процесса**, не меняя глобальное окружение:

```powershell
$env:Path='C:\Program Files\Gitin;'+$env:Path
pnpm test:ci
```

Если у вас Git установлен в другом месте, сначала найдите его. Отсутствие Bash — проблема тестового окружения; это не повод пропустить тест и объявить весь CI зелёным.

Production-сборка и тестовый сервер могут требовать `STUDIOLINK_DATA_DIR`. Для эксперимента задайте новый каталог учебной копии, а не каталог живого сервиса. Никогда не подставляйте production `DATABASE_URL` в тест, который меняет схему.

## Виды тестов в репозитории

Есть тесты чистых функций, тесты HTTP-обработчиков с подменёнными зависимостями, проверки наличия кода по строкам/регулярным выражениям и интеграция с настоящим PostgreSQL. Есть отдельные браузерные сценарии. Они дают разную степень уверенности.

Строковая проверка `object-fit: contain` доказывает только наличие текста. Она не доказывает, что это правило выиграло CSS-каскад. Тест математики поворота доказывает расчёт размеров, а браузерный тест — применение расчёта к DOM. Реальный телефон проверяет ещё захват, ориентацию, разрешения и устройство.

`platform-access-postgres.cjs` проверяет миграцию 004 и конкурентное использование приглашения на настоящей тестовой БД. Он намеренно отказывается работать с произвольной БД. В CI используется отдельная локальная `castlink_test`.

## Как оформлять изменение

Сначала зафиксируйте симптом и критерий готовности. Затем измените минимальный набор файлов. Добавьте тест, который воспроизводит проблему, и проверьте соседние сценарии. После этого прочитайте полный diff: случайная замена заголовка не должна принести изменение firewall, `.env` или чужой задачи.

```powershell
git status --short
git diff --check
git diff --stat
git diff
```

Добавляйте в коммит только относящиеся к задаче файлы. Не используйте бездумно `git add .` в общей папке, где одновременно работает другая задача. Не коммитьте `.env`, dump, приватный ключ, link с bearer и временный browser profile.

Название коммита должно объяснять действие: `fix: preserve portrait video geometry`, а не `fix everything`. Отдельная исправленная функция и отдельный документационный коммит легче проверяются и откатываются.

## Ветки и релизы

Долгоживущими остаются основная ветка, активные release-кандидаты и действительно отдельное направление вроде native Windows. Для отдельного исправления создаётся короткая `fix/*` или `feature/*`. После проверенного merge её удаляют; незамерженные уникальные изменения сначала сохраняют и изучают.

Ветка не является backup БД. Тег исходников не заменяет Docker digest. Удаление поглощённой ветки не удаляет коммиты, достижимые из основной истории, но незамерженную ветку нельзя считать безопасной к удалению без проверки.

## Перед обращением за помощью

Сообщите страницу, роль, версию из `/api/version`, устройство/браузер, действие и фактический результат. Добавьте screenshot без bearer-ссылок и секретов. Для сетевой ошибки полезны код HTTP и request ID; для медиа — источник камеры/экрана, направление, разрешение, FPS, RTT/jitter/loss и момент проблемы.

Такой отчёт позволяет искать конкретную причину. «Не работает» не отличает ошибку доступа от отсутствующей таблицы, кропа CSS или отказа браузера в разрешении.
