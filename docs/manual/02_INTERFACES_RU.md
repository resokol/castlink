# 02. Интерфейсы и первая рабочая комната

[Оглавление](../MANUAL_RU.md) · [Основы](01_BASICS_RU.md) · [Далее: системы](03_SYSTEMS_RU.md)

## Перед первым подключением

Нужны работающая установка CastLink, браузер с разрешениями, камера/микрофон и наушники. Для изучения интерфейса используйте отдельную тестовую комнату, а не эфир клиента. Наушники особенно важны: возвращённый звук из колонок снова попадает в микрофон и создаёт эхо.

Не путайте два сценария. **Пользователь готового сервиса** получает ссылку и открывает её. **Владелец сервера** устанавливает сервис, настраивает сеть и создаёт доступы. Гостю не нужны Git, PostgreSQL, Docker или программирование.

## Карта страниц

| Страница | Кто и зачем её открывает |
|---|---|
| `/` | Входная страница, выбор сценария подключения и сохранённых серверов |
| `/studio` | Основная студия: возврат программы, комнаты, гости, мониторинг, статистика |
| `/room` | Гость: имя, доступ к комнате, проверка устройств, конференция |
| `/admin` | Администратор конкретной комнаты, без автоматического занятия основной студии |
| `/moderator` | Модератор с ограниченными правами комнаты или студии |
| `/output/[identity]` | Чистый индивидуальный вход гостя для vMix; `[identity]` заменяется реальным ID |
| `/monitor` | Мониторинг комнаты отдельным техническим клиентом |
| `/watch` | Отдельная ссылка просмотра Studio Return через выделенный relay-поток |
| `/transfer` | Приём переноса на другую ноду по проверенному билету |
| `/diagnostics` | Ограниченная диагностика для разрешённых операторских ролей |
| `/super-admin` | Отдельная консоль платформы: ноды, сводка, комнаты, доступы |
| `/studios` | Управление студиями и размещением; в новой границе доступа — только Super Admin |
| `/servers` | Реестр серверов/временные серверы; требует Super Admin и настроенного внешнего registry backend |
| `/setup` | Настройка установки с отдельным setup-токеном; не обычный вход участника |

`/super-admin/nodes` и `/super-admin/access` не следует придумывать по названиям разделов: в этой версии это секции одной страницы `/super-admin`, а не отдельные реализованные маршруты.

## Первый сеанс: действия студии

Откройте свою Studio по owner-ссылке либо используйте парольный вход legacy `studio-default`. Это даёт права студии, **не** права Super Admin. Создайте тестовую комнату и откройте её. Для multi-tenant установки ссылка и действия должны сохранять `studioId`.

В блоке устройств выберите камеру/видеовход, микрофон/аудиовход и устройство прослушивания. На студийном ПК источником видео может быть доступное браузеру виртуальное устройство. Сам браузер не превращается от этого в захват произвольного SDI/NDI/Dante: внешняя программа или драйвер должны представить сигнал подходящим устройством.

Проверьте превью **Studio Return** до эфира. Личное прослушивание своего микрофона включайте осторожно и только в наушниках. `ON AIR` управляет отправкой эфира, а кнопки личного мониторинга — только вашим прослушиванием/отображением. Не делайте вывод «эфир выключен», если вы просто нажали «не слушать».

Создайте гостевую ссылку. Откройте её на отдельном устройстве или в отдельном профиле браузера, чтобы случайно не использовать уже сохранённые права студии. Запишите номер сборки, браузер и устройства теста — это поможет воспроизвести ошибку.

## Первый сеанс: действия гостя

Гость вводит имя, проходит проверку пароля/приглашения и выбирает устройства. Страница проверки устройств называется prejoin: она позволяет понять, какая камера и какой микрофон будут использоваться, ещё до полноценного входа в комнату.

После входа гость видит камеры участников и Studio Return согласно режиму комнаты. Если включено «гости видят только студию», это изменение разрешённого просмотра, а не удаление остальных участников.

В блоке конференции есть область видео и отдельный нижний toolbar. В исправленной раскладке toolbar не лежит поверх изображения, а занимает своё место под видео. Если участников много, прокручивается область камер; кнопки остаются внизу этого блока. При единственном участнике блок уменьшается относительно обычной высоты. Полноэкранный режим использует отдельное правило размеров.

Выбор камеры/микрофона и кнопка включения — разные действия. Выбранное устройство не обязательно сейчас публикуется. Отключение камеры не должно самопроизвольно включать другую камеру.

## Что означает «мониторинг у меня»

Это локальная настройка потребления сигнала. «Звук выкл.» на вашей карточке мониторинга не обязательно выключает микрофон источника для всей комнаты. Аналогично личная громкость 0% не должна менять уровень, который получают vMix или другие гости.

Отдельные административные кнопки «Выключить микрофон гостя» или «Отключить гостя» — уже общие действия. Включение чужого устройства может быть только запросом: разрешение браузера и доступность устройства остаются обязательными.

## Камера, демонстрация экрана и отдельные выходы

Камера и экран — разные публикации LiveKit. Экран может иметь отдельную аудиодорожку; возможность захвата звука зависит от браузера и выбранного типа источника. Системный диалог захвата экрана не является окном CastLink.

При отмене выбора или отказе разрешения временное сообщение должно исчезнуть, не меняя камеру и микрофон. «Этот браузер не поддерживает показ экрана» — другое состояние: его нельзя исправить повторным нажатием или обещанием доступа.

Студия получает отдельную ссылку для камеры и отдельную ссылку для экрана. Для экрана используется параметр `source=screen` на output-пути. Не заменяйте вручную секрет приглашения и не убирайте параметры комнаты/студии из выданной ссылки.

`/output` нужен как чистый сигнал. В нём не должно быть панели управления, индикаторов обновления приложения, кнопок и технического debug-текста поверх изображения. Обычная студийная карточка, наоборот, содержит инструменты оператора.

`/watch` — другой продуктовый сценарий: просмотр общего возврата. Он не должен подменять индивидуальные guest output-потоки. Под капотом у него отдельная relay-публикация и техническая identity.

## Кодек камеры кастера

В карточке кастера студия выбирает **VP8**, **H.264** или **AV1**. По умолчанию используется VP8. Кодирует видео браузер кастера; сервер пересылает поток получателям. Недоступные кодеки отключены в списке. AV1 должен поддерживаться также браузером студии и браузерным источником OBS/vMix; наличие аппаратного кодировщика не гарантируется.

При смене кодека кратко перепубликуется только камера. Микрофон и демонстрация экрана продолжают работу. Выключенная камера остаётся выключенной. Интерфейс отдельно показывает сохранённый выбор и кодек действующей камеры, подтверждённый SDK после публикации. Если согласование не удалось, отображается ошибка и выполняется попытка восстановить прежнюю публикацию.

## Запрос смены устройств кастера

Основная студия и администратор в карточке кастера могут выбрать **микрофон**, **камеру** или **выход звука** из доступного списка. Ограниченному модератору список устройств не выдаётся. Кастер видит название предложенного устройства и кнопки «Подтвердить смену» / «Отклонить». До подтверждения устройство не меняется; запрос действует 60 секунд и отменяется при переподключении кастера.

После подтверждения студия видит результат: устройство переключено и проверено либо выбор сохранён до включения камеры/микрофона. Выключенные устройства не включаются автоматически. Отказ, истечение срока и ошибка показаны отдельно. Если переключение не удалось, клиент пытается восстановить прежнее устройство.

Список содержит только устройства, которые браузер уже разрешил видеть. Запрос студии не обходит разрешения операционной системы и браузера. Выбор выхода звука доступен только в браузерах с поддержкой `setSinkId`; при отсутствии поддержки настройка отключена. Для наушников, подключённых после входа, дождитесь обновления списка.

## Поворот и соотношение сторон

Портретное видео 720×1280 и альбомное 1280×720 имеют разные пропорции. Окно 16:9 может содержать портретный кадр с чёрными полями — это нормально. Удаление полей через `cover` обрезает часть изображения.

Поворот на 90° должен сначала поменять геометрию видимого кадра, затем вписать его целиком. В новой реализации размеры берутся из декодированного видео (`videoWidth`/`videoHeight`), а не из предположения «всё всегда 16:9». Поворот интерфейса телефона и ручной поворот видео — не одно и то же; проверяйте оба сценария.

Контрольный тест: в кадре должны быть видны четыре метки у краёв. Сравните гостевое превью, Studio, fullscreen и `/output` при 0/90/180/270°. Если метка исчезла уже у гостя, проблема может быть в захвате, а не в студийном CSS.

## Битрейт: выбранное и измеренное

**Лимит камеры** задаёт бюджет кодирования гостевой камеры. Он влияет на отправителя и, следовательно, на потребителей этого источника, а не только на одну карточку студии. Новые клиенты применяют бюджет к сумме simulcast-слоёв. Старый клиент без этой логики нужно обновить в согласованный момент.

Это не строгий CBR. Браузерный `maxBitrate` ограничивает кодирование, но не обещает каждую секунду выдавать одинаковое количество байтов. Статичная картинка может требовать меньше, перегруженная сеть — не доставлять нужный объём, а короткий замер и транспортные расходы — отличаться от целевого значения.

Раньше выбор в карточке лишь запрашивал примерный simulcast-слой и поэтому не был настоящим лимитом отправителя. Не называйте старую реализацию constant bitrate. Поле «факт» всегда должно показывать реальный замер, а не выбранное число.

Лимит камеры, лимит Studio Return и качество отдельного выхода — разные настройки. Не складывайте их без понимания направления потока. В [системах](03_SYSTEMS_RU.md) разобрано, где именно они применяются.

## Аудиометр

Аудиометр измеряет полученные аудиосэмплы, а не положение кнопки микрофона. Шкала dBFS показывает уровень относительно цифрового максимума: 0 dBFS — верхняя граница. Отрицательное число означает более тихий сигнал; это не «отрицательная громкость».

В исправленном guest meter используются пиковое измерение, быстрый подъём и плавное падение индикатора. Анализатор не пересоздаётся из-за очередного сетевого замера. Нижняя граница расширена до −90 dBFS; значения ниже неё отображаются как отсутствие измеримого уровня, а не как выдуманное число.

Этот индикатор не применяет gate к звуку. Однако подавление шума в телефоне, браузере, драйвере или источнике может изменить сигнал ещё до его приёма. Аудиометр не способен восстановить уже удалённый звук. Проверять это нужно записью/прослушиванием и настройками источника, а не только анимацией полоски.

## Администратор и модератор

Для персонала используются отдельные приглашения и роли. Администратор комнаты не становится основной студией при открытии панели. Модератор не должен получать права администратора от выбранного имени или внешнего вида кнопки.

В панели персонала можно изменить своё отображаемое имя. Оно не должно менять `identity`, роль, границы комнаты и историю авторизации. Имя по умолчанию получает номер. Одновременное создание имён и переподключения обязательно проверяются отдельно: визуальное имя не является уникальным ключом системы.

## Статистика

Выберите период, затем роль, участника по его устойчивой identity и при необходимости конкретную сессию. Тёзки не должны смешиваться. Переименование не должно означать новое подключение.

Входящий битрейт — данные от сервера к тому клиенту, который отправил замер. Исходящий — от клиента к серверу. RTT — время туда-обратно, jitter — неравномерность прихода пакетов, loss — потери. RTT нельзя автоматически делить пополам и выдавать за измеренную задержку картинки «камера → экран».

CSV нужен для таблиц, HTML-отчёт — для чтения в браузере без подключения к сервису. В отчёте должны сохраняться фильтры, реальные пропуски данных и предупреждение, что клиентская телеметрия не является доверенным журналом безопасности. «Нет свежих замеров» не равно «участник точно отключился».

## Диагностика и Super Admin

Обычный `/diagnostics` намеренно ограничен. Полную картину Node → Studio → Room → Participant показывает Super Admin. Верхняя сводка, свежесть heartbeat, серверная диагностика и фактический WebRTC RTT — разные источники данных.

Назначение студии в реестре может расходиться с тем, на какой ноде наблюдаются комнаты. Новая диагностика показывает обе стороны. Она не должна молча переносить эфир или переписывать assignment, чтобы таблица выглядела красиво.

У Super Admin нет кнопок камеры, микрофона, показа экрана и выхода в эфир. Первый доступ создаёт владелец сервера отдельной консольной командой. Вход студией не открывает этот доступ. Подробно: [данные и доступ](04_DATA_ACCESS_RU.md), [операционная процедура](06_OPERATIONS_RU.md).
