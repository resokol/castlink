# 07. Проверка изменений

[Оглавление](../MANUAL_RU.md) · [Разработка](05_DEVELOPMENT_RU.md) · [Эксплуатация](06_OPERATIONS_RU.md)

## Выберите проверку по изменению

Проверка должна воспроизводить изменённое поведение и его границы. Геометрию кадра проверяют расчётом и браузерным рендером; права — запросами с разрешённой и запрещённой ролью; миграцию — на отдельной БД. Успешная сборка сама по себе не проверяет медиасвязь.

Базовые команды из корня проекта:

```sh
pnpm typecheck
pnpm test:ci
pnpm build
git diff --check
```

`pnpm test:ci` выполняет автономный список `apps/web/tests/run-ci.cjs`. Он не заменяет отдельные PostgreSQL, Docker, браузерные и аппаратные проверки. Список и порядок CI определяет `.github/workflows/ci.yml`.

## Данные и авторизация

Для PostgreSQL используйте отдельную локальную `castlink_test` и `TEST_DATABASE_URL`. Тесты, создающие или удаляющие данные, нельзя направлять на рабочую БД. Миграции нужно проверять как на чистой схеме, так и на поддерживаемой исходной версии.

Проверяйте роль, комнату, студию, срок и отзыв доступа. Один и тот же секрет должен отклоняться после истечения, использования или отзыва согласно его контракту. Для одноразовой ссылки проверяйте конкурентное использование. Скрытая кнопка не доказывает запрет серверной операции.

## Браузер и медиа

Проверяйте узкий и широкий экран, тёмную и светлую темы, длинные подписи, ошибки и недоступные устройства. Для видео важны пропорции, поворот, letterbox, отсутствие обрезания и перекрытия управляющими элементами. Отдельно проверьте сохранение mounted media при навигации и повторном подключении.

Синтетические canvas/audio источники удобны для регрессий. Они не проверяют физическую камеру, акустику, разрешения ОС, мобильный фон, задержку реальной сети или длительный эфир. Измерения должны показывать реальные счётчики, а не заданный лимит кодировщика.

| Сценарий | Ожидаемый результат |
| --- | --- |
| Обычный гость обращается к административному API | Сервер отклоняет запрос |
| Studio A передаёт ID объекта Studio B | Нет данных и действий чужой студии |
| Истёкшая или отозванная сессия | Действия отклоняются серверно |
| Повторное подключение | Нет дублей участников, обработчиков и видеотреков |
| Камера, экран, повороты и fullscreen | Геометрия источника сохранена |
| Личный мониторинг или приватная связь | Основной эфир и посторонние получатели не затронуты |
| Stop во время ошибки управления | Владелец может независимо остановить показ |
| Недоступный сервер или источник | Показана ошибка или свежесть данных |
| TURN-only сеть | Выбрана relay-пара и передаются аудио/видео |

## Сборка и выпуск

Фиксируйте точный commit SHA, команды, среду, результат и непроверенные ограничения. При изменении кода после проверки результат относится к прежнему SHA. Отдельно проверяйте готовый пакет: содержимое архива, контрольные суммы, запуск и обновление на целевой платформе. Инструкции выпуска — [RELEASE_POLICY](../RELEASE_POLICY_RU.md).

Для отчётов используйте синтетические данные. Действующие приглашения, bearer-ссылки, ключи, cookies и конфигурацию работающих серверов не включают в репозиторий.
