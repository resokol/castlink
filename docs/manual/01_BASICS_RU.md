# 01. Основы без программирования

[Оглавление](../MANUAL_RU.md) · [Далее: интерфейсы](02_INTERFACES_RU.md)

## 1. Что делает CastLink

CastLink соединяет удалённого гостя с технической студией через браузер. Гость отправляет камеру и микрофон. Студия получает отдельные потоки, может открыть их в vMix и отправляет гостям обратную программу — **Studio Return**. Участники могут общаться друг с другом, а персонал получает отдельные инструменты управления.

Представьте режиссёрскую. Изображение по видеокабелю — это медиаданные. Команда «включить камеру», список гостей и права доступа — управление. В CastLink вместо кабелей сеть, но разделение остаётся тем же.

## 2. Браузер и сервер — два разных компьютера

**Клиент** здесь обычно вкладка браузера. Она видит подключённые к этому компьютеру камеры и микрофоны и спрашивает разрешение на их использование. **Сервер** принимает запросы и организует комнаты. Он не может просто взять камеру гостя без разрешения браузера.

Файл интерфейса может находиться в Git на вашем ПК, а выполняться после сборки в браузере другого человека. Поэтому строка `window...` относится к браузеру, а `process.env...` в серверном модуле — к серверному процессу. Секрет сервера нельзя переносить в браузер ради удобства.

**Процесс** — запущенная программа. Закрытый файл с кодом ничего сам не делает. `node`, Next.js, LiveKit, PostgreSQL, Chrome — разные процессы. Наличие процесса `codex.exe` само по себе не доказывает, что он сейчас изменяет проект.

## 3. Папка, файл, расширение

`apps/web/app/studio/page.tsx` читается слева направо: в корне проекта есть папка `apps`, внутри `web`, затем `app`, `studio`, а внутри файл `page.tsx`.

| Расширение | Для чего используется |
|---|---|
| `.md` | Текст руководств в Markdown: заголовки, таблицы, ссылки |
| `.ts` | TypeScript: логика с описанием типов данных |
| `.tsx` | TypeScript с разметкой React-интерфейса |
| `.css` | Цвета, размеры, отступы и расположение элементов |
| `.json` | Структурированные данные или конфигурация |
| `.jsonl` | По одной JSON-записи в строке; здесь используется для истории измерений |
| `.sql` | Команды для PostgreSQL: таблицы, ограничения, выборки |
| `.mjs` / `.cjs` | Исполняемые JavaScript-скрипты; два варианта модульной системы Node.js |
| `.sh` | Скрипт оболочки Bash, обычно для Linux |
| `.ps1` | Скрипт PowerShell для Windows |
| `.yml` / `.yaml` | Конфигурация Docker Compose, GitHub Actions и некоторых сервисов |
| `.cpp` | C++: отдельные нативные заготовки, не основной web-клиент |

Файл `package.json` не является БД комнат. Он описывает приложение, команды запуска и зависимости. Папка `node_modules` содержит установленные библиотеки; её не редактируют для исправления проекта.

## 4. URL, домен, IP и порт

В адресе `https://castlink.example/room?studioId=studio-demo&name=interview` часть `https` обозначает протокол, `castlink.example` — имя сервера, `/room` — страницу, а после `?` идут параметры. Это иллюстрация адреса, а не работающая ссылка.

IP — сетевой адрес компьютера. Порт — номер конкретной службы на этом адресе. `127.0.0.1` всегда означает **тот компьютер или контейнер, где выполняется команда**, а не обязательно ваш VPS. Если выполнить `curl http://127.0.0.1:3000` дома, запрос не попадёт на удалённый VPS.

HTTPS нужен не только для замка в адресной строке. Браузеры ограничивают камеру, микрофон и некоторые другие возможности на небезопасных страницах. Работа интерфейса по HTTPS ещё не означает, что сетевой путь для WebRTC исправен.

Часть адреса после `#`, например `#access=...`, называется фрагментом. Она не отправляется серверу как часть обычного HTTP-адреса. JavaScript может прочитать её и обменять приглашение на сессию. Такой адрес всё равно является секретом: его владелец может получить доступ.

## 5. Запрос и ответ

**API** — согласованный способ обмена командами между программами. Браузер спрашивает `/api/rooms`, сервер проверяет права, читает хранилище и возвращает JSON.

`GET` обычно читает, `POST` выполняет действие, `DELETE` удаляет или отзывает. Но ориентироваться нужно на реализацию конкретного маршрута: название HTTP-метода само по себе не является защитой.

Основные коды ответа: `200` — запрос выполнен; `204` — выполнен без тела; `400` — неверные данные; `401` — нет действующего доступа; `403` — действие запрещено; `404` — объект не найден; `409` — конфликт состояния; `429` — слишком частые запросы; `500/503` — ошибка или недоступность серверной части.

Страница может отдать HTML с кодом `200`, а её запрос к API — получить `403` или `503`. Поэтому «страница открылась» не равно «права и данные работают».

## 6. Минимальный словарь кода

**Переменная** хранит значение, например выбранный битрейт. **Функция** выполняет именованную операцию, например `readRooms()`. **Аргумент** — значение, передаваемое функции. **Объект** объединяет поля: `{ name: "Гость", role: "guest" }`. **Массив** — список объектов или значений.

**Тип** описывает допустимую форму данных. Если TypeScript ожидает число, а получает строку, проверка может сообщить об ошибке ещё до запуска. Но типы исчезают в собранном JavaScript, поэтому данные из браузера всё равно проверяются на сервере.

**Импорт** подключает код из другого файла. **Экспорт** делает функцию доступной другим файлам. В каталоге исходников можно проследить обе стороны этих связей.

**Компонент React** — часть интерфейса, например карточка гостя. **Props** — входные параметры компонента. **State** — состояние, изменение которого перерисовывает интерфейс. **Hook** — функция React для состояния, подписок и жизненного цикла.

`useEffect` часто подключает обработчик события или таймер. Возвращаемая из него функция отключает обработчик при смене зависимости или закрытии компонента. Забытый cleanup может оставить второй таймер, старый медиатрек или лишний аудиоконтекст.

**Promise** обозначает результат, который придёт позже. `await` ждёт этот результат, не превращая сетевую операцию в мгновенную. `try/catch/finally` разделяет успешный путь, ошибку и обязательную уборку ресурсов.

## 7. Почему в проекте несколько идентификаторов

`studioId` отличает одну студию от другой; `room` или имя комнаты — одну комнату внутри студии; `identity` — участника; `session` — конкретное подключение; `nodeId` — физическую ноду; `installationId` — установку приложения.

Имя «Максим» можно изменить, а `identity` нужно сохранить. Иначе история статистики одного человека распадётся или смешается с тёзкой. Одинаковые имена комнат в разных студиях — тоже разные комнаты.

## 8. Git, сборка, образ и данные

**Git** хранит историю исходных файлов. **Коммит** — зафиксированное изменение. **Ветка** — указатель на линию работы, а не отдельный сервер. **Тег** — именованная точка истории. **Pull Request** — предложение проверить и объединить изменения.

**Сборка** превращает исходники в исполняемое приложение. **Docker image** — упакованная версия приложения и окружения. **Контейнер** — запущенный экземпляр образа. **Volume/bind mount** подключает постоянные данные, которые должны пережить замену контейнера.

Например, `1.0.0-rc.2` — версия продукта, а `1.0.0-rc.2-<git-sha>` — конкретная сборка. Два образа с одинаковым `rc.2`, но разными SHA могут работать по-разному.

## 9. Небольшая проверка понимания

Найдите в GitHub `package.json`, затем `apps/web/app/room/page.tsx` и `apps/web/lib/room-store.ts`. Первый описывает проект, второй — гостевую страницу, третий — интерфейс хранилища комнат. Пока ничего не меняйте. Теперь откройте `/api/version` у своей установки и сравните номер реально запущенной сборки с веткой Git. Несовпадение само по себе не ошибка: установка могла ещё не обновляться.
